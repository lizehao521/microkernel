7甲方 AI 项目验收：把「做成」拆回能回盘核的格子

7.0 前置声明（这一章的位置不是作者选的）

有据盘上 本章写哪一个垂类，由 数据/评分表.json 过 工具/模型.py 重算的赢家决定； 核对道 K11 会检查本章章名含不含那个赢家的名称——赢家一变，这一章必须重写，而不是加一节。 同时要记住第 4 章那条资格线：原始分第一那一行不在本章，因为它只有 3/5 维有依据。

本章的每一小节都以「什么读数会把它推翻」收尾，而那些读数这一发大多没有 （第 2 章 N1–N9、N11 全是「动作没发生」那一类）。 所以它是规格与证伪条件，不是排期表。

7.1 交付对象：不是包，是一张挂尾款的裁决

有据盘上 已关闭方向 C9 禁止把「证据包」本身当商品。所以 V1 的交付对象必须换成一个动作加一个裁决： 一次收口验收结束时，这份回执回答「这一笔该不该付」，买方为这个裁决付钱，不为拿到一份文件付钱。 接口是现成的：验收清单 A1–A5 每行的「未达成处置」都写着尾款不付 （试点函.md:109），A6 不挂钩尾款但必须披露 （:114）。

承诺收窄成一句可守的话：本产品只把「做成」的定义逐条钉回盘上可复算的东西；它不判「业务上是否真的做成」。 后一句是买方的语义真值，归 7.4；把它含糊地算进本产品，就是 C2/C4 那类「审计层冒充防线」的老错。

这一格产品做的产品明确不做的
裁决把声明逐条对到盘上证据，出三态 + 退出码 不判业务价值、不判模型输出对不对、不出具「合格」意见
接口挂到既有验收清单的 A1–A5 上，作为「这一项达成与否」的机械依据 不替代 A4（非作者真人复核）；A4 本身就是没量过的那一格
文件回执是裁决的凭证，随裁决一起生成 不单独报价、不按份卖、不做成可囤的存货

7.2 声明词表：13 种现有类型覆盖什么、缺哪八种

有据盘上 底盘现有 13 种核对类型（交付对账-1026/README.md 的 kind 表）。 先把它们在这个垂类里覆盖什么、不覆盖什么逐类说清——这是产品边界最容易吹大的地方。

类型在甲方验收现场覆盖的那一件事它明确覆盖不了的
file_exists / file_absent约定的产物在不在、约定不该留的东西没留在不在 ≠ 对不对
file_sha256交付物指纹与封存的样本 / 基线一致不证明这一版是「按要求做的那版」
file_bytes / file_lines尺寸与行数下限（防「空文件交差」）不许用它冒充内容量（字节数取盘上真实尺寸，不是字符数）
file_contains指定行 / 任意行含约定句（如合同条款、阈值声明）子串在场 ≠ 语义正确
log_exit末条非空行是 exit_code=N：跑过且结果如何不证明那次跑用的是交付的那份代码
log_contains日志里有约定的那一步（逐字匹配）日志可伪造，故只作 self 档时封顶
json_value / number / bool / string / len评测结果件里某一格的值、类型、数组长度：分子分母、阈值、样本数 值与类型可对，「这一格是不是那次真评测的读数」不能对——那是 7.4 的语义真值

本垂类需要、但本轮不实现的八种类型（只给规格）

待新增类型它要钉住的那句话为什么现有 13 种装不下
heldout_sealed留出样本在某时刻已封存且此后未变需要外部时点锚，不是文件内容比对
ratio_ownership某个比率的分子分母各自属于谁现有 json 类型只读一格的值，不知道分母是谁给的
threshold_provenance达标阈值出自哪份合同条款 / 谁签的需要跨件引用（条款 → 结果件），单文件判据做不到
arbiter_present分歧仲裁人具名且非作者「在场」是组织事实，不在盘上任何一格里
regression_nonempty回归集非空且带版本三元组要同时核集合、版本与一致性，现有类型一次只核一件
exception_paths_count异常路径被走过几条（不是「跑通了」）需要执行轨迹语义，且「没这回事」与「没测」要分开
owner_named_post_release上线后负责人具名可追人事事实，本件不联网取
signature_freshness签字在复核完成后、且未早于回执生成要比较两个独立时间源，时钟刻度即抖动源
「先写声明、后补判据」在这套底盘上是安全路径，不是漏洞

有据盘上 今天若把上面任何一种写进声明交进来，底盘不会静默通过：不认识的类型直接判 ABSENT 并写明「本件不认识这个核对类型」 （对账单.py:249），整单落「核不了」档（退出码 3）。 所以规格可以先于实现存在——而这份报告没有实现它们（内核 48 键 / 49 格与「停止新增」的边界未动， 微内核/微内核/README.md:631）。

7.3 证据源：沿用三源，另给第四源一个规格

证据源它核什么在甲方验收里的角色
Agent 轨迹步数、每步是否真跑、依据档、末步是否终态、五档恒等、行号能否回盘 证明「这句话是哪一步说出来的」
宿主事件调用与事件的形状、进度、断线语义证明「这一步被谁接住了」
账本逐条记录的链自洽证明「记录没被改过」，不证明「记录的内容为真」
contract（规格，未实现） 条款件 ↔ 判据 ↔ 结果件三者的引用是否闭合：阈值出自哪一条、该条谁签、结果件由谁提供 这是 V1 与通用日志车道的真正分界；本件不联网取平台数据、不执行客户代码

第四源在本轮只有规格，没有一行实现，也没有一次真跑； 它进不了任何计数，也不许在第 5 章的格子里换成别的依据。

7.4 语义真值由谁供：这是 V1 最难的一格，也是它唯一的护城河

有据公开件 裁决类产品没有真值供方就是表演。V1 的真值不来自本件，来自买方自己的三样东西： 甲方自写的验收标准、封存下来的评测样本、具名仲裁人。 本轮唯一一条买方自写的证据（一份 2026-10-19 的政采结果公告）恰好落在这三样的第一样上—— 各阶段验收须形成书面记录并由双方签字确认（S01）； 而第二、第三样的形状在供给侧文章里被写得很具体：评测集至少 200 条真实场景样本、达标阈值、谁提供评测集、分歧怎么仲裁 （S02）。

7.5 回执件的合同与法务用法

有据盘上 这一节说的是「这张纸在合同里站在哪」。三条现成接口：A1–A5 挂尾款、A6 不挂但必须披露、 R5「未测写成 0」本身就是拒收码（试点函.md:141）。 最后一条对本产品是决定性的：拒收码里已经有一条专门惩罚「把没量到写成 0」—— 那正是底盘的三态设计要做的事。换句话说，本产品与自家拒收码同向，不靠自己造话术。

条款回执承担的角色限制（必须写进合同，否则产品会被误用）
A1 链自洽退出码与逐条三态即「达成 / 未达成」的机械依据断点可定位是本件给的，不是买方给的
A2 产物原像指纹核对结果N10 = 0 / 2,940：这一项今天过不了，必须写成受理硬门
A3 版本三元组产物 / 行为 / 判据三件齐不齐判据版本变动需重跑，不能只改文档
A4 外部复核回执不能替代它——它要的是非作者真人0 / 1 未量；把它写成「已由回执覆盖」即越界
A5 拒收计数每发记录通过 / 拒收 / 超时及原因码不以 0 代替未测（与本件三态规矩同一条）
A6 R/N 双臂不挂钩尾款，但必须披露 NOT_RUN披露是义务，不是可选项；写成 0 触发 R5

回执内容里不含模型转述：底盘只印自己量到的与量不到的，不印第三方对它的解释（这也是它和「日志 + 一段 AI 总结」那类车的区别）。

7.6 三条定价假设，各带证伪阈值

有据假设 本节不产规模数（口径件 §八）。给的是三条能被读数推翻的假设，形状照底盘的 estimate 凭据规矩： 每条都要有假设与证伪条件。

#假设证伪阈值（读数一出现就推翻）怎么观测
H1一个甲方团队的收口验收次数足够密，使「按次核一份声明」成立 （本轮无读数；桌面端设计稿已把「队列频率 < 每周 3 次」列为降级条件） 若 G1 那 10 例里非作者自发的收口验收次数中位数 < 1 / 周 ⇒ H1 废 回执生成次数 / 周（同一 team 的去重后计数），非作者发起才算
H2买方愿付的形态是「尾款该不该付」的裁决，而不是「一份可交付文件」 若试点里出现要求「只买一份包、不挂尾款」的具名买方 ⇒ H2 废，同时 C9 复开 合同条款里付款条件是否引用退出码；出现「按份采购」字样即记一发
H3单价锚点只做形状对照，不做报价依据：公开价盘里「审计日志挂在最高档」这一形状存在 若任一具名价盘把审计留痕放进最低档或免费档 ⇒ 本形状对照作废，需重找锚 核级价盘件（S16）逐档读；片级价盘不许进本节
本节不许出现的三样东西

规模数；三年三情景；任何来自片级件的数字。理由不是谨慎，是上一族已经为此付过一次： 给「待复核」标注的快照数字仍进了正文，一个判 UNSUPPORTED、一个一手根本取不到。
