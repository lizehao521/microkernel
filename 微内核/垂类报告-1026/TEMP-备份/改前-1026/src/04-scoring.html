Chapter 4 · The Ruler

4评分尺：为什么是这五维，以及它凭什么不能被手改

四个候选垂直不是靠叙事排出来的。五维、权重、每格的分数与凭据全写在一个 JSON 里， 出分与核对用的是同一个实现（工具/模型.py）——否则「渲染出来的总分」与「重算出来的总分」相等 只是巧合。这条纪律来自上一族的教训：交叉等式有一边只有「写的那件」知道时，先把两边搬进同一个只读件。

4.1 五维各自在问什么，权重为什么这么分

有据盘上 权重的取法不是「哪个最重要」，而是「哪一维最缺证据、因而最该被看清楚」。 这一点必须先说破，因为它是一个真实的自利陷阱：

如果按「底盘已经造好什么」来排权重，守现状那一维会直接胜出

D1+D2+D3 三项都是「本件已经会做的事」；把它们合计到 0.68，V3（软件交付声明复核，即守住现在的方向） 就会以技术对齐度的名义被冠「胜出」。那不是判断，是给自家存量找台阶。 所以本件把最缺证据的那一维 D4（2026 付费语境）设成最高权重 0.30， 并把这段取法写进 数据/评分表.json 的 weight_rationale，让读者可以审它而不是猜它。

维它在问什么权重方向为什么不是别的数
D1这一垂类的交付物里，今天有多少能被现有 13 种核对类型直接钉住，多少必须等新类型 0.15越高越好 「接得快不快」是 0/1 未量的门，不许计分；可数的只有「已被现有类型覆盖的比例」
D2「这句话算不算数」由谁说了算，本件能不能拿到那个真值 0.28越高越好 没有真值供方的裁决是表演；这一维同时是同分时的第一顺位比较维
D3这一垂类天然的记账单位，装不装得下内核冻结的「一格一行」 0.12越高越好 装不下就是要动判据表——那是单独的决定，不在本报告的授权范围内，所以只给小权重
D42026 年有没有可指认的买方文件或真实价盘，把这一垂类要买的东西写成条款 0.30越高越好 最高权重给了最缺证据的一维：只有核级外部件能算分，「这类东西当然要买」这种推定不算
D5这一车道 2026 年已被平台方 / 机构级件占住多少 0.15反向（分数越高＝挤压越重＝越差） 反向维必须显式声明；它是同分时的第二顺位比较维

4.2 「未判定」不是 0，也不进分母——于是尺子长出了一个病理

有据盘上 本族有一条硬规矩：unknown 不许折成 0。落到算法上是不进分子也不进分母， 按「已知维的权重和」归一。这条规矩单独看是对的（缺依据不罚分也不加分）， 但它有一个副作用：在一维上「没证据」恰好躲开了「没证据所以打低分」的罚。

第一次算就撞上了：盘上 只有 3/5 维有依据的 V4 排到了原始第一（加权好度 0.756）， 把五维全有依据的 V1（0.740）压在下面。这不是数据错了，是这台机器的病理被真实数据照出来了。

处理办法是改尺子，不是改格子

有据盘上 在 数据/评分表.json 里加一条胜出资格线（win_rule.min_known_dims = 4）： 原始名次照原样印（不藏），但只有达到 4/5 维有依据的候选才允许被冠「胜出」； 若没有任何候选达标，脚本判 rc=3 而不是「取一个最接近的」。 这一条是本件自己第一次算的时候逼出来的，不是事后为结果找的补丁——它把「依据薄」这件事从脚注升成一个会挡住判定的机械条件。

4.3 每格的凭据要能回盘核，否则那个数字不算数

凭据种类核对方式（脚本实际做的动作）核不过时
disk 盘上文件存在 → 行号在实测行数内 → 引文（去空白后）确实在那一行或紧邻行 整格判红，格子不许出分
public 公开件指向的引用号必须是核级，且带 url + quote + checked_at 三样 判红：快照级数字不许进正文，这条同样管打分
estimate 假设必须同时带 assumption 与 falsifier（能把自己证伪） 判红：不许用「估计」当挡箭牌
relayed 转述词表里有这一档，但本件一次都没用 评分表里没有 relayed 凭据（计数由核对件自印）

也就是说：想给某一维填一个好看的数，必须先有一条能回盘核或能复跑的依据。这不是防错，是防自利。

道判据挡住的错法
K1权重合计 = 1总分不可解释
K2结构齐：4 垂类 × 5 维、不缺格不增格偷偷删一个候选或加一个候选来挪名次
K3格值合法：整数或字符串 unknown把 unknown 写成 0、写成 true、写成 null
K4未判定格必须带理由，且不挂凭据挂着凭据却说「没依据」，或空着却不说什么

取不到未量 本报告自己的一个缺口：这十四道 + 两道闸的「分辨力」尚未用反臂验过。 臂检件（工具/臂检-文档.py）计划要故意写错十二种地方——删凭据、权重改成 0.98、静默删一个垂类、 把 unknown 折成 0、把 disk 路径指向不存在的文件、只改 HTML 里一个总分、手写赢家、 整维全 unknown 却带权重、把第 7 章章名改成非赢家、插一个悬空引用号、 插一句没标 data-scan 的「没有取到」、把页脚日期改到 decided_at 之外， 外加一根「把某个候选的有依据维压到资格线以下 ⇒ 赢家必须换到次位」。 在它跑绿之前，本件不说「这把尺子会红」（波 2 未起的一半，口径件 §一）。

Chapter 5 · Score, Computed

5评分结果：本块由脚本生成，手改会被判红

下面这一块不是人写的。它由 工具/出表.py 从 数据/评分表.json 生成， 工具/文档核对.py 每次核对时用同一个实现重渲染并逐字比对（K10）。 灰格是「未判定」，不是 0；未判定既不进分子也不进分母。

5.1 怎么读这一块

看到什么它意味着什么因此能说什么 / 不能说什么
两个名次：原始第一与「胜出」不是同一个候选 原始第一那一行依据薄（3/5 维），被胜出资格线挡住 能说「它现在分最高」；不能说「它是最优方向」——薄依据本身是本轮最重要的发现之一
加权好度 0.740 对 0.756，差 0.016两个数在 ±20% 单维权重扰动下不翻赢家 能说「名次对权重扰动不敏感」；不能说「结论稳」——扰动只动权重，不动格子； 格子里那三个未判定一旦补上依据，名次可能整体重排
某一行的「已知权重和」小于 1.00那一行有几维根本没依据 必须原样印出来，不许用归一化把它藏成「全维优秀」
D5 带↓反向维：分数越高＝平台挤压越重＝对本件越差 颜色深浅一律表示「好不好」，不表示「高不高」

敏感性本轮只动权重、没动格子，所以它回答的是「权重我是不是手抖了」， 不回答「数据是不是还缺很多」——后一问的答案在第 2 章和第 5 章那三个未判定格里。

Chapter 6 · Collision Check

6撞车核对：每个候选必须自报撞了哪条已关闭方向

库里已经判死过一批方向。一份新报告若把它们换个名字再推一遍，它就是废纸。 所以本件把关闭方向做成机器可读的唯一真值源（数据/已关闭方向登记.json）， 核对道 K8 逐条检查：每个候选必须点名撞到哪一条（closed_collision）， 且差异说明必须含一个可证伪条件——条数由脚本现数并自印，本正文不写死。

候选撞到差异（要点）可证伪条件：什么一读出来，本差异就废
V1C9 C9 关的是「把证据包当商品单卖」。V1 卖的不是包，是一张挂尾款的收货裁决： 买方为「这一笔该不该付」付钱，不为拿到一份文件付钱。 若出现愿意单买一份包、既不挂裁决也不挂尾款的具名买方，则本差异不成立，C9 回到台面上。
V2C6 C6 的原话是「预算存在、坑位在平台内，不是单点账本件」。V2 不申请那个坑位： 它只做签字前那一道复核回执，真值取自既有制度文本，且要求交付方自己把产物落盘。 若下一轮取到的买方文件把这个复核写成 GRC 平台里的一个内置模块来采购，则V2 与 C6 同形，本差异不成立。
V3C3 C3 关的是通用审计日志，但同一行留着「只能做『说法-出处』差异层」这句。V3 就是那个差异层： 收口那一次核一份声明，不接、不存、不查询交付事件流。 若 V3 的形态变成需要接收并存储全量交付事件（即成为日志后端），则本差异不成立； 桌面端设计稿另有一条独立的降级条件：队列频率低于每周 3 次时把方向 B 降级为方向 A。
V4C1 C1 关的是「按承诺逐条记账」，理由是记账单位不对（需要会在承诺发生时发事件的宿主）。 V4 的记账单位不是承诺事件流，是一批交付 + 一次抽检裁决，宿主是采购方本来就有的验收动作。 若标注验收实际需要逐条承诺事件（而非按批抽检），则V4 退化成 C1，本差异不成立。
这一章存在的意义，是让「换个名字复推」变成一件会被机械挡住的事

有据盘上 关闭方向不是观点，是登记件里的行；撞车不是修辞，是 JSON 里的一个字段名。 缺字段、指向不存在的 id、差异说明为空、差异不可证伪——四种都判 rc=3， 而不是「算了让它过」。上一族的自否证（把定向检索没够着写成市场不存在）就是这么被做成 guard 的。
