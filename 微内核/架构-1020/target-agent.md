# 目标态 · 从记账件到「看得见循环」的智能体

图源：`target-agent.dot`（容器）、`loop-one-shot.dot`（一发的解剖）。本轮**没有改任何代码**，以下是形状与切分。

## 形状上只有一条硬规矩

循环住在**新容器**里，内核一个字都不动。理由是证据给的，不是审美：

- `README.md:9`：「它不调度、不联网、不执行工具、不写磁盘。那些是 Agent 框架的事。」
- `mcpsrv/mcpsrv.go:283`：`kernel.encode_journal` 只交字节，**不写盘**。
- `README.md:262`：审计面「住在 `cmd/` 而不是内核里，因为 `package kernel` 不 import `net/http`」。

一旦把循环写进内核包，这三句话同时作废，而这三句正是这套东西区别于「又一家观测工具」的地方。**所以目标态是加一块，不是改一块。**

## 四个要圈的决策（D1–D4）

### D1 循环宿主：Python 扶正，还是新写 Go `agentd`

| | A. Python（`tasks/mcp/`，3172 行已有实物） | B. 新写 Go `cmd/agentd` |
|---|---|---|
| 今天能不能零成本跑 | 能（`sdk/py314` 在盘上） | 能，但 `go` 不在 PATH，须给 `AGENTKERNEL_GOBIN`（`client.py:17-27` 已有这套解析顺序） |
| 能不能进发布包 | 不能（对外只剩 exe，Python 依赖跑到对方机器上） | 能，与现有 5 个 exe 同构 |
| 新增判据成本 | 0（已有 `Judge`，`client.py:169-179`） | 要给新容器配自己的针与判据，且要防它把格子往里塞 |
| 我倾向 | **先 A 后 B**：A 用来把回路证真，B 只在 A 的 KPI 非 0 之后才值得写 | — |

### D2 模型从哪来：三条驱动共用一个缝

循环体不许知道自己接的是哪家。三个驱动，**话术各不同，不许混用**：

1. **session（推荐先走这条）**：Qoder 会话本身当模型，通过已连的 `kernel.*` 10 件工具落账。零新增账号、零密钥、今天就能跑。
2. **scripted**：假端点按剧本回话（`agent.py:35` 那个 `MAX_TOKENS` 旋钮注释就写着「假端点靠这个旋钮走剧本」）。**只能证明循环机械正确，不能对外说「智能体在跑」**。
3. **real**：外部端点 `AGNES_BASE/AGNES_MODEL/AGNES_KEY`（`agent.py:28-30`，KEY 默认空串）。要凭证，不提议你去开任何东西。

### D3 持久化桥的节奏

`当前态` 那条「内存账 / 磁盘账两态、中间没有自动桥」必须由循环补上。三种节奏：每发落 / 每 N 发落 / 收口落。
判据不是风格：**收口落**时进程被杀 → 账本缺尾段，`kaudit` 载入必须能指出缺到哪一条；**每发落**时循环耗时上升要能被 `first_byte_ms` / `max_gap_ms` 这两格读出来。

### D4 判据表：智能体只消费，不新增（红线）

48 键 / 49 格已冻结（`contract.md:336` §3）。改这张表要「三件配齐」，不是顺手加一格的事。

但这里有一个**正向的联动**，是这次改造最值得拿的东西：kcheck 今天有两条 — 栏（本轮自印读数）

> — 输入侧：键名表 20 格，其中 20 格没有任何声明者读 …（框架未生产，还没有任何声明者；这一栏不是判定）
> — 输出侧：键名表 29 格，其中 29 格没有任何声明者读 …

`kernel.declare_reader`（`mcpsrv.go:279`）就是为这一栏准备的，而它是内核自己核不到的那一半（缺口第 1 条）。**智能体运行时就是那个「框架」**：循环每读一格就声明一次，49 格从「没人读」变成「有真声明者」，一格都不用新增。这件事只有智能体化能做，纯记账件永远填不上这栏。

## 一发循环的目标形状（`loop-one-shot.dot`）

`think → 按 §2.5 装两侧 → check_call 预检（副本上真跑，不写回）→ record_call 落账（两侧一起，任一不自洽整发拒收）→ read_back（session+发号+侧 三轴）→ POLICY 由账决定下一步 → 收口 → encode_journal 落盘`。

回边已有实物：`agent.py:53-60` 六条 `fail_kind → 动作`（transport 原样重发 / http 等一等 / config 停 / protocol 停 / malformed_action 换个说法 / budget 挤历史），`agent.py:61-66` 每次决定都记「第几发、依据哪一格、读到的值、动作、为什么」。

唯一 KPI 也已经有定义（`agent.py:8`）：**账本触发过几次决定。0 就证明这条边虚接。** 目标态不改这个定义，只是把它从示踪弹变成常驻。
