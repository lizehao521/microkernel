# AgentHub 1021 · 核心模块设计与数据流说明

一台**能对话、能自己挑工具真跑、把过程画出来**的本地 Web 应用。单二进制 Go 服务 + 零构建前端，
只监听 `127.0.0.1`。写完本件时现算的数在最后一节，每个数都有出处文件。

## 1. 一页结论

| 目标里那句 | 这台机器上是什么 | 在哪看 |
|---|---|---|
| 自然语言对话 | `POST /api/chat` 一句话进规划器，多轮同一本会话 | `httpapi.go:54` |
| 消息流式渲染 | SSE 逐事件推：`meta / plan / tool_status / tool_result / answer_delta / result / done` | `httpapi.go:129`（`推.发`）、`web/app.js:处理()` |
| 工具调用过程可视化 | 每一步画：工具名、参数与**参数来处**、状态（排队/试第几次/退避/重试/成功/失败）、返回正文、尝试次数、出处档 | `web/app.js:步节点()`、`retry.go:调一次()` |
| Agent 调度循环 | `选一步 → 门口预检 → 真调 → 观察 → 再选 → 收口`，带步数上限与三种结束原因 | `agent.go:RunTurn` |
| 工具注册与管理 | `Registry` + `ToolSpec` 说明书 + 清单挂载（`tools/*.json`），重名与影子注册判错 | `registry.go` |
| 上下文记忆 | append-only JSONL 会话文件；跨进程续发号；窗口裁剪带"挤掉几条"计数；**上一发的读数能绑到这一发** | `memory.go`、`planner.go:最大文件路径` |
| 错误重试与降级 | 按错误类别决定要不要再来；退避吃工具自己交的 Retry-After；用尽走备选并标 `degraded_from`；没有备选就记 absent 带理由 | `retry.go`、`agent.go:RunTurn` 降级段 |
| 易于扩展新工具 | 内置加工具 = 加一个 `quick(...)`；外部工具 = 放一个带 `triggers` 的 JSON；两者都不动调度循环 | 第 5 节 |
| 本地运行 | `go run . -port 8790`，浏览器开 `http://127.0.0.1:8790/` | 第 6 节 |

**一条硬边界**：本机没有任何模型口令，`-model-endpoint` 留空 ⇒ 选件的**全部**步骤由本机规则决定，
屏幕与读数上署 `estimated`；模型那一路由 `modelPlanner` 实现并用本机假端点把管路量通了，
但那不是真模型，文档与界面都不许说成"模型自主决定"。

## 3. 核心模块设计

### 3.1 注册表（工具的"说明书"是能读的）

`ToolSpec` 不只是名字：`params`（含类型与必填）、`risk`（6 档：local_read / compute / net_local /
net_remote / fs_write / exec）、`timeout_ms`、`retry`（次数、退避、上限、不重试类别）、`fallback`、
`requires_flag`、`triggers`、`source`（`builtin` 还是 `manifest:<文件>`）。

三条机械规矩：
- **重名与影子注册判错**，并把撞名记进 `Registry.shadow`，`/api/tools` 原样列出 —— 覆盖是静默的话，
  "这台机器有几个工具"就再也数不准了（`registry.go:92`）。
- **超时或重试次数没给 ⇒ 拒注册**。0 秒等于允许永久挂起，0 次等于一次也没试却算注册过（`registry.go:40`）。
- **参数校验按说明书逐条判**：未知键、缺必填、类型不对都返回 `bad_args` 且**在句子里列出可用参数名** ——
  把 `path` 写成 `Path` 时，忽略未知键的实现会拿着空路径去读根目录（`registry.go:140`）。

### 3.2 两道门口，都走在调起之前

- `FsGuard.Within`：路径必须落在 `-fs-roots` 内，并对已存在目录做 `EvalSymlinks` 归一化（符号链接逃逸走的就是这一步）。
- `NetGuard`：URL 主机必须在 `-net-allow` 内；拨号前再判一次（DNS 重绑的那类只看 URL 拦不住），
  重定向出清单也算失败；`预检()` 让**调度循环在调起之前**就挡下 —— 被挡的那一步 `attempts=0`，
  账上才分得开"压根没打出去"与"打了但失败"（`guard.go:113`、`agent.go:160`）。
- 风险档门禁：`fs_write` 要 `-allow-write`、`exec` 要 `-allow-exec`，默认关。被门禁挡下的那一步
  **不许**顺手降级 —— 找替身等于绕过用户的同意（`agent.go:135`）。

### 3.3 规划器：两个实现，出处分开署

`Planner.Propose` 每轮交回一个 `Action{kind: tool|done|ask}`。

- `localPlanner`（本机规则，`estimated`）：`抽目标()` 按触发词命中目标、**按词在话里出现的位置排序**
  （"先列再统计"不会被排乱），逐个目标看有没有成功观察；没有就造参数：
  路径/URL 从话里扒，扒不到就回看记忆里上一发留下的 `Data`（`最大文件路径` 把 `fs.list` 的
  `top + dir` 拼成真实路径），**再扒不到就 `ask`** —— 停下来问，不编参数、也不换统计对象。
- `modelPlanner`（`model_says`）：真发一次 OpenAI 式请求，把工具说明书与本机算的上下文摘要一起带过去，
  只把**已放行**的工具给端点看（不然它必然选到一个会被门口挡下的）。任何失败都交回 error，
  由循环记下"为什么降级到本机规则"再走 `localPlanner`。

### 3.4 调度循环（`Agent.RunTurn`）

```
①收到 → 记忆落一行 user
②选一步（model → 失败则 local，降级话进 Fallbacks）
③ask / done → 收口
④tool → 不认识 / 门禁未放行 / 出网预检拒 → 记 absent 带理由，continue
⑤调一次（每次尝试都推 tool_status；退避吃工具交的 RetryAfterMs）
⑥失败且有备选 → 降级参数 → 再调一次 → 标 degraded_from 并把"从谁降级来"写进这一步的结论
⑦观察进 pc.Obs + 记忆落一行 tool（含 Data，供下一发指代）
⑧同形失败（同工具+同参数再撞一次）⇒ Stop=重复失败即停；到步数上限 ⇒ Stop=步数上限
⑨收口 → 结论行分五档 + 本机摘要 + 窗口挤掉计数 + 端点没配就写 NOT_RUN（不写 0）
⑩整列过 12 条自洽判据 → sane 三态 + 原话
⑪agent 回话落记忆 + result 事件
```

### 3.5 重试与降级（`retry.go`）

`该重试` 只放行 `upstream` / `timeout` 两类，且吃工具说明书的 `no_retry_classes`；
`退避` 优先吃工具自己交的 `RetryAfterMs`（超过 `backoff_max_ms` 压回上限），没有就指数退避；
重试用尽后 `降级参数` 按对子映射参数（`fs.read→fs.list` 把文件路径换成上级目录），
一个参数都递不过去就**不硬调**；降级成功也要留 `degraded_from` + 结论里那句"从 X 降级来"，
判据会专门盯它（否则读起来就像原工具自己成功了）。

### 3.6 记忆（`memory.go`）

三种用途，都有针：① 跨进程续（重开同一本 JSONL，`NextTurn` 接续，坏行单独计数）；
② 窗口（按码元上限从最近往回收，**挤掉几条要出现在结论行里**）；③ 指代（每步的 `Data` 落盘，
下一发能绑）。摘要与"这一步是谁选的"分档写死：摘要是本机规则写的 ⇒ `estimated`。

### 3.7 判据（`sane.go`）

13 条有名规则 + 名册：`没成却署了measured`、`成了却没读数`、`absent没理由`、`五档加总不等`、
`步数句自己数错了`、`不认识的工具没标类别`、`端点没配却有model_says`、`成功了却一次也没试`、
`降级却没写从谁降级来`、`没放行却跑成了读数`、`空收口`、`署名不在名册里`、`同形失败重撞`。
两条纪律：**规则名不在名册里 ⇒ 判据自己判红**（写了分支没人认得等于没跑）；
每条规则都配一发谎发针（`hubd_test.go:TestSaneJudgeBitesEachLie` 九形 + `TestJudgeNameMustBeInRoster`）。
跨发判据另管发号接续、每发都交自洽读数（旧记录没这一格 ⇒ 算"没量过"，不塌成担保）。

## 4. 数据流（一次对话）

```
浏览器 textarea
  └ POST /api/chat {"text":"列一下 . 目录，再统计最大的那个文件"}
       └ hub.chat 抢锁（上一发还在跑 ⇒ 直接回"没排队、不混列"，不混列）
            └ Agent.RunTurn
                 ├ Memory.Append(user)
                 ├ 规划器链：modelPlanner? → localPlanner
                 ├ Registry.Get(tool) → 门禁/出网预检 → Tool.Run(ctx,args)   ← 真执行
                 │     · fs.list/fs.read 走 FsGuard.Within
                 │     · http.get 走 NetGuard（清单外主机 attempts=0）
                 │     · calc.eval 走本地解析器（不执行代码）
                 ├ 每次尝试 emit tool_status；每步 emit tool_result（Observation）
                 ├ 失败 → 退避/重试 → 降级 → 或 absent+理由
                 ├ Memory.Append(tool, Args, Data)      ← 下一发的指代材料
                 ├ 收口：Findings 五档 + 摘要 + 窗口计数 + 端点 NOT_RUN
                 ├ 自洽判据 → Turn.Sane/SaneWhy
                 ├ emit answer_delta（分帧）+ result(整个 Turn)
                 └ Memory.Append(agent 回话) → JSONL 落盘
```

字段契约（`event: result` 的 `Turn`）：`turn answer findings[] steps[] stop stop_why plan
fallbacks[] retries waited_ms degrades mix{measured,estimated,model_says,relayed,absent,total}
mix_ok sane(*bool) sane_why ms memory_msgs dropped_from_window context_chars_used`。
每个 step：`step tool args args_from class text data ms attempts degraded_from why
provenance evidence absent_why plan`。
`sane` 是**指针**：`null` = 这一发跑在判据上线之前 ⇒ 前端画"没量过"，不塌成红也不塌成过。
`stop_why` 只写**为什么停**，不抄答案：结论已经在 `answer` 一格、收口那条 finding 里各有一份。
先前"跑完"那一支把全文拼进 `stop_why`，前端结论带因此撑到 404 字 12 行（浏览器量的）——
一格一份，别处引用格名，不复制正文。

## 5. 加一个新工具（三条路，都不用动循环）

1. **内置**（Go）：在 `tools_builtin.go` 里 `add(quick(ToolSpec{...}, fn))`。给 `Triggers` 也没必要 ——
   内置目标在 `目标表` 里带触发词与造参逻辑。
2. **清单**（不重编译）：往 `-tools-dir`（默认 `<工作目录>/tools`）放一个 JSON：
   ```json
   {"name":"我的探针","summary":"…","risk":"net_local","timeout_ms":2000,
    "retry":{"attempts":2,"backoff_ms":40,"backoff_max_ms":200},
    "triggers":["探一下我的"],"params":[{"name":"url","type":"string","desc":"…","required":false}],
    "invoke":{"kind":"http_get","url":"http://127.0.0.1:8790/api/health"}}
   ```
   `invoke.kind` 现在认 `http_get` 与 `fs_read`（后者带 `root` 与 `max_bytes`，越界即拒）。
   `triggers` 让它进本机规划器的目标表；没写 `triggers` 就只会被 `tools.list` 数到、由端点选择。
   坏清单不拖垮启动：它进 `rejected` 并显示在 `/api/tools` 与右侧面板上。
3. **外部 API**：同样走清单 `http_get`，但要先把主机加进 `-net-allow`；不在清单里就是**门口挡**
   （`attempts=0`、句子里明写"没打到外面"），不是"打失败了"。

每加一个工具要走的验证：`go test -count=1`（含挂载工具那两形）→ `hubd -selfcheck`（25 条，
含"放一个 JSON 就多一个工具"那条）→ 页面上点一次看时间线有没有它的参数与状态。

## 7. 不承诺清单（写死，别读成"挡住了"）

- **审计层不是防线**：判据只能证明这台机器自己有没有说谎，不证明结论对世界正确。
- 真模型端点 **NOT_RUN**：本机没有口令；`modelPlanner` 只被假端点量过管路。
- 真人试读 **0/1**：页面上的"看得懂"由 AI 判据与 DOM 读数说话，不是真人反馈。
- 默认**不执行任何用户代码**；`exec.run` 默认关，开了也在临时目录里跑并带超时。
- 出网默认只 `127.0.0.1/localhost/::1`；未批准不把真流量打出去，也不占内核交付件的 8797/8799。
- `notes.write` 需要 `-allow-write`；被门禁挡下时不降级（不找替身）。
