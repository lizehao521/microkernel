## 0. 结论（TL;DR）

### 0.1 两张表：形态级与取证级必须分开

| 面 | 形态级（按代码行为能走到哪一级） | 取证级（按 PDF 七项指标能否定级） | 一句话 |
|---|---|---|---|
| **agentd** | **L2（下沿；宿主流程）** | **不足以定级** | 预定义 6–8 发记账流水线；一发内不需人逐步确认、可随时 SIGINT、可结算；但**无规划、无结果校验、无回滚**，`ledger_add` 只声明不执行。模型自主级：**NOT_RUN** |
| **pgagent** | **L2** | **不足以定级** | 固定九语义步；`/api/stop` 可随时停；失败只归因、不自动重试；无拆解/回滚。模型自主级：**NOT_RUN** |
| **AgentHub** | **L2（下沿；严格读只到 L1 上沿）** | **不足以定级** | 规则驱动多步 + 重试/降级 + 记忆；但**没有服务端停止入口**，L2 的「人类可随时打断」未做满。模型自主级：**NOT_RUN** |
| **微内核** | **N/A** | **N/A** | 被动记账件：不规划、不选工具、不执行；它不是 L 级对象，但可以是 L4「可审计」的底座 |

**按轴看（互审端独立判定，五轴顺序：人类介入 / 规划自主 / 错误恢复 / 跨域泛化 / 安全可控）**：

- agentd：**L2 / L1·NR / L2 / L1 / L2**；宿主流程取 L2 下沿，模型面 NOT_RUN。
- pgagent：**L2 / L1·NR / L2 / L1 / L2**；30/30 是同一合成任务，不能当业务闭环。
- AgentHub：**L1–L2 / L2 / L2 / L2 / L2**；严格按「随时打断」读，人类介入只到 L1 上沿。
- 内核：五轴 **N/A**；它提供审计底座，不是 Agent。

注意：**分轴高不等于总裁定高**。三面的规划轴都停在 L1/L1–L2，恢复轴最多 L2；PDF 的 L3 问句要「拆解 + 验证结果 + 异常请求人工」同时成立，没有一面满足。

### 0.2 三句话

1. **没有一面能签 L3。** PDF 的 L3 三条判据——独立拆解目标、验证结果、异常时回滚/请求人工——在这三面上都找不到实现件（agentd 只有记账自检，pgagent 只有归因，Hub 只有一次性降级）。
2. **L4/L5 不成立。** 三面都是单域；没有跨系统协作、并发多域、高风险审批、长期运行与成本报表；L5 的自我迭代与多 Agent 协同只存在于**我们这次的评估流程**里，不存在于被评估产品里。
3. **「L2」只是行为形状，不是经过任务测量的能力等级。** PDF 要求「10–20 个真实业务任务、20–50 次重复」；四个面都没有这个分母，三个带循环的面的**真模型端点全部 NOT_RUN**（本机 env 无任何模型口令，`driver.go:54-58` 等）。按 PDF 的取证口径，正式等级是**未定**，不是 L2。

### 0.3 最接近 L3 的是谁

不是 agentd。按「拆解 / 验证 / 回滚」三件逐条比：

| 件 | agentd | pgagent | AgentHub |
|---|---|---|---|
| 独立拆解目标 | 无（任务编译进二进制，`loop.go:113-119`） | 无（24 个关键词投票，`intent.go:20-72`） | 规则词表拆多目标，缺参反问（`planner.go:163-313`、`:454-494`） |
| 验证结果 | 只核账本哈希链，不核答案（无 oracle；`ledger_add` 不执行） | 只核账本自洽，不核「分析对不对」 | 13 条整列自洽，不核业务结果 |
| 回滚 / 补偿 | 无（append-only；只有「拒写」） | 无 | 只有一次性 fallback，不是回滚 |
| 异常时请求人工 | 无审批入口 | 失败归因后交人重发 | 缺参反问；高风险默认拒绝，不是审批 |

**结论：三面都停在「预定义流程内自主」这一格；AgentHub 在恢复机制上最接近 L3，但它的「可随时打断」比另外两面弱，且仍是规则驱动。**

## 4. 逐面证据

### 4.1 agentd（主面）

#### 4.1.1 它是什么

Go 宿主 `cmd/agentd`：内核是被动记账件，agentd 在宿主侧加 append-only 事件流 + SSE 投送 + 结算（E1–E5 已 Exercised，E6–E9 Planned/在改）。内核 v1 冻结：48 键 / 49 格，`README.md` §8「15 条为止，停止新增」。agentd **只消费格子，不新增格子**。

**它不是「模型自主 Agent」，是一条预定义记账流水线**：默认 `scripted` 驱动，横幅自己写「这一路是剧本走出来的绿，不是模型自主决定的绿」（`cmd/agentd/main.go:59-61`）；`Autonomous()` 对剧本返回 false（`driver.go:16-21`）；`real` / `session` 都只回 NOT_RUN（`driver.go:54-58`、`:66-68`）。

#### 4.1.3 典型流程（12 段，逐段 path:line）

1. 入口：`main.go:143 r.tRequest = time.Now()` → `:144 say(userAsk)` → `:155 r.loop()`；任务是常量（`loop.go:113-119`），**没有输入参数**。
2. 驱动选择：`main.go:63 buildDriver(*driverName, *script)`；选谁由旗标决定，不由模型决定。
3. 每发起点：`loop.go:327 turnEnter` → 先看 abort（`:330-337`）→ 剧本尽/额度到（`:338-345`）→ 回执先落盘（`:352`）→ 10s 看门狗（`:356`）→ `-shot-delay` 窗口（`:360-368`）。
4. 装配：`loop.go:370 assemble()`（`:291-317`）：system + toolspec + [history | 折成桩] + user + observation。
5. 驱动出提议：`:379 r.drv.Propose(...)`；`scripted` 按数组顺序、`fake` 真发 HTTP、`real/session` 回错。
6. 发号：`:393 r.shot = call`，只有真要发出去的那一发占号。
7. 预检：`:402 kernel.check_call`；预检拒 ⇒ `refused` 结算后 continue（`:419-420`），这一发一条都不写。
8. 落账：`:424 kernel.record_call`；账满 ⇒ `refused` + `stop=capped` 退出（`:456-458`），其他拒 ⇒ 结算后 continue（`:463-464`）。
9. 回边（唯一 KPI 来源）：`:475 readBackCell()`（`:543-560`）读 `output/fail_kind`；读不到记「本地信息，没问内核」，KPI 不加；读到且与当场值不漂移 ⇒ `r.kpi++`（`:504`）。
10. 账 → 下一发：`:496-499` 用 `POLICY[fail]` 选动作；`:570 decide()` 落两个旗标（budget ⇒ 折历史，malformed ⇒ 换说法）；动作以「停」开头 ⇒ 结算 `completed` + `stop=policy`（`:514-518`）。
11. 结算：`:523 settleTurn("completed", ...)`；`settleTurn`（`:254-287`）是唯一收口函数，`settled` 标志保证一发只结一次；相位表 `turnPhases`（`events.go:120`）算 reached/not_reached。
12. 收口：`main.go:156 closeOut()` → `loop.go:846-912`：关看门狗 → 印补位失败 → `run_settled`（stop token + stop_why + done/total/limit）→ `verify/tally/readers_report` → checkpoint → 写轨迹页 → `os.Exit(exitOf(stop))`。

**规划/反思/回滚三件**：
- 规划：**无**。只有「剧本还剩几发」这个静态计数（`loop.go:245-250`、`events.go:835-840`）。
- 反思（对账目）：有 4 件——`driftOf`（`policy.go:39-41`）、`confirmFold`（`loop.go:585-611`）、`verifyRoundTrip`（`:814-844`）、收口 `verify+tally+readers_report`（`:878-890`）。都是**记账自检**，不是「答案对不对」。
- 反思（对任务结果）：**无**。没有 oracle，`ledger_add` 不执行，84 只是剧本里的一句话。
- 回滚：**无**。append-only；两个近似物是「一发被拒时整发不写」（49 格原子，`mcpsrv.go:421-450`）与「续跑核链不符就拒写」（`loop.go:662-668`，rc=2）——这是「拒绝往下写」，不是「撤回已写的」。

**人类打断点**：SIGINT（`main.go:133-142` → `loop.go:134-148`，先交账再走）；进程内 `Stop(why)`（`:134-148`）；`-max-turns` / `-entry-cap` / `-checkpoint-every`。**没有**运行中审批、暂停/继续、单步确认、第二发入口。

### 4.2 pgagent（编程 Agent）

#### 4.2.1 它是什么

### 4.3 AgentHub（通用 Agent 应用）

#### 4.3.1 它是什么

`AgentHub-1021`：12 个工具（11 内置 + 1 清单挂载），5 个 HTTP 路由，2 个 planner：

- **内置 11 个**（`tools_builtin.go:74-389`）：`fs.list` / `fs.read` / `text.stats` / `calc.eval` / `time.now` / `http.get` / `tools.list` / `memory.recall` / `notes.write` / `exec.run` / `demo.flaky`；另 1 个由清单挂载（`registry.go:350-353`）。`demo.flaky` 是自检用故障注入工具，不是业务能力。

## 7. 红队：判定的反面与证伪条件

（互审端 23:50 已回填；本节已与 `互审-分级判定.md` §5 交叉，保留双方一致与分歧。）

### 7.1 支持 L3 的最强论证（以及为何不成立）

**最强论证（pgagent，不是 Hub）**：它是三面里最接近 PDF L3 门槛的——单域（代码审查）、9 个语义步固定走完、30/30 同一任务连发不劣化（`报告-验收.txt:12`）、22/22 边界、跨进程 2 程 × 2 发续号对链（`:17`）、`traceSane` 11 条 + `chainSane` 6 条整列自洽、人可随时 `/api/stop` 或断连。按 PDF「单域内能稳定闭环，但跨系统还不稳定 → 更接近 L3」（`1792678944187.txt:149-152`），它看起来可以签 L3。**AgentHub 是更弱的候选**：12 工具 + 规则拆多目标 + 重试/降级 + 13 条判据，但 6 步上限、双目标 0/1、无服务端 stop；agentd 更弱：无输入面、无 oracle、无回滚。

**为何不成立**：
- **先给「规则/剧本不算规划」这条留最大让步**：就算把 Hub 的词表拆解、pgagent 的意图投票、agentd 的剩余发数都暂时算作「规划」，L3 的关键问句仍缺两项硬件（PDF:31）：
- L3 要「**验证结果**」：三面都只核账本自洽（哈希链、五档、counts），没有业务 oracle。agentd 的 `ledger_add` 不执行，84 只是剧本里的话；pgagent 的 `chainSane` 只证账没断、不证审查结论对；Hub 的 13 条整列自洽也不核业务结果。
- L3 要「**异常时请求人工**」：Hub 缺参反问算一小半，但异常（工具失败、步数上限）只降级/停；agentd 没有审批入口；pgagent 失败归因后交人重发。都不构成「异常时主动请求人工」的闭环。
- 再退一步看「**独立拆解目标**」：Hub 是 11 条目标词表且双目标 0/1，pgagent 是 24 个关键词且空问题照跑，agentd 根本没有输入面。「不是模型在拆」是解释，不是唯一理由；**可观测证据本身也不够**。
- L3 的级别特征还写了「**回滚**」：三面都没有。agentd 是 append-only + 拒写；pgagent 没有（打断只收口不撤回）；Hub 只有一次性 fallback（不是撤回已发生的动作）。
- **「稳定闭环」是合成闭环**：pgagent 的 30/30 是同一合成任务 + 假端点；22/22 是输入边界，不是 22 个业务任务。PDF 要的是 10–20 个真实业务任务，这里一个都没有。前提不成立，不能拿 `:149-152` 那条规则把任何一面推到 L3。

### 7.2 支持 L1 的最强论证（以及为何不成立）

**论证**：三面的所有「绿」都是剧本/假端点/本机规则走出来的；真模型端点全部 NOT_RUN（agentd `driver.go:54-58`；pgagent `gateway.go:165`；Hub `main.go:75`）。如果按「模型自主」定义 Agent，那么它们连「模型选了一次工具」都没有发生过：Hub 的选件来自 11 条目标词表（`planner.go:163-313`），pgagent 的意图来自 24 个关键词（`intent.go:20-72`），agentd 的提议来自固定剧本（`driver.go:81-96`）。按这个读法，三面都应记 L1 甚至「不是 Agent」。

**为何不成立（作为整体定级）**：L1 的判别问题是「每步是否都要人确认？失败是否只能交还人工？」——三面都不是每步确认：agentd 一发内 0 次确认、可 SIGINT；pgagent 1 次输入后九步自动走、可 `/api/stop`；Hub 1 次输入后最多 6 步自动走。它们都有失败策略/停止窗口，不是「失败只能交还人工」。所以整体不是 L1。

**但这个论证赢了一半**：它正确地指出「模型自主」这一栏是 **NOT_RUN**，不能记 L2。正确处理是**拆两栏**：宿主流程级 L2 结构（可观察）+ 模型自主级 NOT_RUN（没发生）。**agentd 还要再拆一层**：宿主流程是 L2 形状，但工具不执行、无任务入口，作为 Agent 的实质更接近 L1；应写「L2 形状 / L1 实质」，不能直接判 L1，也不能把宿主流水线当成模型 Agent。
