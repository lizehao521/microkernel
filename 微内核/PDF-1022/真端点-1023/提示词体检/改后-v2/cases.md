# 相似案例 Top-3

## 案例 1：case-089（相似度 0.1736）

- **类型**：tool-call
- **问题标签**：no-failure-handling
- **适用场景**：把一份长文档交给工具链自动生成摘要存档

**原文（病灶版）**：

```markdown
调用 read_file 工具读取用户指定的文档，提取正文内容，再调用 write_summary 工具生成摘要文件。
```

**诊断**：两段工具调用首尾相接，但路径不存在、文档无法解析、写入目标缺失时的处置完全未定义。

**重写版（好样子）**：

```markdown
## 触发时机
当用户说「总结这份文档」「把它压成摘要」时进入本流程。

## 调用规范
1. 先调用 read_file 读取指定路径
2. 提取正文后将摘要暂存于内存
3. 确认目标路径后再调用 write_summary 落盘

## 输出
输出 summary.md：正文摘要 + 原文出处两节。

## 失败处理
- 路径不存在：回报用户并请求有效路径
- 文档无法解析：说明格式不支持并列出支持格式
- 写入失败：提示目标被占用或权限不足

## 边界
不覆盖已存在的同名文件；不做原文档删除操作。
```

## 案例 2：case-130（相似度 0.1652）

- **类型**：tool-call
- **问题标签**：no-failure-handling
- **适用场景**：跨日历排会前先扫一遍冲突

**原文（病灶版）**：

```markdown
调用 check_calendar 工具读取用户日历，找出互相冲突的日程，调用 notify_user 工具提醒用户调整。
```

**诊断**：两段调用首尾相接，但日历为空、授权失效、工具超时时如何处置完全没有交代。

**重写版（好样子）**：

```markdown
## 触发时机
当用户说「看看日程冲突」「帮我排一下会」时进入本流程。

## 调用规范
1. 调用 check_calendar 读取指定日期区间
2. 比对起止时间找出重叠场次
3. 冲突时调用 notify_user 提醒并建议可选时段

## 输出
输出 conflicts.md：冲突清单（场次 A / 场次 B / 重叠时长）+ 建议一节。

## 失败处理
- 日历为空：回复「该区间暂无可读日程」
- 授权失效：提示重新登录后重试
- 工具超时：告知用户稍后重试

## 边界
不做日程删除或改动；不代用户回复会议邀请。
```

## 案例 3：case-007（相似度 0.1423）

- **类型**：tool-call
- **问题标签**：no-output-contract、no-failure-handling
- **适用场景**：Agent 接天气 API 时的调用规范段

**原文（病灶版）**：

```markdown
当用户询问天气时，调用 get_weather 工具查询天气并告诉用户。
```

**诊断**：工具调用指令未约定入参从哪来、出参以什么格式回给用户；工具报错、城市不存在、返回超时三种失败路径全部缺失，一旦异常模型只能现场编。

**重写版（好样子）**：

```markdown
## 天气查询工具调用

### 触发
用户询问某城市天气时使用 get_weather。

### 入参
- city：从用户消息提取；用户未说城市时先反问，禁止默认城市

### 出参呈现
固定模板：`{城市}当前 {天气}，气温 {温度}。`

### 失败处理
| 工具返回 | 应对 |
|---|---|
| 城市不存在 | 告知用户并请其确认城市名 |
| 超时/网络错误 | 告知查询失败，建议稍后再试，禁止编造天气 |
| 参数缺失 | 反问用户补齐，不发起调用 |

```
