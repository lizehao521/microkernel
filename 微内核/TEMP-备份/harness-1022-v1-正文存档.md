## 0. 五条结论（带分级，分级依据见方法与分母 §二）

1. **[High]** 没有任何一份本轮读到原文的规范，要求「逐调用机器可读账本」。MCP 的进度件规定的是**进度值与完成即停**，A2A 规定的是**任务状态机**，LSP 规定的是 **begin/report/end 三段 + 数值要递增**；三者都不含「受理回执」「出处分档」「停止后的结算载荷」这三件——那三件是本研究件**自己加的**，不是行业惯例。（P21 已由波 2 对规范原文复核；**P20 的 A2A 状态机与终态关闭流、P22 的取消语义只到「波 1 子代理读到原文并逐字引用」这一层，波 2 预算内未复核 ⇒ 本条只以 progress 支撑，另两段标 待复核**；P23 LSP 为规范页快照）
2. **[High]** NIST AI RMF 在 nist.gov 官网原文里就写明「is intended for voluntary use」；生成式 AI Profile（AI 600-1，2024-07-26）同属自愿文件。**「不规定任何交付物」是我从「自愿」推出来的，不是原文话** ⇒ 正确说法：这两份文件都**不要求任何特定的留存件**。另须补一句：nist.gov 同时写明 AI RMF 1.0「正作为白宫 AI 行动计划的一部分被修订」。ISO/IEC 42001 是自愿可认证的管理体系，认证审计吃的是**过程记录**（C7 官网原文、C10 ISO 板块页、C11 ISACA）。
3. **[High]** 篡改痕迹（tamper-evidence）不是已解决的类目：Apple 的 CT 日志计划原文要求日志「不得在不同时间、或对不同方，给出 Merkle 树的两个及以上冲突视图」（L42 已读原文）；RFC 6962 的安全考虑一节标题即为「Misissued Certificates / Detection of Misissue」⇒ 威胁模型是**发现错误签发**，不是担保记录为真（L41 已读原文）。所以「防篡改 = 可信」这句话站不住。**（波 2 更正：我先前写的「CT 当前定义件是 RFC 9162、Experimental 轨、obsolete RFC 6962」中，后两个限定词没对 rfc-editor 原文核到 ⇒ 撤；且 Apple 现行政策仍要求至少一张来自符合 RFC 6962 日志的 SCT，不能暗示 6962 已退役。）**
4. **[High]** 监管真正接受的是**存储配置判断**而不是内容判断：S3 Object Lock 的 compliance mode「不可被覆盖（含 root 账号）」，配合 Cohasset Associates 对 SEC 17a-4 / CFTC / FINRA 的评估——限定语「when correctly configured」。也就是说，「被接受」的形态是把留存配置变成可评估对象，而不是「我的哈希链很硬」。（L47/L48 已读原文）
5. **[Medium]** 本件可防守的差异点不在「记账」本身：Langfuse 定价页原文把**审计日志与 SCIM 锁在 Enterprise（$2,499/月）**，而 **SSO 强制出现在 $300/月的 Teams 加购档或 Enterprise**（**波 2 更正：我原先把 SSO 强制也算进 Enterprise，错了**）；留存按 30 天 / 90 天 / 3 年分级；SOC 2 与 ISO 27001 在 Pro 及以上（M77 原文已读）。「自托管为 MIT 许可」不写在定价页上 ⇒ 撤，待取 LICENSE 件再说。预印本 **Traccia**（arXiv:2607.14309，2026-07-15）确实存在，作者自述在 OpenTelemetry 之上「追加防篡改指纹与 SHA-256 内容哈希」以把 trace 映射到监管要求、证据导出为受哈希保护的单份 JSON；**「开源」未核到 ⇒ 撤；「作合规证据」要降为「作者自述的映射尝试」——预印本，未经评审，也不是任何监管接受的方法**。因此本件尚未被占的形状是：**被动、本地优先、出处分五档、且停止必须结算**——而这四点目前只有计划态证据（事件层 E1–E9 一行代码未动）。

## 1. 三份成熟规范到底规定了什么（原文，已读）

| 规范 | 规定的内容 | 对本件的意义 |
|---|---|---|
| MCP 2025-06-18 Progress（P21） | 客户端在 `_meta` 里给 `progressToken`；同一 token 内 `progress` 值 **MUST increase**；`total` 可选；**请求完成后通知必须停止**；服务端 SHOULD 限流 | 「数值必须递增 + 完成即停」与本件契约 §5 的单调 seq 与终态事件一致 ⇒ 这两件可以写成「照标准」 |
| MCP 2025-06-18 Cancellation（P22） | `notifications/cancelled` 带 `requestId` 与可选 `reason`；服务端 SHOULD 停止、释放资源、不再发送响应；对已完成/未知 id **可以忽略**；**迟到的响应属预期**；整体 best-effort | 标准**只要求尽力停**，不要求说明「停在哪一步、已经发生了什么、没发生什么」，也没有任何回执 ⇒ 本件的「停=结算」严格高于业界底线，这是差异点也是成本点 |
| A2A v1.0.0（P20） | 显式状态机：submitted/working/input-required/auth-required → completed/failed/canceled/rejected；**终态后不得再收消息**；流必须在终态时关闭；`tasks/cancel` 只是「attempt」，非可取消态返回 TaskNotCancelableError，重复取消可能返回 TaskNotFoundError | 「终态冻结 + 关闭流」与六态退出码是同一族思想；但 A2A 里**没有**出处分档，也没有「没量到必须写理由」这一层 |
| LSP 3.15+/3.18 Work Done Progress（P23） | `$/progress` 的 begin/report/end 三段，挂在 token 上；「The value should be steadily rising. Clients are free to ignore values that are not following this rule」；percentage 可选（即无限进度合法）；`cancellable` 控制是否显示取消按钮，「取消 work done progress 就是取消对应请求」 | 这是与本件 `turn_accepted → step → settle` 最接近的既有先例；注意它把「客户端可以忽略不守规矩的值」写进了规范——**规范的宽容不等于可信**，本件的针8（界面不许自算）正是在补这一刀 |

**一句话结论**：本件事件契约里的单调序号、终态关闭、数值递增三件有标准依据；受理回执、五档出处、结算载荷三件没有。报告与对外材料**必须分开表述这两组**，把后一组说成「业界做法」就是营销夸大。

## 2. 「自愿」两个字的原文重量

- nist.gov 的 AI RMF 项目页原文即为「is intended for voluntary use」（C7，已读官网）。AI 600-1 于 2024-07-26 发布，属同一族自愿文件；其 12 个风险类、200+ 建议动作是**建议动作清单**，不是交付物清单（C8 独立复证日期与自愿属性）。
- ISO 板块页确认 42001:2023 是这一族里唯一可认证的管理体系标准，正文付费（CHF 225），因此**条款级记录清单无法从公开网核实**（C10）。这条方法论限制本身就是结论之一：任何声称「ISO 42001 第 X 条要求保存 Y 个月日志」的公开材料，都应当要求对方出示条款原文。
- 实操侧：42001 与 27001 同族，团队做法是把 AI 控制项「折进既有审计节奏与证据里」（C11，ISACA）。这直接推出一条对本件不利的采购惯性：**审计师接受复用既有证据管线，新的机器可读运行时件要自己论证为什么值得换**——而不是默认别人想要。
- 反面样本（只能当证据用，不能当事实）：一家中文 ISO 42001 代办机构在页面上声称现场审核会问「是否保存至少 12 个月的输入输出日志供追溯」，并把它归给「Clause 8.2.3 及附件 B 的强制性要求」。本轮在任何 Tier1/2 源里都**找不到**这条 12 个月留存强制要求（C13）。它的正确用法是：证明**存在把自愿框架包装成强制要求的中介话术**；这与学界对合规评论的利益相关审计结论同向——卖合规服务的来源自称无偏见，实则既有既得利益（C18）。

## 5. 账本完整性：能证什么、不能证什么（原文已读）

- **两类证明不是一件事**。RFC 9162 把 CT 定义成 Merkle 树 + inclusion proof + consistency proof；RFC 6962 §7 的安全考虑标题就叫「Misissued Certificates」「Detection of Misissue」——威胁模型是**发现错误签发**，不是担保记录为真。原文里甚至写明日志「可以接受过期、尚未生效、被吊销或其他不完全有效的证书」，只要求拒掉不可验证的链：**结构诚实，对真假 indifferent**。
- **写方连续性靠政策，不靠数学**。Apple 的 CT 日志计划把「不得对同一 Merkle 树给出两个及以上冲突视图」列为准入要求（L42 原文）。这正是本件 `resume` 读回先核链那一跳在**没有**的性质：链对得上只证明没被剪，不证明没被同时展示两个版本。
- **最强账本也会漏**。2025 年 GoDaddy 事件：证书内嵌的 SCT 对 DigiCert "Yeti 2025" 日志密钥**签名无效**，根因是 CA 自己没做 SCT 签名校验，**树没发现，外部研究者发现**，2025-05-24 吊销（L43 bug 原文）。对本件的可迁移结论：签名校验必须是**写之前的强制闸**——本件的对应物是核链不符就拒写（退出码 2），方向对，但只覆盖「我自己写的」，不覆盖「别人会不会拿到两本账」。
- **完整性缺口的可引形式**：2022 年监控可靠性研究发现，若监控方无法为某个主体返回**完整**集合，欺诈证书就检不出，CT 的担保随之塌（L45）。这与本件已知缺陷同族：`read_back` 不给指纹、`load_journal` 可被换账。
- 学理句（预印本，须标注未评审）：「哈希不证语义为真，签名不证授权，外部锚不证捕获完整」；「它构成的是自述主张，不是完整性保证」（L52，arXiv 2609.08481）。
- **QLDB 是本节最有说服力的产业注脚**：营销语「由中央可信权威维护的不可变、可加密验证的事务日志」（L51 原文），2024-07 停新签、2025-07-31 停止支持，迁移目标 Aurora **不维护永久不可变变更记录**，历史必须作为审计数据存在库外（L49/L50，待抽查坐实时点）。一句结论：**可信权威托管账这个形态被 AWS 自己撤了；要把信任外移，就得有非写方的验证者**（Let's Encrypt 同时运营日志**并**开源监控器 CT Woodpecker，因为日志方不能自证清白，L58）。

## 6. 「被接受」长什么样：存储配置，不是记录语义（原文已读）

S3 Object Lock 的 compliance mode「不可被覆盖，包括 root 账号」，并经 Cohasset Associates 针对 SEC 17a-4 / CFTC / FINRA 的 WORM 要求评估（L47）；同一评估结论在第三方栈（IBM Ceph）上复现，且带限定语「**when correctly configured**」（L48）。
⇒ 三件事同时成立，必须一起说：
1. 评估机构判的是**配置与流程**，不读记录内容；
2. 因此「49 格分档出处」在监管眼里没有直接价值，它的价值在**内部复核**（谁的哪一次调用被账本改写过结果）；
3. 本件若要进入受监管采购，正确的卖法是「把留存与不可逆配置变成可评估对象 + 提供可分发的复核件」，而不是「我的账本很硬」。这与 §2 的「审计师接受复用既有管线」是同一件事的两面。
