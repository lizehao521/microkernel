## 2. 判据一条命令：`agentd -check-log`

判据的口径只在这一个二进制里有一份。尺子（冒烟、别的会话）**不许自己在 Python 里再数一遍** ——
各数各的就会出现「Go 红、Python 绿」两头不认账的日志（上一轮两路 M2 都点到这一条）。

```bash
cd 微内核/微内核
C:/Users/Admin/sdk/go/bin/go.exe build -o "$TEMP/agentd.exe" ./cmd/agentd
"$TEMP/agentd.exe" -check-log <一本事件日志> [-ack-limit-ms 100]
```

读数一行一个，制表符分列：`check-log  <判据名>  <它管什么>  GREEN|RED  <为什么/条数>`，
最后一行 `check-log  口径  ack_limit_ms=<用的哪个数>`。退出码：**0 全绿 / 4 有红 / 2 日志读不动**。

四支判据：`ValidateLog`（序号接续 + 状态白名单 + 出处五档 + absent 必带理由 —— 22:4x 起读回路径也真查这三样，以前只有写侧 `validate()` 查，注释却声称读回也管）、
`ValidateAccepts`（每发第一条是回执 + 预算 + 载荷给全）、
`ValidateSettlement`（一发恰好一结、相位齐、counts 逐名对得上、不许半结算）、
`ValidateReplay`（尾游标接得上）。

**限度分离（重要）**：`ack_limit_ms` 默认 100 是**契约预算**。本机实测同一形态两跑分别是
`29ms` 与 `516ms` —— 也就是说 100 这一档在本机**偶发会真红**。所以：
- 判「结构对不对」（第一条是不是回执、counts 对不对）时传 `-ack-limit-ms 60000`；
- 判「宿主承认收到它有多慢」时单独跑一次 100，把它的读数当**发现**记下来，别当闸。
两次的读数行都会写明用的哪个上限 —— 放宽过的读数不许冒充契约预算下的读数。

## 3. 臂检（全绿先问这把尺子会不会红）—— 只有一件是 owner

**`臂检-全部族.py` 是唯一的臂件**；A/B、C、D、E、F 那五件散件已被它并掉（历史散件留在
`TEMP-备份/臂检散件-1022/`，别再单独跑 —— 两份闸会各说各话）。签名：
`<py> 臂检-全部族.py <go.exe> <树根>`，先跑 `--anchors-only` 预检（只核每根锚的命中数，不跑测试）。
规矩统一：**先跑未变异对照（必须绿）→ 落变异（必须红）→ 编译崩/进程崩单列**（崩不算红）；
锚没接上单列 **NOT-WIRED**（与 BLIND 分档 —— 一个是臂坏了，一个是判据没牙）。

分母不写死在文档里，从读数现数（这条命令自己印族、根数与 verdict）：

```bash
cd 事件层-1022
C:/Users/Admin/sdk/py314/python.exe -c "import json,io,collections;c=collections.Counter(json.loads(l)['arm'].split()[0] for l in io.open('读数/臂检-全部族.jsonl',encoding='utf-8'));print(dict(c),'total',sum(c.values()))"
```

读数落 `读数/臂检-全部族.jsonl` + `臂检-全部族-读数.md`。**看三件事，不是只看「咬了几根」**：
`control_rc` 必须 0（对照不绿 ⇒ 这一根的结论全作废）、`mutant_build_broken` 必须 False、
`verdict` 不许出现 `BLIND`。

四个已知的坑（都真犯过）：
- **锚文本漂了会报成 blind 而不是「变异没接上」**。例：`countsFor(r.turns)` 改成
  `countsFor(r.session, r.turns)` 之后 C3 一度报 blind。改签名之后必须回来看臂的锚文本。
- **臂要指在走得到那条分支的负载上**。例：counts 的键退回「只按 turn」那一形，只有**跨趟日志**能抓住；
  指在单趟负载上就是恒绿假盲区。
- **变异把声明拆了是 BROKEN 不是 BLIND**：`if err := f(); err != nil {` 整条换成 `if false {`，
  `err` 就没被用过 ⇒ 编译崩；range 键同理。恒假写法要保留声明与引用：`err != nil && false`、`m[k] && false`。
- **判据前置之后，后面那道同形 guard 就成了走不到的第二层保险** —— 臂指在它上面必然恒绿。
  例：`checkPhaseShape` 加了前缀比对后，`reached` 里那句「表外相名」的 guard 再也走不到（F7 报 BLIND 的原因）。
  做法：把靶搬到**真会开火的那一层**，并在文档里点名旧 guard 是冗余层、不许宣称有牙。
- **计时型针在并发编译下会抖**：`TestInterruptSettlesWithinSecond` 断言「打断后 1 秒内交账」，
  臂件连着编两轮时 CPU 抢不过 ⇒ 对照不绿（`CONTROL-NOT-GREEN`）。单跑 `-count=5` 全绿。
  那一根的读数**作废重跑**，别写进「全咬」。

## 5. 两把尺子（证据件自证）

```bash
cd 事件层-1022
C:/Users/Admin/sdk/py314/python.exe 锚点刷新.py     # SPEC 驱动，按符号反推 sourceRefs 的行号；找不到符号就 rc=2 且不写盘

C:/Users/Admin/sdk/py314/python.exe 证据模型核对.py # event-layer.evidence.json 自洽：引用回盘、端点闭合、状态口径、分档
C:/Users/Admin/sdk/py314/python.exe 尺子自证-旧病复现-1023.py # 把尺子二修掉的两个旧病注回内存副本，验新臂真会红
```

- 两把尺子的退出码 **3 有两种成因**：真有坏件 **或 臂没红**。臂没红时「全部命中」不作数，读数行会写
  「不写『已核对』」。
- `证据模型核对.py` 分两档印分母：**符号可核 N 条**（自己回盘反推行号来比）/ **仅存在性 M 条**（只验文件在、行界内）。
  别把「N 条全部可解析」说成 N 条都核过。
- 这一档的分母**必须由 `锚点刷新.py` 的 SPEC 全量喂进来**。10-23 抓到两例尺子自己的病，都是「少核了但照印 PASS」：
  1. `refresher_spec()` 只解析 `SPEC = {…}` 字面量，看不见 `SPEC["ev.sse"] = […]` 这类**追加式赋值** ——
     E4/E5/E7/E8 的 21 条带行号引用被整体降成「仅存在性」，符号可核停在 32 而 rc 仍 0。
     现在读数里多一行「符号档形状：SPEC 槽 N（字面量 x ＋ 追加 y）｜ 解不出来的 z」，`unparsed` 非 0 就点名。
  2. `audit()` 的返回字典里 `"mis"` **写了两个键**，后一个把 `mis + sym_bad` 覆盖成 `mis` ——
     符号档坏点进了报表却没进判 rc 的那份清单（「[符号对不上]」挂着，退出码 0）。
  两例各钉一条臂（A5 / A4b），`尺子自证-旧病复现-1023.py` 把旧代码注回内存副本跑三遍：
  **注病必红、基准必绿**，否则那两条臂就是装饰。判「有没有牙」只看 `sym_bad>0 而 mis=0` 这一对数，
  不看 rc —— 注病那一份的 rc=3 是臂自己死了拖红的，读成「抓到了」就上了当。
- `锚点刷新.py` 的 SPEC 里**不许写死对齐空格**（gofmt 重排一次就哑，而且尺子拒写会连带把另一把尺子的臂顶失效）。
  写死格式的地方一律 `\s+`。
- **新增 SPEC 槽一律用追加式**（`SPEC["x"] = […]`）或字面量都行，但改完必须重跑 `证据模型核对.py`
  并核对「符号可核 N」是不是等于 `锚点刷新.py` 自己印的 `refs total=`。不相等就是有槽没进档 ——
  这一条对账 10-23 之前没人做，所以那 21 条漂了整整一轮没喊。
