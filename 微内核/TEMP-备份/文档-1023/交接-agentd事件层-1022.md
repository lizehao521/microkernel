## 3 三态清单：这些不许被下一个人读成「已验」

**NOT_RUN（本机做不了，不折算成 0）**
- `-race`：需要 cgo，本机跑不了 ⇒ **并发安全是「未确证」**，不是「测过没问题」。`eventBus` 三个共享态
  （`seq` / `written` / `states`）只有静态读码支撑（`Emit` 全程持锁）。
- 真模型端点：env 里没有任何口令。`-driver real` 只演到 `NOT_RUN` 就收口。
- 真人可读性 0/1：这条流要给界面当底，人看不看得懂 `resumable:false` + 那句 why，没人看过。
- OS 级 SIGINT 只在单测窗口里演过，exe 那一侧没确证。

**NOT_MEASURABLE（形状存在，本机这个位置量不了）**
- 「同一游标重放两次得到同一序列」在真进程上测不了：投送层随进程生死（进程在 ⇒ 日志一直在长；
  进程停 ⇒ 端口已关）。这条性质由 Go 侧 `TestReplayTwiceGivesSameSequence` 在**封板日志 + HTTP** 上钉。
  ⇒ **架构后果待拍**：界面（E7）要断线重连，投送层必须在收口之后继续活着（独立 serve，或收口后 hold 一段）。

## 4 三处**偏离契约**，等作者认（我不自己定）

1. **身份四元组**：日志跨趟接续后同一 session 会有两条 `turn=1`，而 `seq` 是**发内**序号
   （`Emit` 里 `e.Seq = b.seq[e.Turn]+1`）。所以事件身份与 SSE 游标都要带 `run` 轴：
   `(session, run, turn, seq)`，重放尾部按**日志行序**切，不按 seq。
   这比 §5.2.6 写的三元组多一段。**要么改契约文本，要么这套重放在跨趟日志上不成立。**
2. **针1 的锚点与预算**：`enteredAt` 现在钉在「进程拿到这个任务的那一刻」（`main.go` 的 `r.tRequest`），
   回执前那段包含 `newEventBus` 为接续序号**读回整本既有日志**的开销 ⇒ 跨趟日志上实测
   `516ms` 与 `29ms` 两跑不同。100ms 这一档在本机**偶发会真红** ⇒ 现在的处置是限度分离
   （闸吃 60000，预算 100 单独判读当发现）。**要不要把「接续读账」挪到回执之后**，是个设计决定。

3. **E6「一发一锁」在这棵树上没有入口可钉**（复算过，不是偷懒）：`cmd/agentd` 唯一的 HTTP 面是**只读**的
   `/events`（`sse.go:146 sseHandler` / `sse.go:200 serveEvents` / `sse.go:211 eventsMux`，全树再无第二个 handler），
   一发是由 `main.go` **一次性**起 `r.loop()` 的 CLI 进程内循环 —— 没有「第二发从外面进来」那条路，
   所以契约 §5.7/§15 要的「入口加锁、直接拒、把在跑的 (session,turn) 报回去」**没有产品落点**。
   已经成立的是**另一半**：混列由身份四元组挡住（`run` 轴 + `blockOf`，跨趟 append 的两列各归各，臂 E1/E 族），
   而「同一进程并发起两发」这一形在 sibling 面（pgagent W24 针 33 + 重入保护）才有对应物。
   **要么给 agentd 加一个起发的入口（新攻击面，我不自作主张），要么把 E6 改成「身份轴已覆盖，入口级锁不适用」**
   —— 「不适用」别说成「挡住了」（这条是本现场的房规）。

另外三个待圈的问题沿袭上一轮：针4 的「已完成计数」以哪一格为准（发级 `done_before_shots` / 趟级
`progress.done` / `tally÷49` 真落账数）；落盘写失败要不要改退出码；`resumable` 的逐字段出处算哪一档。
