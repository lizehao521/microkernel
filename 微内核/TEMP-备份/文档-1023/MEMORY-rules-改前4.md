给他写文档、报告或结论时守这六条：

1. **「红不了的承诺是散文」**：任何断言要能被一次失败证明，否则他不认。写"已守护"之前先问哪条判据/哪根针会让它红。
   **针要钉危害、不钉形状**：钉"非零"守不住"限得太狠"（他把 `IdleTimeout` 那根从"非零"改成钉数值量级才咬住），
   同理 10-17 立的一条是"两个桶不许共用同一句话"——测法是让两桶的数**各自必须动**，
   坏字节把话术并成一句就红；光断言某句话在不在，数字是 0 也照样绿。
   **写针/写测试之前先确认它在今天会红**：那次我第一版只断"两桶各走各的数"，而数**本来就是分开的** —— 那一版会直接绿，
   就是一根 `VACUOUS` 针（与封板轮那两根空针同一个病因：夹具给的输入根本不会触发判据）。红要钉在**今天还不成立**的那件事上。
2. **数以工具自印为准，且变了要能逐名归因**：不要往文档里抄会随 commit 漂的数（格数、字段数、文件数、import 条数）。要数就去跑那条命令、
   把工具自己印的那几行贴过来；带出处的历史读数是例外，因为那是证据不是当前状态。
   两个独立来源必须对上才算核过：自己 `grep -c '^func Test'` 的实数 vs 脚本 `对照 0` 印的条数
   （10-17 实测：全树 144==144、外壳两包 17+12=29==29、zip 原文 14+11=25==那一轮自印的 25）。
   **分母变了要能说出多出来的算哪几支**；归因不到的部分明确标"未闭合"并说清为什么归不了（比如手上最早的树副本已经包含了那些改动），
   **不许编几个名字把差额填满** —— 填了就是交给他一个看起来对得上的数。
   **同一个事实数出三个数，就把尺子钉成文件**（10-17 数"看板上有几张卡"：先用 `^- ` 数出 3、再改"跟非标点"数出 1、
   最后认卡片标记字面量才数出 0 —— 前两个都是我把归档说明当成了卡）。规矩：一条要反复数的口径要落到一支可跑的探针里
   （现在是 `tasks/probe/board_check.py`：段名齐不齐 + 抬头分母 vs 实数 + "一个卡都没数到即尺子漂"的闸），
   不要在 shell 里每次现编正则 —— 现编的样式本身就是第二次事故来源。
3. **三态不许塌成一态**：量到了 0 / 没量到 / 忘了填 是三件事；「核不了」既不是绿也不是红（`—` 不是 `✓`）；
   「编译过了」不等于「测试跑过了」。报告任何状态时把第三种答案单列，别让它长得像通过。
   **失败理由也不许塌成一条**：10-17 判定器只印「名字命中名单」那一条 FAIL 理由，另一条独立原因（判据自己缺半边）没印，
   于是交接文档那句「命中名单就 FAIL」被读成反面「不命中就绿」—— 真人来跑照样 FAIL。
   真话的反面不成立时要把反面写死，并把**全部**独立理由逐条印出来；可达性由脚本自算自印，不靠人记。
4. **人造实例要标明**：演示（自己拧旋钮造出来的现场）必须写清"真实发生 0 次"，不许被读成观测；
   把答案递给模型再夸它答对了属于污染实验，比没做实验更糟。
   演示用的字段值要自带"这是演示"的字样（如 `--attest-caller "演示串·非接手…"`），免得日后被读成一次真接手。
5. **审计用的命令本身也是断言**：报出"某处有洞/交付物缺东西"之前，先确认自己的尺子与检索键是对的。
   10-17 连着两次伪异常都出在命令上而不是事实上 —— ① 拿针表的历史编号 `m76` 当"第 76 根"推进度（表名不连续、
   按表序排，真实进度是 36/78）；② 用 `《改前对照》` 当切分键去查归档文件（文件里写的是圆括号），
   于是数出"表行数 0"，差点把"对照表没写进去"当成事实报出去。
   正确做法：先用一个不依赖字符串形状的口径（行计数、正则两类都摆出来）复核，再决定是不是真有洞。
   10-17 又添一例同类：用 `awk '{if($NF=="OK")…else 非OK++}'` 数 `sha256sum -c` 结果，把它的
   `WARNING: 1 computed checksum did NOT match` 那行也算成"非 OK"，报出 `非OK=2`（真值 1）。
   第三种形态（10-17）：用 `\b`+段名+`\b` 去匹配**方法名**（Field 写成 `Sent()` 这种带括号的），尾部那个 `\b` 落在 `)` 之后永不成立，
   于是三格被数成"0 读者"——**假的硬结论**。规矩：正则的边界要单独喂一个已知会命中的**正对照**进去，
   对照数出 0 就让整份名单作废并退出非 0；"0"这种硬结论只在正对照通过时才有资格说出口。
   对的做法：分别 `grep -c ': OK$'` 与 `grep -c ': FAILED'` 两个口径并排印，末列判定法不用来数失败。
   **审归档交付物用逐行差集，不用"我记得写了"**：把前后两张表按行对齐，**变了的行数要等于该变的行数**，
   没变的每一行也要能说出为什么没变（10-17 审前后对照表：9 行里 4 行变、5 行不变，
   不变的那 5 行分别是"臂本身无效"、"#32 那一族今天没修"、"本来就对"、两条对照臂）；
   同理"判分线是不是跑之前就定死"这件事，可以用**它在源码 `main()` 之前那一段里**来机械证明，而不是靠叙述。
   **检索命中 0 行时，先怀疑键名/枚举，再谈结论**（10-17 第三次栽在尺子上，而且这次错进了耐久文件）：
   我断言"归档账里分帧三格过去全是 `absent`"，拿 `"chunks"` 去搜 Entry 得**命中 0 行** ——
   那一刻最容易写成"账里根本没有这三格"，真因是我猜错了存储形状（账是按 `kind` 存、`basis` 是整数枚举，
   `kernel.go:29-41` 里 `unset=0…absent=5`）。按真名重数才拿到 **198 行 = absent 159 ＋ measured 39，11 本旧账本就有 measured**，
   我那句断言当场被推翻，而它已经写进了看板、对账件与一支脚本的文件头 ——
   **所以要就地更正三处，并且把错误原文一起留在更正旁边**（他自己在 §8 也是这么处理的：更正不删）。
   推论：**凡要写进归档的比较级声明（"第一次""全是""从没"），必须先跑一次按真名计数并把数字贴在自己那句话旁边**；
   否则把措辞降级成"这一发量到了 X"这种只说自己读数的形式。
   第四种形态（10-17，这次错在**靶场的臂**、不是检索键）：一支臂名叫「有执行不了却连 0」，只把 `MalformedStreak` 钉成 0，
   而底样 `ToolCalls` 本来就是 0 ⇒ 先撞上另一条规则（个数比总数多），它**期望那条根本没执行**，我却按臂名记了一功。
   规矩：**跑臂的工具必须自带一列「撞中哪条规则」**，且该规则的文案要按**源码行号现取**（格式动词当通配去匹配原话），
   不许手抄样例短语 —— 我给另一条规则手抄的那句"原话"与源码差半行，是正对照判 False 才逼我去读的。
   正对照的形状：把每条模板的动词各自填成"只有这一臂会有的"假值，要求**自配且不串到别的臂**；坏就退出非 0、不出读数。
   第五种形态（10-17，错在**我的臂标识符**）：一批臂各自要用独立 session，我把 session 名截成键名前 6 字，
   于是 `notice_text / notice_trimmed / notice_why` 三臂挤进同一个 session，第三臂拿到的是**去重那句**「同一发只许记一次」——
   拒确实拒了、`isError` 也真为 True，但拒它的是我的 harness 撞车，不是那一格的判据。
   规矩：**凡"被拒"要当判据证据的批次，都要给"理由来自工具自身撞车"留一个单独计数并让整份作废的闸**
   （现在那支印 `被去重话挡下 0 个`）；同族前两次是"臂名≠撞中的规则"与"空表被读成全绿"，共同点是
   **分母数的是我自己做了什么，却没数对面为什么答**。
   **改了共用的尺子，必须拿它跟"已经落盘的读数"逐条对开**（10-17）：`rule_template` 取"第一个字符串字面量"，
   而判据行常写成 `if strings.TrimSpace(x) == "" {` —— 那个**空字面量**先被取走，于是两条臂报「源码里取不到句子」、整支 NOT_RUN 退出。
   改成"取含 `kernel:` 的第一段"之后，我把上一轮报告里**已经印出来的 8 条模板**逐条重取比对，印 `compared=8 drift=0` 才算改干净：
   否则一次修尺子可能悄悄把已归档的读数改脏，而那份脏没人会去复查。
   配套：**作废的那一跳也要落产物**（`exit 4/5` 分支同样写报告文件），只在 stdout 里说一句"我拒绝了"等于没证据。
   **给自己的归档定判据，要先数全集里有几种写法，不能拿最新几份的样子当唯一形状**（10-17 同一支尺子错了四轮）：
   我写"逐条打开核引用"的检查时，① 只搜 `报告/` 与仓库根 ⇒ 把确实存在的 `tasks/probe/lie_arms.sh` 报成断链；
   ② 拿"自印行"这一条判据去量 `.go` 与基线文件 ⇒ 13 条被误报成"证据没了"（**类别不同，判据要各用各的**：
   报告看自印行、基线看哈希行、脚本看有没有入口、源码只验存在）；③ 只认全角竖线 ⇒ 早轮那些 `名=数` 形状的自印行全被判成没有；
   ④ 哈希行正则只认一个空格 ⇒ 早期基线那份 `<hash>␣␣路径` 判成"没哈希行"。
   规矩：**这类"可核/不可核"的栏位必须自己印出误报样本**（现在它印"它里面第一行带数字的是…"），
   并留一条正对照（故意引用一个不存在的文件，必须被判成断链）—— 否则"全部可核"是最容易自造的绿色。
   同一族又添三条（都是"拿自己的归档当被测对象"才会遇到的）：**报告里的原话尾巴是按列宽截过的**，
   所以匹配规则句要取"模板里最早那段够长的字面量"，取最长那段（常在句尾）会永远匹配不上；
   "包装层"的判据是**句尾以 `%v` 结束**（把内层错原样拼上来），不是"句里出现 %v"（那会误排真判据）；
   中文的签名门槛要按信息密度定（≥4 字），按拉丁字母的习惯定 ≥6 会把短中文字整批判成"没签名"。
   **崩也要落产物**：一次 `NameError` 崩在打印行上、什么文件都没留下 —— 从那以后这些工具在 `__main__` 里把 traceback 写进 `…-崩那跳` 文件再重抛。
   **引用行号不是读数，每次要现验**（10-17 抓到两处，其中一处会扩散）：那句「这一格从此不再是死格」实际在 `mcpsrv.go:418`，
   而看板卡、三份归档读数、一支探针里都写着 417 —— 一次抄错会跟着复制粘贴走六处，每处看起来都"有出处"；
   另一个是我把 `acceptance_probe.py` 的 `c1_named = "NOT_CHECKABLE"` 写成 226，重构判定表后它已挪到 **234**。
   规矩：写带行号的结论前 `grep -n` 现取；**改过尺子或重构过被引用的文件之后，重扫全部引用**；
   归档里的错引用不删原文，在原句旁边就地标注。
   **引用还要指到"能复算出那个数"的那一份**（10-17 06:19 在交给第三人的接手包里抓到）：我把「点名句式 3/8」指到一份归档的 `:27-30`，
   而那份文件第 34 行**自己就写着"我不印这种数"**（印它要先造一份中文名单）—— 行号是真的、那份文件也确实有数，
   但那个数不住在那儿。接手人照我的引用去核会核不到。规矩：**每条带数的引用，先打开被指的那几行，确认它印的就是这个数**；
   口述过的数要么给出一段谁都能重跑的复算口径（含"要剔掉哪几行"），要么明说"这是散文，别当读数"。同族一条：**"已经有过某种验收"这类话要先数**——
   我以为 kcheck 早就有"钉文档那句话"的针，`grep -c README tasks/probe/kprobe.py` 印的是 **0**（真实形状是四根：守 6.2/6.3/6.4/7.3，第五根得新加）。
   **期望值/答案键本身也要现算，不许手算填**（10-17 出考卷时栽的）：我把题 12 的键算成 `11711.50→1463.94`，
   两个互相看不见的子代理**各自**算出 `11311.50→1413.94`，Python 复核后确认**错的是键、不是答卷**。
   ⇒ 从此判卷器一律从数据卷解析后现场重算（含工作日推算、矛盾行的候选值枚举），我不再往键里写数字。
   **拿一份"故意做坏"的输入喂给自己的判卷器**：v2 的判卷器先被 4 种已知错法（编数、指纹张冠李戴、引不存在的行、该拒却给天数）打过一遍，
   **四种全抓到 + 好的两行全命中**才有资格去判人 —— 否则它只是个会把错判成对的装饰。
   **子代理回报的结论要自己复现，别当二手事实转述**（10-17 同一晚推翻它两条）：它说「估算/转述要写出处那条判据在预检里没有 enforcing 分支」——
   我自己拿 `Basis=3`/`Basis=2` 各打一发，两发当场被拒且 `isError=true`（它以为没分支是因为它交的谎账用了 `Basis=1`，而 measured 本来就不欠 Source）；
   它说「`isError` 在挂载通道不可见、#20 没证实也没证伪」——真相是 HTTP 原始字段就是 `true`，抹平只发生在 Qoder 面板回显那一层。
   反过来，**两臂独立同值也能纠我的错**（上一条就是）。规矩：**双臂一致而与我不符时，先复核我，别先判他们同错。**
   **指认别人"捏造"之前，先查那句话的出处 —— 出处很可能是我自己**（10-19 中午 M5）：我记下「审查端编了一道 `:573` 的空文本闸和一根 `TestNilTextIsRefusedNotAnEmptyLedger`」，
   复算后两条都不成立：它原话是「那里**没有**非空检查」，`:573` 只是它**给修法提的行号锚**；那个测试名**是我自己造的**，
   第一次出现在我发给子代理的指令里（会话原件可定位到具体行）。规矩：**"队友造假"这种指控要拿三条东西才配得上出口**——
   ① 被指的那句原文（文件＋行号，打开看过）；② 全树 grep 证明它不存在；③ 回溯这个词最早出现在谁的输出里（我自己的指令也算一个人）。
   同一条的另一半：**我自己写进指令里的"预期测试名/预期闸门"是假设，不是事实** —— 交给子代理时要写明"不存在就说它不存在，别为了让指令成立去补造"。
   **分母要互相印证，不能只信计数行**（10-17 真流量轮）：runner 自印「落账成功 8 发」是计数器漏加，
   是链增量 `1323→1764 = 9×49` 把它戳穿的 —— 计数行旁边要放一个独立可推算的量（增量、格数、逐名名单），两边对不上就当我错。

   写一支不花额度的自检件，喂几份**该红**的输入，逐条断言「该红的红、该绿的绿」，再报数。

   ⇒ 没查过也算有出处 —— 修法是把记账收进"发出这个数的那个 owner"，不推给调用方补一笔（谁忘补谁就在造假）；
   ③ 禁令只写了一种语序（禁「到账…3 天」而漏「3 天内到账」）⇒ 禁令类判据要把同一句话的多种写法都摆进自检。
   **配套：判据要配反臂** —— 把那条边关掉，判据必须红（`--edgeback 0` → `from_ledger=0` → (C) 当场红并写明

   ㉑ **结构类产物（HTML/表格/嵌套标记）的针必须数结构，不能只按文本切块**（10-20 一次撞两形）：
   我给轨迹页加「每发一格表」，Go 针用 `strings.Split(h, "<details>")` 切块再查里面有没有某键名 ——

   ② 重出任何产物前先确认跑的是**刚编出来的那份**（改完代码没 build 就等于没改），
   浏览器复核 `file://` 要带 `?v=N` 破缓存；③ 页面对不上账时，**先怀疑针没看结构，再怀疑浏览器**。
   配套形态：**"某一格被用了"这类标记要按"哪一发用的"打，不能按"全局用过哪些格"打** ——
   后者给 18 处（每发的表里都有那两行），真值 10 = KPI。

   ㉒ **跨进程"逐字比"会做成抖动针；抖动针比没针更糟**（10-20 23:24，把跨面对账从 6 个工具扩到 10 个时撞上）：
   同一份代码、同一枚交付件 exe，连跑 8 次出现 3 红 5 绿 —— 红全落在 `encode_journal` 那一发。
   根因量清了：这台机墙钟刻度粗，两个进程落在同一刻度里时整串 `ts` **完全相同**（实测两边都是 `15:23:04.0517276Z`），
   跨一个刻度就整串不同；`ts` 喂进 `hash` ⇒ `prev_hash/chain_head/gate_sha256/seal` 全跟着变，头行那句"多少个字节"也变。
   规矩三条：① 比的是**内容字段**（`kind/claim/basis/source/payload_b64/payload_sha256/seq`），不比字节；
   ② 让开的格必须**逐名逐次打印**（`map[chain_head:1 gate_sha256:1 hash:49 prev_hash:48 ts:49]`），
   白名单里每加一格都要写清它为什么是时间戳的倒影 —— 否则掩码就是把差异藏起来的地方；
   ③ **掩码要配一发反臂证明它不吞内容**：只把对面那侧的 `payload` 改成 `omitted` ⇒
   当场红并点名 `payload_b64（MQ== vs <nil>）`，还原才回绿。
   同族更早一形（第 ㉑ 条）是"旧二进制 + `file://` 缓存"冒充新证据；这一形是"**针绿不绿取决于时钟落在哪个刻度**"。
   共同点：**针的结果必须只由被测内容的对错决定**，任何别的东西（编译产物新旧、缓存、时钟）能改变它，它就是抖动源。

   ㉓ **把"收口表"做成生成器之后，第一次跑它必须允许它抓到自己的错**（10-21 W8 收口件，一次抓到四处）：
   分母会随代码漂（Test 个数、针编号、判据条数、读数份数），所以那张表不该由人抄，应由一支脚本现跑 `go test`/`selfcheck`/`vet`、
   现扫步骤名与编号、现算哈希，并且**自己印"跑了哪几条命令、各退出码"**；命令没跑成或某个关键行没匹配到 ⇒ **拒绝落表**（出一张有洞的表比不出表更坏）。
   它第一次跑就报出：① 步名正则字符类漏了连字符 ⇒ 误判"缺步"；② 按**文件行序**当执行序 ⇒ 收口步排到了第一；
   ③ 工具路径写错时**崩栈绕过了闸门**（该记成退出码走"不落表"那句话）；④ 编号最大 21 ≠ 有 21 根针（**8 号是空的**，`grep` 现证）。
   规矩三条：结构类扫描的**字符类与排序键要用真物验一遍**（拿一个已知存在的名字当正对照，数不出来就是尺子错）；
   **"最大编号 / 个数 / 空缺"三件分开印**；反臂就是"故意喂一个不存在的命令"，必须看它退出非 0 **并确认好产物没被覆盖**。
   同族旧形是第 ⑨ 条"脚本自己印的两行互相矛盾"——那一形靠人回读，这一形靠闸门：没根据就别出文件。

   ㉔ **界面类判据要量"有人在看的那一份"，而且要按结构判、不按字符串在不在判**（10-21 W9 一次撞三形）：
   ① 响应式探针的 iframe 只加载空页面（没跑过那一发）⇒ "四档断点 overflow 全 0"是量空气量出来的；真跑完之后同一份 CSS 在 390px 溢出 138px。
   规矩：**几何类读数的被测态必须含数据**，并让尺子自己印"这一档里有多少条内容"（现在印 `trace_items`/`band_chars`），
   空态就直接判"这一档不算数"。② 判据写成"文件里有没有 `overflow-wrap: anywhere`"会被**无关出现**满足（header 那条规则里也有），
   变异臂（只摘掉 `main *` 那半边）照样绿。规矩：**CSS/配置类判据按规则块解析，要求它作用在哪个选择器上就验那个选择器**；
   写"某字符串存在"的判据，配一条"把它从正确那处摘掉"的变异臂，红不了就是假针。
   ③ **出图通道的边界也是量法**：这台机 Edge 无头把窗口宽度夹在 ~528（`--headless`/`--headless=new`/`--force-device-scale-factor=1` 都一样），
   所以 390/320 的 PNG 内容是按 528 排的 ⇒ 窄屏只认 iframe 读数，不认那两张图。规矩：**换量法拿到的像素，先证它的视口真的是你要的那个宽度**
   （PNG 像素尺寸 == 请求尺寸还不够，要看内容有没有被裁）。
   同族：自动触发（`?run=1`）不是造假，但**必须让产物自己声明触发方式**（页面上写明"不是人点出来的"），否则那张图日后会被读成一次真人操作。

   ㉕ **修"静默吞掉"之后，要用真调用路证明接得住；注入式断言只证"报出来好看"**（10-21 W10）：
   一张截图把藏了很久的形状拍出来了 —— `declare_reader` 每一发重喊一遍，内核从第二发起全数拒收（"同一个读者声明两遍会把分母数大"），
   而代码是 `_, _ = rpc.call(...)`。修法分两条，缺一不可：① 失败接住并点名；② 把"每格只声明一次"定成口径
   （声明是**代码的属性**，不是一发的属性 —— 只修②等于把真失败藏起来，只修①等于把噪声当读数）。
   针必须有三半：正向（第一发与**第二发**都不许出现失败）、注入式（把失败塞进返回值，验渲染层点名了没、五档塌没塌）、
   **真调用路**（把被测函数依赖的东西换成最小接口，测试里让那一条调用真失败 ⇒ 才证明"抓得到"）。
   只有前两半时，把代码改回 `_, _ =` 针照样绿 —— 那正是它要防的东西。
   配套：`-race` 这类"该给输出却没给"的命令一律记**没跑成**，不许写成"竞态检测通过"。

   推论：**`ok` 不等于"那根针跑了"**（10-21 差 30 秒就抄错）：`go test -run <写错的名字>` 回的是 `ok … [no tests to run]`，
   与真跑过的 `ok` 只差一行尾注。单针复读一律 `-v`，并要求看见 `=== RUN <真名>` 与 `--- PASS <真名>` 两行才记"跑过"。

   ㉖ **数"红/失败"的那一路必须与打印件自印的计数对开；检索键写错会让闸门恒真**（10-21 W11）：
   我数 `^\[FAIL\]`，而 reporter 打的是 `[RED]` ⇒ 收口表里"[FAIL] 0 条"是恒真，那道"有红就不落表"的闸门从建立起从没工作过；
   同一支错的键还把新写的"闸门会红"六臂全误报成"恒绿"（错方向：把在响的判据说成不响，比假绿更显眼，所以更容易被抓）。
   规矩：**红行条数与工具自己印的"失败项 N"必须相等，不等就拒绝出表并说明是口径漂**；
   任何"数某种标记"的判据都要配一条正对照（先注入一次真红，确认数得出来）才允许宣称"0"。
   同族第二形：那条"管路七格翻档"的判据看的是内存结构体的字段（代理读数），把真正该管的 Measure 改坏成恒 absent 它照样绿 ⇒
   **判据要查"落到账上的那一格"，不是查"我手里那个变量"**。

6. **「跑完了」要用产物证明，不用退出码**
：改完一轮先确认**输出文件真的生成了**、里面带着工具自印的分母行，再谈绿。
   **报告要在所有话说完之后才落笔**（10-18：收尾那三行写在 `writeFileSync` 之后，于是 23 份报告里都没有 `NODE status` 汇总行 —— 事后 grep 全空）。   **报"0 行不对"之前必须先证分母非 0**（空表全绿是最坏的一种假绿）：10-17 重新生成回滚基线时，取路径用了
   `awk '{print $2}'`，而本机 `sha256sum` 写的是 `<hash> *<路径>`（二进制标记）—— 星号让 `-f` 全假，
   生成的基线**0 条路径**，我的计数器却印 `OK=0 FAILED=0`；同一份交给 `sha256sum -c` 它答
   `no properly formatted checksum lines found`（拒绝 ≠ 通过）。所以计数行要与分母行并排印。
   10-17 实测：我把 `kprobe.py` 的点名表插错了字段（四元组的第四项写进了第三项），脚本 import 就 SyntaxError，
   那一轮 **20 秒"跑完"、退出码 0、报告文件根本没生成** —— 只看退出码就会把"没跑成"读成"跑过了"，正是 README 点名的那一族错误。
   配套：改 Python 探针后要过 `py_compile`，改 Go 要过 `go vet` 与 `gofmt -l`；
   **自己把工具/交付物改坏过一次，就要把它写进看板或读数里**（他自己写在 §8 第 14 条），不留成"没人知道"。

   **判卷器/套件自己也会假绿，要给它配"针没扎进去"的探针**（10-18 一晚抓到三次）：
   ① 18 根针第一次跑印"退出码 0、无漂移"，其实其中一根 payload 写错类型、被**解析层**先挡了，
   那条判据**根本没被考到**却被记成"如预期红" —— 修法不是改期望，是把**拦在哪道闸**（门口/判据）做成读数的一列，
   加完立刻又暴露 5 根针没声明闸层；② 判"有没有时间戳"用 `time|ts|timestamp` 去匹配，`ts` 命中 `part_totals` ⇒ 假绿；
   ③ 判"不得据残缺下结论"用子串 `提升|达标|通过` ⇒ 一句"不能判断是否**达标**"会被判成违规（没处理否定极性）。
   推论：确定性闸门**不需要重复发**（同 payload 重跑 100 次同一个判据，重复不产生信息）；
   该配的是**最小差异对** —— 同一份 payload 只改一根针，红（有针）+ 绿（拔掉针）才证明红是那根针造成的。
   ④ **测一条"状态"只在内存里证，等于没证**（10-18 深夜，M2 两路互审各独立撞到同一条，而我 11 条测试全绿）：
   那条名字叫「守 Partial（下界）」的测试从不 re-encode → re-load，于是一本下界账过一次落盘就被洗成"完整可数"，
   正是这次改动声称要防的形状、由它自己制造了一次。规矩：**凡有持久化形状的状态，反臂必须跨一次往返**
   —— 写出去、读回来，数与口径都得原样；连封条也要盖住口径本身（改数容易，改"这是下界"这句话更难被发现）。
   ⑤ **修一个假绿形状时，要扫同一个响应/同一行旁边有没有把同一形状重造一遍**：我把 `rejected_writes` 从 0 改成 null，
   却在新加的 `gate` 对象里把六个格子又全印成 0（同一响应自相矛盾），一路代理当场抓到。同族：修"两桶共句"时别在第三桶重犯。
   ⑥ **"剔除/过滤"类判据，必须拿产物再点一次，只看输入目录等于没验**（10-18 深夜我自己造的假修）：
   改了"搬运时跳过 `.log`"，脚本当场自印`剔运行日志 2`看着像修好了，而**上一轮已经搬进树里的旧副本没人管** ——
   `unzip -Z1 | grep -c '\.log$'` 实测仍是 **2**。规矩：过滤类改动要加一条**扫成品**的自检（`zipfile.namelist()` / 最终文件），
   命中就退出非 0；"我改了输入侧的口径"不等于"输出里没有那东西"。
   ⑦ **"端口有人在听" ≠ "是我起的"**（10-18 深夜实测踩实）：我把 PoC 实例起在 8811，`netstat` 只 grep 到 LISTENING 就开打，
   实际我的进程因 `bind: Only one usage…` 立刻退了，8811 早被宿主应用占着 ⇒ 一整轮六组"读数"打的是别人的本地服务（一律 405、零写入）。
   规矩：探测之前先证 owner —— `netstat` 拿 pid → `Get-Process -Id <pid>.Path` 必须是我那个二进制，且启动日志里 `bind:` 计数为 0。
   ⑧ **一句话有多个渲染处时，改一处等于没改**（10-18 深夜我自己撞的第二例）：聚合口径我只加在 `gateNow()` 里，
   而 `tally` 与 `gateReadout` 还各自读 `ledger.GateStatus()` ⇒ "只有门口拒收"的进程仍旧说"不可知"，把本程实数到的扔掉。
   规矩：**动一条判据/口径之前先 grep 它的全部读数出口**，把渲染收敛到一个函数（这次收到 `gateNow()` 与 `CapWords()`），
   否则测试只能证明"我改了那一处"，证明不了"这句话 everywhere 都对了"。
   **别用聚合总数指别人口误，先把分母拆开**（10-18 差点写下的错话）：`tally` 印 343 格（=7 发）而调用方自报"3 发 147 格"，
   我正准备记它口误；按 `session` 一拆是 `ai-home-…`×147（正是它说的 3 发）＋另一个 session×196 —— 它精确对，错的是我拿总数当它那一笔。
   同族反向：**别拿启动行的旧读数当现状**（我说过"我起的实例是 0 条没人用"，其实那本账里已经有别人的 3 发）。
   ⑨ **生成式读数里，结论句必须回读它自己上面那几行**（10-19 中午我自己撞的）：脚本先 `say(归档04: 行=130 ✓=41 —=6)`，紧接一行 `say("与 40 那臂逐数相同 → 40 的出处就是这份归档")` ——
   **两行都是脚本自己印的、互相矛盾，而它照样落成一份"看起来有据"的归档件**。这不是尺子错、是**尺子印对了、我拿它写错了话**；
   规矩：凡"→ 结论"这种句子，写完要把被引用的那一行**逐字重读一遍**再落笔（或干脆让脚本自己断言：`assert 结论里的数 == 上一行里的数`，不成立就 exit 不出文件）。
   配套：**发现自己刚生成的读数带一句假结论时，原文件改名留着、另出一份 v2**，不许原地覆盖 —— 那份错的读数也是证据（这次是 `报告/复算-…-1019-第一版把04读数用错那版.txt`，v2 头部指着它并写清哪一行错）。
   推论：**"两个数对不上"先怀疑量法，别急着记成有人数错**（40/41 就是这么关掉的：同一支 exe、只换 PATH，多的那行是 `— 依赖闭包核不了`）。
   ⑩ **读数里凡是时刻，一律从 `os.path.getmtime` 现读，不许手写**（10-19 12:4x 我连犯三处：归因件写"13:1x–13:3x"、看板小标题写"12:5x→13:1x"、
   违禁端口那事我记成"两跳"而产物只支持 12:33:42 那一发 —— 现算 mtime 全部对不上）。配套坑：Windows 文件名**不允许冒号**，
   拿 `12:4x` 当"坏那轮"改名后缀会直接 `OSError[WinError 123]` ⇒ 改名说法要写成「第一版把时刻写错那版」。
   ⑪ **尺子的扫描键本身也是断言**：`chain_status.py` 的基线 glob 硬写 `1017`，于是 12:38 重出的 `回滚基线-1019a.txt` 对它不存在，
   它拿 87 条旧集报 `FAILED 18`，而我差点把这句话抄进账（**抄尺子的结论 = 第 ⑨ 条的同形错误**）。修法不是换个说法把数做大，是三件配齐：
   **全集扫法自己印**（`回滚基线*.txt` 共 44 / 认 41 / 认不到 3）、**认不到的逐名豁免带理由**（漏声明→进"不可核"；声明了但盘上没有→同样进"不可核"）、
   **双向合成名对照**（6 支里必须既有人被认也有人不被认，一边倒就报红）—— 那条 `[a-z]*` 不是 `[a-z]+` 就是我自己的合成名对照报出来的。
   ⑫ **尺子登记的正是它自己要核的文件 ⇒ 改尺子必然让基线红一次**：基线含 `tasks/probe/chain_status.py`，12:45 改完它，`sha256sum -c` 立刻 `OK 95 FAILED 1`。
   口径：**基线只在"源码停手之后"才值得重出，重出后必须再跑一发机检拿 `不可核 0` 收口**；反臂不用另造，这一跳的上一跳就是这么红的。
   ⑬ **捕获子进程读数要两侧同时钉，并把"脏字符数"当成一位读数印出来**（10-19 午后修机检那行乱码时撞清的）：只在母进程写 `encoding="utf-8"` 没用 ——
   本机 python 子在 GBK 控制台仍按 cp936 写字节，两边一错一对，中文在归档里全变 U+FFFD、只剩 ASCII 数字能读（那份归档的"绿"其实没人守）。
   正解：`env=dict(os.environ, PYTHONIOENCODING="utf-8")` ＋ 母进程 encoding 写死 ＋ **把 `stdout.count(U+FFFD)` 自己印出来**，
   再配两根对照（同一 `run()` 喂 UTF-8 必须逐字回来、喂 GBK 必须判出脏）；**只跑正对照的闸门等于没有闸门**。
   顺带可测的方向感：Go 子进程恒写 UTF-8（与终端 cp 无关），拿一支 kcheck 同一串字节两解 = utf-8 脏 0 / cp936 脏 643。
   ⑭ **编辑层会静默吃掉不可打印字符**：我写的 `bc.stdout.count("<U+FFFD>")` 落到盘上成了 `count("")` —— **那是个永远非零的判据**，
   红得毫无信息。写含不可打印字符的判据一律用转义（`"\\ufffd"` / `chr(0xFFFD)`），并在改完**现读字节回证**（`[hex(ord(c)) for c in line if ord(c)>126]`）。

   变异必须**能编译**（例：改成 `if j == "" {` 这种保留变量使用的失效写法）。
   ② **靶要选对**：判据被摘平（恒过）时，红的是**接坏值那支臂**，不是走绿路径那支 —— 给"摘平判据"配绿路径测试 = 假盲区。
   ③ **有的坏法在类型上根本坏不出来**：`*bool` + `omitempty` 不会吃掉 false（nil 才省略），
   "演示 omitempty 塌 bool"是空靶；换成 `json:"-"`（字段不落盘）才是那支针真在防的坏法。选靶前先问这个改法是否真会让产物变坏。
   同族另一条：**冒烟报的 `ack_ms = 0` 不证明量到了东西**（亚毫秒落盘的真值与"恒填 0 的假数"在读数上不可区分），
   能区分的只有把入口时刻拨慢 250ms 那支 Go 臂 —— 这类"0 是真 0 还是没量"要写进文档，不许让读者拿它当证据。

   同族第三种假象（10-22 E3 沙箱）：**臂指向的负载走不到那条分支 ⇒ 数空气**。
   `not_reached`（没走到的步骤）只有被打断/被拒那一形才非空 —— 拿「全跑完」那趟去当 C1/C2 的靶，
   变异改坏了也照样绿（报 BLIND 是运气好，运气不好就报 BIT）。
   配臂之前先问：**这条判据的输入在这一发负载里真的存在吗？** 不存在就换负载（打断/被拒/回帧坏那一形），
   而不是换判据；并且要有一支测试断言"该非空的那格真非空"（`refused == 0 → t.Fatal("负载不对")` 这种自我检查）。
   另一条同刻的坑：打断类测试**别用墙钟对撞**（`Sleep(300ms)` 赌延迟窗口）—— 单独 `-run` 一支时控制就不绿了；
   改成轮询产物等到该出现的事件出现再动作，断言量**事件落盘那一刻**（ts），不是"函数返回那一刻"。

**判据把合法形状判红时，先查产物与覆盖，别查判据**（M5 2026-10-22 实证）：新加的「done_before 不许大于发号」在
`-resume` 续跑上红（rc=4）。我复算的路线是：在未修代码上跑新针（红-first）→ 再逐格看真 exe 落盘的数
→ 发现是**两根轴不同源**（事件 turn 从 1 重数、结算 done_before 从 7 起），判据红得对。修法：`turnFloor`+`turnNo()`，
进度 limit 折到同一根轴。**并报另一件事**：91 支 Test 全绿看不见它，因为「跨进程续跑 × 事件流 × 结算」这个组合一个负载都没有
—— 覆盖空洞会让正确的判据看起来像 bug，会让错误的判据看起来像 OK。
**臂的锚文本命中数必须自成一档**（同一轮）：函数签名一改（`countsFor(r.turns)` → `(r.session, r.turns)` → `(r.session, r.turnNo())`），
旧臂锚命中 0 次却被报成 BLIND「判据没牙」—— 那是尺子哑了不是代码没问题。给臂件加 `NOT-WIRED` 档 + `--anchors-only` 预检，
预检当天就抓到 C3 第二次漂。**凡"整包 rc 判变异咬没咬"的读数，先确认锚接在被改的那个绑定上**。
**五端并行改同一棵树**：按文件隔离（各自只新建自己的测试文件、各自 TEMP 沙盒做破坏），落地后 `diff -rq` 证明；
并行端会读到别人半写的文件 ⇒ 分母要重取快照（本轮扫端自印的 19/6795/80 中途变成 21/7215/91，它如实标了两个快照点）。
**别用 python heredoc 生成 Go/嵌套字符串源码**：`	`/`

`t.Fatalf` 少了 `t`）。要么用 Write 工具整文件写，要么行级替换后**立刻** `ast.parse`/`go vet` 校验。

**工具件里写死「要处理的文件清单」与写死分母同族**（M5 2026-10-22）：合并后的臂检件把「加载哪些源文件」写成硬编码元组，
我新加一根打 `checklog.go` 的臂就 `KeyError` —— 报错点在**运行期深处**，不在「你漏了什么」那一层。
凡是「以后还会加东西」的件（臂表、SPEC、锚点表、收口清单），清单必须**从条目自己推导**（`{a.file for a in ARMS}`），
否则每加一条都要有人记得改第二处；记得住就不是机械约束。同一轮的另一例：SPEC 写死 gofmt 的对齐空格 ⇒ 加一个长旗标名就哑。

**两个自印分母必须互相对账；「注释说修好了」不是修好了**（证据模型轮 2026-10-23）：尺子二印「符号可核 32 条」，
`锚点刷新.py` 印 `refs total=53` —— 差 21 条就是**有东西没进档**，而尺子照印 PASS、rc=0。两条根因都在尺子里：
① ast 只解析 `SPEC = {…}` 字面量，`SPEC["x"] = [...]` 追加式赋值整体读不到（**值是 `ast.List`，不是 `ast.Dict`**）；
我第一次的修法把新分支仍写在 `isinstance(node.value, ast.Dict)` 里面 ⇒ `ast.parse` 过了、跑了、**数没动**。
② `audit()` 的返回字典里同一个键 `"mis"` **写了两次**，后者把 `mis + sym_bad` 覆盖成 `mis` ⇒ 坏点只印不判；
而那几行代码上方正有一条注释声称「坏点必须进 mis 才算闸」（注释与实现不符）。
可复用的三条：**(a)** 任何「分档/覆盖率」的数，要能等于另一件自己印的总数（不等就是洞，别只看 rc）；
**(b)** 改完判据件先问「这条新分支挂在哪个类型判断下面」，按被测对象的**形状**数一遍，语法过不等于数动；
**(c)** 程序化拼字典字面量时要查重键（Python 静默取最后一个，`dict(...)` 同样）。

**自证「臂有没有牙」不许看 rc，要看清单对数**（同一轮）：把旧病注回尺子的内存副本时，注病那份 rc=3 ——
但红是**臂自己死了**拖出来的，不是坏点被抓。真判据是同一条漂移下 `sym_bad>0 而 mis=0`（只印不判）。
我第一版把「注病后 rc 仍 0」写成预期，自证件当场判我这条不过：**自己的探针里那条预期，也要能被探针红一次。**

**子进程为上屏做的 ASCII 转义会渗进上游报告**（同一轮）：`验收-事件层` 为了 GBK 控制台把 stdout 转成
ASCII 反斜杠转义（中文全变 `\` + `uXXXX`），`体检-全闸` 抓「最后两行」当凭据写进报告 ⇒ 报告里那一行是半损坏文本。
组合件的尾巴要**从各闸自己的 UTF-8 读数文件取**，取不到就退回 stdout 并**点名退回原因**；
「产物文件写 UTF-8、控制台写 ASCII」这条规矩，只管到写它的那一件，管不到有人去 grep 它的 stdout。

**加一道闸，现场所有「几道/几把」的枚举句同时变谎话**（尺子自证轮 2026-10-23）：我给全闸加了「尺子自证」这一道，
`README` 与说明书里那句「两把尺子 / 八条针」当场成了假的，桌面用户手册同一句也是 —— **三处**都是我去查才看到的，
不是我写的时候想到的。可复用的做法：**新增判据件的同一步就 `grep -rn "两把\|三把\|几道\|N 道\|全套闸"` 全现场**，
并把枚举改成「不写死，读 `报告-全闸.txt` 自己的行数」。枚举比数字更容易漏，因为它看着像描述不像分母。

**判据链里不许塞写盘件 —— 想做的等式若有一边只有「写的那一件」知道，就先把两边搬进同一个只读件**（同一轮）：
我原本打算把「尺子的符号可核 N == `refs total=`」做成闸，但 `refs total` 只在 `锚点刷新.py` 跑的时候印，
而它会把行号写进被审的模型 ⇒ 让判据流程动被审对象，等于闸自己造现场。正确形状是同一条 ast 解析**顺手把各槽列表长度加总**，
等式在尺子内部成立，纯读。推广口径：任何「A 件对 B 件」的交叉判据，先看 B 那个数是**读出来的还是写出来的**。

**「先备份再改」我在一轮里连犯两次，且第二次是明知故犯**（无 git 的现场 2026-10-23）：改桌面手册没先 cp，被自己抓到并写进交接；
半小时后改本面 `README`/`说明书` 又是先改后补。补救办法是可用的但不是规矩：**按编辑时逐字 old/new 反向重建改前版 + `diff` 核过只差那一处**，
并在文件命名上如实写「改前还原版」而不是「备份」——**重建看不见我记忆之外的改动**。下次动文件的第一条命令就是 `cp`，
不要拿「改动很小」当理由；写进文档的 confession 不阻止下次再犯，只有把 `cp` 放进同一条 Bash 调用里才放不进借口。
