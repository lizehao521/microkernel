## 3. 跑一趟宿主：常用旗标与含义

```bash
"$TEMP/agentd.exe" -script happy -max-turns 20 \
  -journal-out "$TEMP/x.jsonl" -events-out "$TEMP/x.events.jsonl" -trace-out ""
```

| 旗标 | 管什么 |
|---|---|
| `-driver scripted\|fake\|real\|session` | 谁在决定下一步。`scripted` 是**剧本走出来的绿**，stderr 上会明写「不是模型自主决定的绿」。`real` 需要模型口令，本机 env 里没有 ⇒ 只演到 `NOT_RUN` 就收口。 |
| `-script full\|happy` | 剧本：`full` 跑到按账停，`happy` 跑到剧本完。 |
| `-events` / `-events-out` | 事件层开关与落点。默认 `--events=true`；不给落点就从 `--journal-out` 推。**只在内存数序、盘上一条不落** 与 **落盘** 是两种态，横幅会分开说。 |
| `-events-serve` | 把这本日志接成 SSE 推到 `127.0.0.1` 的**随机空闲端口**（只绑回环，随进程关）。stderr 那行印地址。断线重连接不上时回一帧 `event: resume-lost`，与「真追平的静默零帧」分得开。 |
| `-shot-delay` | 每发之前等多久。用来制造「真能停的窗口」给打断测试用。 |
| `-progress-tick` | **10s 兜底进度**（默认 `10s`，填 `0` = 关，关与开都会在 stderr 说一声）。某一发开着之后长时间没新事件，就往事件流里补一条：知道还剩几步时补 `progress_tick`（带 `done/total/limit`，出处 measured）；不知道时补 `why_late`（出处 **absent 且写明为什么算不出**，`total` 留 nil，绝不编一个 0）。超时在这里是**汇报**，不是报错，也不改变退出码。 |
| `-read-back=false` | 核心 KPI 的反臂：关掉后账上触发次数必须掉回 0。 |
| `-entry-cap` / `-resume` / `-max-turns` | 账满、跨进程续跑、额度。 |
| `-check-log <日志>` | **只读判据模式**：不跑循环，只吃一本日志交四支判据的读数。见 §4。 |

**stdout 是给逐字比对的运行正文**；横幅、警告、降级说明一律走 stderr。别在 stdout 里找状态。

## 4. 读数怎么解释（三态，不是两态）

### 退出码（六态，owner 是 `cmd/agentd/main.go` 顶部注释）

| 码 | 意思 |
|---|---|
| 0 | 跑完剧本 |
| 2 | 这一路跑不了（缺口令、链不符、日志读不动） |
| 3 | 轮次额度到 |
| 4 | 账上 `fail_kind` 指向「停」／判据红 |
| 5 | 这本账已到上限 |
| 6 | 外部打断（**先交账再走**） |

**1 不在契约里**。看到 rc=1 就当是命令用错或尺子自己崩了，别记成「闸红」。

### `-check-log` 一行一个读数

```
check-log  ValidateSettlement  一发恰好一结、counts 与账对得上  RED  第 1 发…
check-log  口径  ack_limit_ms=100  INFO  12 条日志、4 支判据
```

制表符分列：`check-log | 判据名 | 它管什么 | GREEN|RED|INFO | 为什么/条数`。
退出码：**0 全绿 / 4 有红 / 2 日志读不动**。

四支判据：`ValidateLog`（序号接续 + 状态白名单 + 出处五档 + absent 必带理由 —— 这三查以前只在写侧，注释却声称读回也管；现在读回路径真查）、`ValidateAccepts`
（每发第一条是回执 + 预算 + 载荷给全）、`ValidateSettlement`（一发恰好一结、相位齐、
counts 逐名对得上、不许半结算）、`ValidateReplay`（尾游标接得上）。

### 限度分离（很容易读错的一条）

`-ack-limit-ms` 默认 **100** 是**契约预算**。本机实测同一形态两跑分别是 `22ms` 与 `516ms`
（并发抢 CPU 时还见过 `248ms`）⇒ 100 这一档在本机**偶发会真红**。所以：

- 判「结构对不对」→ 传 `-ack-limit-ms 60000`，这一支**当闸**；
- 判「宿主承认收到它有多慢」→ 单独跑一次 100，把它的读数当**发现**记下来，**别当闸**
  （当闸就把闸变成随机红）。

两次的**前四行逐字相同**，只有末行的 `ack_limit_ms=` 不同 ⇒ **单条 GREEN 不带上限身份**。
要把一条 GREEN 说成「契约预算下也绿」，必须把那一行口径一起带回来。

**投送层多了一帧，读的时候要知道**：断线重连时，若游标指向的那条已经不在账上、而那一发当初老实写了
「不可续」，投送层回的是 **200 + 一帧 `event: resume-lost`**（不是静默零帧）。静默零帧现在只有一个意思：
「你要的都在我这儿了，真追平了」。以前这两种逐字相同，客户端分不出来。

**`-check-log` 的每一行现在都带用的是哪个上限**（第三列末尾 `ack_limit_ms=…`）。以前只在末行印，
于是放宽过的 GREEN 与契约预算下的 GREEN 前四行逐字同形 —— 抄一条出去就能冒充。

**长那一发不再只是「屏幕不动」**：`-progress-tick`（默认 10s）到点就往事件流里补一条说明，两种形状分得很清 ——

| 流里出现 | 意思 | 出处档 | `total` |
|---|---|---|---|
| `progress_tick` | 这一发还在途中，已经落了哪几条、预计落到第几发、额度到几发 | `measured`（静默时长是量出来的） | 有（剧本驱动知道） |
| `why_late` | 同样在等，但**还剩几步算不出**（不是剧本驱动） | `absent` + 必带为什么 | **nil**（绝不写 0） |

三条数（`done`/`total`/`limit`）在同一根轴上，且 `total` 不会越过 `limit`：剧本比额度长时，落点夹到额度并在说明里写明是哪一侧决定的。
补位只在这一发**结算之前**有效——结算已经抄过当时的账，之后再挤进一条会让「自印的 counts」与账上差一条，那种账宁可少一条也不留。
超时**不改变退出码**，也不补出任何步骤：它只是把「还在等」这件事写进同一本可以回放的账。
实测那一发（`-script happy -max-turns 2 -shot-delay 12s`）：`elapsed_ms=10089` 出现 `progress_tick`，
`-check-log` 四支判据全 GREEN —— 读数在 `事件层-1022/读数/真负载-E5兜底进度-1022.txt`。

**轨迹页现在只从一本账读数**（以前它自己乘了一遍）：页首那行「事件日志数出来的这一趟共 N 发」与
「共 M 条（发级 N 发，逐发条数 1:5 2:5 …）」都来自那本 `*.events.jsonl`，`每发 49 格 × N 发` 用的也是同一个 N。
这件事之所以要写进说明书：页上原来那个数取的是**落账的 shot 数**，而一发被拒/装不出时它不涨 ——
于是「共几发」在页上与流里本来就是两个数。今天实测那一趟：日志 9 发 / 47 条 / 逐发 5 条，页面三处一字不差（`读数/真负载-E8同源-1022.txt`）。
**没开事件层时，这一格写「没量过」而不是一个数** —— 不会退回内存里那个 shot 数冒充。

**开了 `--events-serve` 就有一张网页可看**：浏览器打开 stderr 里那行地址的根路径（`http://127.0.0.1:<随机端口>/`）
就是三行页 —— **现在**（最后一条事件是哪一步 + 流的状态）、**已经**（后端交过的 `done/total/limit` 与结算 counts，
下一帧没带也不会被抹掉）、**接下来**（这一发还剩哪几相 / 剧本还计划几发 / 「剧本已尽」）。三条规矩：

- 页面上**没有一个数是前端算出来的**（不加总、不换算、不比大小）；判据 `TestPageDoesNotComputeAnything` 见到
  `reduce(` / `Math.` / `parseInt(` / `+=` 就直接红。
- 后端没交的那一格在屏上写「**没量过**」，不写 0、不写空。实测里跑到中途 `total` 就是「没量过」——那一刻收口还没落账。
- 列表**有界**：只留最近 12 条（真浏览器喂 32 条仍是 12 行）。

这一页随进程关：那一趟跑完，端口就没了（`ERR_CONNECTION_REFUSED` 是预期，不是页面坏了）。
真人可读性仍记 **NOT_RUN** —— 上面这些是本机浏览器实测的读数是「看得见、没脏字、数对得上」，不等于「好读」。

### 三态不许塌

- `absent` 必带「为什么缺席」；
- 量不到**绝不写成 0**；
- 「本来没这回事」不挂成未决。

看读数时找这几个词：`NOT_RUN`（本机做不了）、`NOT_MEASURABLE`（形状存在但这个位置量不了）、
`NOT_REPRODUCED`（别人报了、我这台撞不出来）。**它们都不是「没问题」，也不是 0。**

## 6. 现在**不能**对它期待什么（照抄进汇报会翻车的那几行）

**这里原本有一条假红，现已修（同一命令复跑会变绿）**

```bash
# 跑一趟 → 续跑 → 对续跑那本日志判据
"$TEMP/agentd.exe" -script happy -max-turns 6 -journal-out "$TEMP/j.jsonl"  -events-out "$TEMP/e1.events.jsonl" -trace-out ""   # rc=3
"$TEMP/agentd.exe" -driver fake -resume "$TEMP/j.jsonl" -max-turns 2 -journal-out "$TEMP/j2.jsonl" -events-out "$TEMP/e2.events.jsonl" -trace-out ""   # rc=3
"$TEMP/agentd.exe" -check-log "$TEMP/e2.events.jsonl" -ack-limit-ms 60000   # rc=4
# check-log | ValidateSettlement | … | RED | 第 1 发结算说停下时已完成 7 发 —— 不可能大于发号本身
```

根因不是判据错，是**产物两根轴各说各话**：续跑那趟 stderr 印「发号从第 7 发接着走」、结算 `done_before` 也从 7 起，
可事件流里的 `turn` 却从 1 重新开始 —— 同一本日志里身份轴与载荷轴打架，判据（done 不许大于发号）红得对。
现在 `r.turns` 只数本进程几发（额度与停止判断看它），落进事件流的发号是 `turnNo()=turnFloor+turns`；
进度格的 `limit` 一并折到同一根轴，不再出现 `done=9 / limit=3` 这种分子分母不同源的并排数。
**为什么之前四条闸全绿看不见它**：「resume × 事件日志 × 结算」这个组合今天才有负载（新增 `events_resume_axis_test.go`，
配 H1–H3 三根臂）。教训记进交接件：新加判据把合法形状判红时，**先怀疑产物与覆盖，别急着迁就判据**。

**NOT_RUN（本机做不了，别折成 0 或「没问题」）**
- `-race`：需要 cgo，本机跑不了 ⇒ **并发安全是「未确证」**，不是「测过没问题」。
- 真模型端点：env 里没有任何口令。
- 真人可读性 0/1：这条事件流要给界面当底，**没有一个人看过它好不好读**。
- OS 级 SIGINT 在 exe 那一侧没确证（单测窗口里演过进程内叫停）。

**NOT_MEASURABLE（位置不对，量不了）**
- 「同一游标重放两次得到同一序列」在真进程上测不了：投送层随进程生死 —— 进程活着日志一直在长
  （两次天然不等），进程一停端口就关了。这条性质由 Go 侧 `TestReplayTwiceGivesSameSequence`
  在**已封口的日志 + HTTP** 上钉。架构后果待拍：界面要断线重连，投送层就得在收口之后继续活着。

**NOT_REPRODUCED**
- `Stop` 的双关竞态：上一轮报告说 400 轮撞出 `panic: close of closed channel`；
  我这台 40 轮 × 8 并发在**未修改的真树**上是绿的。修法照做了，但**能确定性撞开原始竞态的臂还欠**。

**结构性没有负载（不是「没跑到判据」，是「代码路径没人走过」）**
11 处收口调用点里，`failed` 一族今天 0 负载（本轮已钉 3 处）；剩下几处判过是
**公开路径不可达**（装配恒不失败、进程内 `Serialize` 恒有回帧），不是漏了。

## 7. 出问题先看哪里（按踩到的次数排）

| 症状 | 先看 |
|---|---|
| 「所有文件都不一样」「拷贝没生效」 | 树根是不是少写了一层（三层） |
| rc=1 冒充闸红 | Python 打了 `✓`/`⇒`（GBK 崩），或 `-seed` 写法错，或尺子自己的 bug |
