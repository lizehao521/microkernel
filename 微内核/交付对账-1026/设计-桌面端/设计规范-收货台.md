# 收货台 · 桌面端设计规范

- 版本：0.1.0-prototype（2026-10-26）
- 适用：`交付对账-1026/设计-桌面端/收货台-原型.html`
- Token 源：`design-tokens.json`（逐值抽取自 `原型-源/style.css`，无新造色）
- 走查与实测：`读数/走查-收货台-1026.md`

## 1. 一句话与边界

收货台是**只读**的交付验收入口：把 Agent 的交付声明按可信度分诊，逐条回盘核对，给出可转发回执。

三条不可越过的边界：

1. 不执行交付代码、不联网、不调用模型。
2. 代码与证据不出本机。
3. 只消费既有判据与格子，不新增内核格子。

「核不了」不是「通过」。收下只记录决定，不改变声明真假，也不为代码质量背书。

### 3.3 对比度

目标 WCAG 2.1 AA：正文 ≥ 4.5:1，大字 ≥ 3:1。全部六位色值在最终 build 上由脚本重算；20 组文字配对全部 PASS：

- `ink-3` 最低 4.69（在 `surface-3` 上），在 `paper` 上 4.91；
- 状态色最低 4.74（`ok` 在 `ok-bg` 上）；
- 深色栏 `side-dim` 在 `side` 5.26、在 `side-2` 4.77。

两处例外已写进 tokens 的 `contrast_audit.exceptions`：

- `ink-4` 在 `surface` 上 2.41：只用于关闭态圆点，纯装饰，旁边有文字状态。
- `side-dim` 在 `side-3` 上 4.03：`side-3` 只出现在选中导航项（白字）与图标按钮 hover（`#e6e8ec`），没有任何 `side-dim` 文本落在它上面。

## 4. 字体

- 无衬线：`"Segoe UI", "Microsoft YaHei UI", "Microsoft YaHei", system-ui, -apple-system, sans-serif`
- 等宽：`"Cascadia Mono", "Cascadia Code", Consolas, "Courier New", monospace`
- 数字与编号一律 `tabular-nums`；时间、ID、seal、rc 用等宽。

阶梯：

| 档 | 字号 | 典型用途 |
|---|---|---|
| Display | 28 / 25px | 状态块数字、空态标题 |
| H1 | 23px | 页面标题 |
| H2 | 17 / 15px | 区块标题 |
| Body | 13 / 12.5 / 12px | 正文、行标题 |
| Meta | 11.5 / 11 / 10.5px | 副标题、时间、说明 |
| Tag | 10 / 9.5 / 9px | 表头、来源字母、类型 chip |

规则：正文最小 11.5px；10px 及以下只用于表头、编号、来源字母与类型 chip。8.5px 已取消（来源字母与「转述」标签提到 9.5px）。字重只用 400 / 500 / 600 / 700。

## 5. 间距、圆角、阴影、动效

- 间距基准：2 / 4 / 6 / 8 / 10 / 12 / 14 / 16 / 20 / 24 / 30px；页面内边距 `26px 30px 40px`。
- 表格密度用 10 / 14px，卡片用 12 / 16px。
- 圆角：3 / 4 / 6 / 8 / 12px；胶囊 999px。
- 阴影只有两级：`0 1px 2px rgba(20,22,28,.05)` 与 `0 12px 32px rgba(20,22,28,.14), 0 2px 8px rgba(20,22,28,.06)`。

## 7. 状态语义与操作规则

### 7.1 判定

| 判定 | 含义 | 能否收 |
|---|---|---|
| MATCH | 盘上实测相符 | 可收 |
| MISMATCH | 盘上实测不符 | **不可收，整单退回** |
| ABSENT | 证据缺席，核不了 | 可收，但结论保留 UNVERIFIED |
| 核对中 | 尚未完成 | 不可操作 |

### 7.2 依据

- `disk`：唯一算实测的依据。
- `relayed`：交付方自述；无论多少条，只能封顶到 `NOT-ACCEPTED-UNVERIFIED`。
- `absent`：必须写明为什么缺席；不得记 0，不得读成通过。

### 7.3 决定

- **收下**：记录决定并保留结论；历史与回执仍标 UNVERIFIED；不改变声明真假。
- **退回**：必须带理由（模板 chip 或自由文本）；回执可离线打开、可转发。
- **归档**：只读留存。

UI 已把规则写死：

- `status === 'bad'` 时收下按钮禁用，标题提示「有声明与盘上不符，整单必须退回」；模态层与确认函数各有一道同样的 guard。
- 收下/退回的说明文案随状态变化，不再出现「收下 = 确认声明一致」这类对核不了的单也成立的错话。
- 历史行的决定文案由数据推导：已收下 / 已收下 · 仍核不了 / 已退回 / 已归档 / 未决定。

## 8. 交互与键盘

- 队列 → 单件 → 证据抽屉；抽屉不离开当前交付，保留上下文。
- 收 / 退最多 2 次点击：行内「核对 →」进单件，主按钮开模态，确认落决定。
- 退回理由 chip 选中即启用确认按钮；无理由不能退。
- 键盘：`/` 聚焦搜索；行 `Enter` / `Space` 打开；`Esc` 关闭抽屉或模态；焦点可见环 2px accent。
- `#d=`、`#claim=`、`#pane=`、`#modal=`、`#state=`、`#screen=` 可深链；可从回执直接跳到某条声明与某个证据页。
- 列表面板在空态 / 读取中 / 读取失败三态下隐藏表格；表尾、三态计数、头部摘要同步切换（空态 0、加载与错误显示 `—`，不冒充 0）。

## 9. 演示数据口径

- 6 单 = 3 份实测回执（`DLV-1023-0042` 真端点核不了 / `DLV-1026-0007` 好样例 / `DLV-1026-0008` 谎报样例）+ 3 条演示占位（hub 处理中 / 账本样例 / 待核）。
- 每行都有「实测回执 / 演示占位」标记；页头写明「样例数据：3 份实测回执 + 3 条演示占位」。
- 账本 49 格是形状样例，抽屉内明写「与本交付无因果关系」。
- 原型不读文件系统；「导入」与「重新读取」只做交互演示。

## 10. 已知限制

- 无后端、无持久化：刷新即回到种子数据；决定不落盘。
- 批量预核未实现（Brief 的设计策略里有，原型未做）。
- 真实用户可用性测试 NOT_RUN；屏幕阅读器实测 NOT_RUN；Windows 125% / 150% 缩放 NOT_RUN。
- 抽屉关闭时仍在 DOM 中、靠 `transform` 移出画布；屏幕阅读器仍可能读到，当前用 `aria-hidden` 管理，但未做完整焦点陷阱。
- 系统字体随机器变化，本机为 Segoe UI + Microsoft YaHei UI；未打包字体。
- 颜色对比度是脚本计算值，非人工判色；视觉观感仍需真人复核。
