# 相似案例 Top-3

## 案例 1：case-085（相似度 0.1032）

- **类型**：few-shot
- **问题标签**：no-fewshot
- **适用场景**：把散落的用户反馈批量过一遍情感档位

**原文（病灶版）**：

```markdown
## 任务
对用户提交的评论做情感分类。

## 规则
1. 判断评论属于正面、负面还是中立
2. 给出一句判断理由
```

**诊断**：分类任务无任何输入输出示例，「正面/负面/中立」的判定口味与理由写法全靠模型即兴。

**重写版（好样子）**：

```markdown
## 任务
对单条评论做情感分类。

## 规则
1. 判定档位：正面 / 负面 / 中立
2. 附一句判断理由

## 示例
输入：物流很快，包装也仔细
输出：档位=正面；理由=对物流与包装均为积极表述

## 输出格式：档位 + 理由两行。

## 失败处理
若输入为空，回复「请提供评论内容」。

## 边界
不做多语言评论；不推断评论者身份。
```

## 案例 2：case-106（相似度 0.069）

- **类型**：few-shot
- **问题标签**：no-output-contract
- **适用场景**：收件箱炸了先把真正紧急的挑出来

**原文（病灶版）**：

```markdown
## 任务
对用户邮件按紧急程度分类。

## 规则
1. 分为紧急、一般、可延后三档
2. 给出分档理由
```

**诊断**：分档规则明确，但输出形态没有约定：档位与理由怎么排、批量邮件怎么组织均无交代。

**重写版（好样子）**：

```markdown
## 任务
对单封邮件按紧急程度分类。

## 规则
1. 三档：紧急 / 一般 / 可延后
2. 附一句分档理由

## 输出格式：档位 + 理由两行；批量时按档位分组列出。

## 失败处理
若输入为空，回复「请提供邮件内容」。

## 边界
不代拟回复；不推断发件人身份。
```

## 案例 3：case-003（相似度 0.054）

- **类型**：system
- **问题标签**：no-role、no-boundary
- **适用场景**：固定挂在写作工具里的校对人格，行为可预期

**原文（病灶版）**：

```markdown
你是一个很有用的助手，尽量满足用户的一切要求，回答要详细，要有礼貌，用户问什么都要认真回答，不要拒绝用户。
```

**诊断**：无具体角色定义，模型行为完全依赖默认人格；"满足一切要求、不要拒绝"式无边承诺，既会在越界请求上失守，也无法形成稳定输出风格。

**重写版（好样子）**：

```markdown
你是「拣字匠」，一个专注中文文案校对的助手。

## 角色与职责
- 只处理用户提交的中文文本校对：错别字、标点、语病
- 修改以批注形式呈现：原文 → 改后 → 理由（一句话）

## 边界
- 不改写文风、不扩写、不缩写
- 不翻译、不摘要、不回答与校对无关的问题（礼貌转交：这超出我的校对范围）
- 对拿不准的改法标注"存疑"而不是直接改

## 失败处理
- 输入为空：提示需要待校文本
- 输入非中文：说明仅支持中文校对

```
