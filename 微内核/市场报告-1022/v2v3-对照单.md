## 三、v2 留的那句反面（v3 的主判点）

> 原文（`src/02-exec.html:69`）：「SAM 下调可能过度悲观。如果『AI 审计』在 2027 年成为独立预算科目，SAM 会回升。」

本轮倾向：**这句风险方向反了 —— 在「靠法规推动」这条路上它过于乐观，在「靠采购门槛推动」这条路上它又过于悲观。**

- 法规侧推动力弱（支撑「过于乐观」）：日志类高风险义务推到 2027-12 / 2028-08；NIST 自愿；ISO 42001 证据=过程记录；执法人手薄。
- 采购侧门槛真实且与法规无关（支撑「过于悲观」）：买方拿的是**对供应商的 SOC 2 Type II 准入**（"没有它 RFP 阶段直接淘汰"，Tier 3 [17]；"自有 SOC 2 的企业要求供应商也带 Type II"，Tier 3 [16]），Type II 要的是**持续生成 + 全程留存**的证据（6–12 个月，Tier 3 [14]），最常见的 AI 网关发现项是 API 层访问控制与「共享服务账号无法归属到人」（Tier 3 [14]）——**归属 + 连续性 + 留存**这三条，正是逐调用账本能直接供上的东西，而 v2 把需求整个挂在「审计」这个词上，挂错了接口。
- v2 那句「如果成为独立预算科目」目前唯一像样的正面证据：IDC 有 **AI-enabled financial GRC** 的 MarketScape 正式类目（Tier 2 [22]）——但类目由 IBM 类平台占着，说明预算存在、坑位在平台内，**不是单点账本件**。
- 结论口径（待抽查后定稿）：v3 把 SAM 判据从「法规时间线」改写成「买方门槛三件套（归属 / 连续留存 / 可分发报告）」，并明确 v2 的「为 AI Act 提供证据」这条话术要撤。

## 五、双臂负结果的学理保护（研究区 6，本轮）

- MT-Bench：GPT-4 裁判换序一致率仅约 65%；「列表复读」冗长攻击下失败率 8.7%（GPT-4）～91.3%（Claude-v1/GPT-3.5）；同族自评约 +10 个百分点 —— 支持「AI 模拟读者不能用来推翻双臂负结果」这条纪律（Tier 1 [54]）。
- 反面也要写：2026 Springer AES 研究发现「位置偏差迹象极小」（Tier 1 [56]）。→ 引用口径：LLM 裁判是**有条件的可信**，永远不能替代预先注册的人测臂。
- 缺口：双臂「加层无增益」的方法学对照（评测污染、基准饱和、框架消融）本轮**没取到源**，列 R2 优先补。

## 六、必须改的两条旧说法（我自己的口径）

1. **OTel 不是「零审计用途」**：v1/研究件里「OTel 的 trace 只能调试、不能审计」太绝对。OTel GenAI semconv 标准化的是**字段词表**，采样策略（正常流量 ~10%、异常全采）使它按设计有损 —— 正确说法：**「采样与字段语义使它不能充当可出示的逐调用账本」**（Tier 1 [34] + Tier 3 [36]，抽查后定分级）。
2. **E1–E9 的「业界都这么做」不许出现**：检索明确显示 LSP/MCP/A2A 三家都**没有**「受理回执 + 出处档 + 结算载荷」。`turn_accepted` / `why` / settle 是本项目的**主张**，不是被标准确认的做法（Tier 1 [20][21][22][23]）。
