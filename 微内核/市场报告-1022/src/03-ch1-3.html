01 · Why a v3

01为什么要出 v3：抽查抓到的五处错

v3 不是因为市场变了，是因为 v2 与本轮初稿里有五处会被两分钟内复核掉的错。先把错摊开，才有资格讲后面的判词。

#被抓到的句子抽查判定纠正后的口径
1「Art.12 要求高风险系统在全生命周期内技术上支持自动记录事件」内容大致对，时点错Art.12 只规定记录使用期间、参照数据库、输入数据、核验人员；高风险义务的适用时点已被 Omnibus 推迟（见 §2.2）
2「至少六个月留存」挂在 Art.12 名下归属已核六个月在 Art.26(6)，是部署方义务；Art.12 本体不含时长
3MT-Bench：换序一致率 65%、复读失败率 8.7%/91.3%、同族自评 +10 分、人-人 81–82%UNSUPPORTED，撤摘要层只支撑「与人类一致率 >80%」；其余四个数字与论文原件不吻合，不进正文
4「89% 团队已上可观测、29.5% 完全不做 eval（n≈1,300）」一手取不到，撤连报告名都存疑；一手报告页打开之前，这组数与 n 一律不出现
5「Langfuse 把审计日志、SCIM、SSO 全锁在 Enterprise」PARTIAL审计日志与 SCIM 是 Enterprise；SSO 强制另出现在 $300/月 Teams 加购档。自托管许可（MIT）不写在定价页，须另取件
这五处错共同指向一条新规矩

第 3、4 条当初都带了「待复核」的标注，仍然进了正文——说明「标注了风险」不等于「没有过界」。 v3 起用机械口径执行：只有 A 级（读过原文正文或表格原件）的数字才允许被排版。 这条规矩本身也配了闸：话术闸（研究-1022/话术闸.py）逐行扫描四类越界话术并要求每个 `**[High]**` 同段有凭据词，五条臂全部验过会红（GATE_RC=0）。

另有两处降级留在附录 A：RFC 9162 的「Experimental 轨 / obsolete RFC 6962」两个限定词未对 rfc-editor 核实即撤；Traccia 的「开源」未核到即撤。

02 · Regulation

02法规时线重算：账本义务现在到底要不要

2.1 Art.12 与 Art.26(6) 的分工

读到原文的 Art.12 只要求：高风险系统在整个生命周期内技术上支持自动生成日志，记录范围包括使用期间、参照数据库、输入数据（造成匹配的那些）与核验人员，并指向 Art.26。 条文本体没有任何留存时长，也没有任何格式规定。 「至少六个月」出现在 Art.26(6)：部署方须保留系统自动生成的日志，期限按预期目的定，且「至少六个月」，除非适用的联盟或成员国法律另有规定。

条文要的对象
部署方保留系统自己生成的日志
条文没要的
格式、字段、分档出处、第三方件、可独立验证

⇒ 直接后果：本件的「49 格 + 五档出处」不是法定要求，它是内部复核装置——回答「谁的哪一次调用被账本改写了结果」。把后者讲清楚，比把前者说成合规要可信得多。

一手没打开的部分，写在这里而不是抹平

Regulation (EU) 2026/1744（Digital Omnibus on AI）的标题与编号经 ELI 条目与两家法律二级源核对； 但 EUR-Lex 页面本轮两次不可达，「Official Journal 2026-07-24 / 生效 07-27」与「Chapter III Sections 1-3」这两个措辞都已从正文撤下。 ISO/IEC 42001 的条款级记录清单在付费标准正文里（CHF 225），公开网无法核——所以我们同时拒绝两种说法： 既不说「42001 要求 12 个月日志」，也不说「42001 什么都不要求」。

2.3 自愿框架为什么撑不起预算

NIST 官网原话是 AI RMF「is intended for voluntary use」，生成式 AI Profile（AI 600-1，2024-07-26）同族自愿； 两者提供的是风险类与建议动作清单，不规定任何特定留存件。ISACA 的实操描述更关键：因为 42001 与 27001 同族， 团队的真实做法是把 AI 控制项「折进既有审计节奏与证据里」——也就是说，审计师接受复用既有管线。

中介话术样本：有人在替监管立法

一家 ISO 42001 代办机构的页面声称现场审核会问「是否保存至少 12 个月的输入输出日志供追溯」，并归给「Clause 8.2.3 及附件 B 的强制性要求」。 本轮在任何 A/B 级来源里都找不到这条要求。它的价值不是「证明 ISO 有这个要求」，恰恰相反—— 它证明市场上存在把自愿框架包装成强制要求的推销话术，而这正是学界提醒要打折的那类来源（卖合规服务者自称无偏见，实则既有既得利益）。 ⇒ 对我们的含义：我们的客户会被这种话术教育过一遍，我们的诚实表述反而听像「卖得不够狠」。这是真实的销售摩擦，不是修辞。

智能体专项法律分析的位置也要更正：我们曾把 Nannini et al.《AI Agents Under EU Law》（arXiv:2604.04604，2026-04-06）称作「唯一一份」， 它自述为该方向第一份系统性监管映射（预印本），涉及 Standardisation Request M/613 下的草案协调标准、九类 agent 部署分类， 四项挑战为网络安全、人类监督、多方行动链上的透明度、运行期行为漂移。最后一项与本件同题——但它是预印本，不是监管意见，不能当依据卖。

03 · Buyer Gates

03买方门槛三件套：归属 / 连续留存 / 可分发报告

3.1 门槛真实存在，但与法规无关

门槛买方实际要的东西本件能不能供上来源强度
供应商资质SOC 2 Type II 报告（被多份材料描述为 RFP 阶段即淘汰的门槛；一家有一 SOC 2 的企业会要求供应链也带 Type II）不能——本件没有报告，且这是对供应商的要求，不是对产品的要求D 级
证据生成方式Type II 要 6–12 个月持续生成并留存，不许审计前临时抓能——append-only 逐发落账正是连续生成；这是本件与门槛最直接的对接口D 级
可归属最常见发现项：共享服务账号无法归属到人、密钥进源码、缺细粒度访问控制半个——账本记的是调用与 session/发号/侧三轴，不记「人」；归属要靠宿主把主体写进入参D 级
可分发一份报告可复用分发给所有客户（这也是厂商愿意为 SOC 2 付 $12k–20k 的原因）能——本件的收口件（轨迹解剖 + 判定表 + 可复跑命令）天然是可分发形态D 级
不可逆留存监管接受的是存储配置判断：Object Lock compliance mode + Cohasset 评估，限定语「when correctly configured」不能单独供——本件不写盘、不控制存储；必须与宿主/对象存储配置件搭配讲A 级

3.2 没人要求「逐调用记录可独立验证」

这是一条自我否证的检索结果

补证波专门去找「客户/监管明确要求 agent 逐调用记录须可独立验证」的一手件， 结论是：没有取到，并且该路子代理在报告里明写「nearest thing is an unsourced practitioner assertion」。 我们把这个空洞放进正文而不是放进附录，因为它是本报告最重要的负结果： 如果连「要求」本身都没有被记录下来，那 v2 那句「等它成为独立预算科目」就不是乐观不乐观的问题，而是尚不存在。

但同一批检索给出了两个不依赖法规的正面信号：

  • 买方把合规排在第一位
    云 AI 规模化障碍榜：治理/安全/合规 53% > 数据质量 40% > 成本 30% D 级
  • 治理成熟度是缺口
    约 1/5 公司对自治智能体有成熟治理模型，74% 计划部署 D 级（厂商引 Deloitte）

⇒ v3 的接口建议：不卖「合规要求」，卖「买方自己承认排在第一的那件事」——他们要在没有时间线压力的窗口里，把 agent 行为变成可归属、可持续留存、可分发的复核对象。这句话比「Art.12 要求你」小，但站得住。
