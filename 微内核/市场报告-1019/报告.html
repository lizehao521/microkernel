Executive Summary

00摘要与建议

一句话答案：先以“研究出版 + 开源证据闸门”面对市场，把付费私有化设为条件触发；不做托管按次，不做承诺记账，不做“更可信的 Agent”叙事。六个月四道闸，不过就冻结为研究资产。

这不是一个“市场够不够大”的问题，而是一个“证据够不够硬、买方够不够具体”的问题。 市场数据能证明“可追溯”有预算，但不能证明“这颗内核”能被一个没参与过项目的人接上并愿意付钱。 后者只能用外部干净臂和设计伙伴来证明，不能用市场规模代替。

三个结论

结论一：市场存在，但它的形状是“收口件”，不是“引擎”

agentkernel 把一次 Agent 调用拆成 49 格、逐格要求“值 + 出处”，任一格不自洽就整发拒收，账本用哈希链串起来。 这解决的是“说出来的话有没有出处”，不是“活干得好不好”。外部证据也支持这个边界： 8 题盲测里纯模型 8/8、带内核 6/8；它管报账的出身与自洽，不跑代码、不判语义。 因此它不能被卖成“能力增强”，只能被卖成“收口时的一份可复核交代”。

这个“收口件”寄生在三类预算里：可观测性（已经有追踪，缺拒收语义）、 合规（EU AI Act 第 12 条、GB/T 47746—2026、电商法第 48 条要求可追溯）、 外包/多代理交付（出事时要能指名哪一格被拦）。 它不寄生在安全预算里——因为审计层不是防线。

结论二：今天不能卖，因为证据债还没还完

“可复核”是产品承诺本身。如果产品自己不能被外部复核，卖它就是把证据债转成声誉债。今天有五个缺口：

结论三：进入方式是 D + A → B，不是 SaaS

市场太窄，撑不起一个通用平台公司；但足够养活一个高单价、低销量的窄产品。 这决定了进入方式必须是“低成本分发 + 高单价私有化”，而不是“免费增值 + 自助 SaaS 规模化”。 先用研究出版（D）建立话语和外部证据，再用开源闸门（A）换真实调用方； 只有外部干净臂、2 家设计伙伴、1 次安全审查都过了，才启动企业私有化（B）。 托管按次（C）与“运行时不联网”的定位冲突，且运营负担最重，今天不做。 竞赛/生态（E）是可选放大器，不是主线。

本报告可能错在哪里

三处最可能错：第一，SAM 的子层占比是假设，厂商不披露“证据/审计”子层收入，1.6–3.0 亿美元只是一个可用来做决策的数量级； 第二，买方可能不为“审计”单独付费，而是要求它包含在现有可观测性套餐里； 第三，大厂可能在 12–24 个月内把“证据/拒收”做成默认功能，把价格打到零。 这三条中任何一条成立，都指向同一动作：不要先建销售组织，先建外部证据与开源分布。

今天最危险的动作

把“市场很大”当成“产品可卖”。AI 治理、AI TRiSM、LLM 可观测性都是真预算，但它们的入口是平台、网关、云厂商，不是一颗独立的 Go 内核。直接做 SaaS，等于用最贵的获客方式去卖一个最窄的功能。

Chapter 01 · Object & Problem

01研究对象与问题

本章回答：为什么市场报告的对象是 agentkernel，而不是刚做完闭环的 26 策略引擎？这颗内核到底卖的是什么、不卖什么？

选市场对象的标准不是“哪个更酷”，而是三条硬条件：有没有外部调用方、有没有可验证的账、有没有一条能被证伪的验收线。 agentkernel 三条都有；26 策略引擎三条都没有走到“外部”这一步。这不是贬低后者，而是把研究资产和产品对象分开， 否则报告会把“技术能力闭环”误写成“市场验证”。

1.1 为什么是 agentkernel，不是 26 策略引擎

26 策略引擎是一套内部研究资产。它的目录声明 26 条策略，其中 20 条有实现分支、1 条是恒等返回（context_switch）、5 条是只参与调度的元策略。 2026-10-19 的离线合成样例 7/7 环跑通，但真实靶场投递仍然是 NOT_RUN，宿主引擎在 Qoder 内真实执行 0 次。 它证明的是“策略目录可以被审计、恒等分支可以被修掉”，不是“有人愿意为它付钱”。

agentkernel 不一样：它有 49 格契约、哈希链账本、外部调用方的 6 发实测（294 条记录，整本账 490 条）、 一次 session 内 4 次当面拒收，以及一条写死的唯一验收。它已经走到了“外部调用方真的把数据发进来”这一步。 所以它是市场对象；26 策略引擎最多是技术品牌附件，不能作为收入对象。

1.2 产品是什么、不是什么

agentkernel 的一句话是：给 Agent 的每一句话上税：说不出“谁算的”，就进不了下游。 交付形态是一个能挂进任何 Agent 框架的证据闸门（MCP 服务 + 一本可验链的往来账），不是一个 SDK、不是一个评测榜单、不是模型。

它是什么

输出闸门：一发往来拆成 49 格（输入侧 20 + 输出侧 29，call 两侧同名），逐格带“值 + 档位 + 出处”。

原子拒收：任一格不自洽，整发拒收、两侧都不写、拒收另计一格。坏数据一条都不写。

可验的账：哈希链、append-only、三态结论（自洽 / 不符 / 核不了）；缺尾不许读成自洽。

一个机器可读的数：拦了几次、拦在哪一格、拒的是哪一路（落账 / 预检 / 门口 / 协议层 / 传输层）。
它不是什么

不是调度器：没有循环、定时器、cron；谁调它、调完去干什么，是调用方的事。

不是联网器：不调模型、不取外部数据、不推送；只有被动监听回环端口与账本文件 I/O。

不是工具执行器：不跑命令、不加载代码；唯一 exec 在构建期自检里，用来证明依赖集仍是纯 stdlib。

不是防线：不挡提示注入、不做访问控制、不替代网关或 WAF。审计层不是防线。

49 格与五种档位

每一格不是裸值，而是“值 + 档位 + 出处”的形状。档位是整数枚举： 0 未标 / 1 measured / 2 relayed / 3 estimated / 4 model_says； 账本渲染里的 5 是落账时由缺席翻译出来的，不手填。 一个 Measure 缺席的正确写法是 Absent=true, Basis=0, N=0，理由写 Why； Absent=true 时给 Basis=5 会被拒——“没量到的东西说不出是谁算的”。

规矩只有一句：0 是量到的 0，不是“没量到”的占位符。 这里说的 0 是值的 0；档位里的 0 是“未标”，两件事不要混。 这条规矩是整颗内核的底线，也是它最容易被误解的地方：它让“没量到却写成 0”变成一个可拒收的错误，而不是一个沉默的默认值。

“给 Agent 的每一句话上税：说不出‘谁算的’，就进不了下游。” 产品定位 · 一句话

原子拒收与哈希链

一发里任一格不自洽，整发拒收、两侧都不写、拒收另计一格。 外部调用方的实测里，它那 6 发 = 294 条，整本账 490 条；每发落 49 条，没有出现非 49 倍数的半发。 注意：490 里面另有 196 条属于一条与本调用方无关的 session，不能把整本账的增长全记在它头上。 这不是“尽量不写坏数据”，而是“坏数据一条都不写”。

账本每条带前序哈希，verify 能逐条比对原像。外部评估的 6 发全部能按 session + 发号 + 侧读回， 逐发指纹与盘上文件对上；它没有回改旧发。这证明的是链的完整性，不是内容的真实性： 链能证明“这条记录没有被改过”，不能证明“记录里那句话是真的”。 这条区分必须在对外材料里写清楚，否则安全买家会在第一次尽调里把它证伪。

1.3 两种失效：说法漂白与事后拿不出

第一种：说法漂白。上游一个没有依据的计数，被下游当证据写进结论。 这个仓库的 kernel.go 头部写的第一条不变量就是为这件事写的，来源是一次真事故。 说法一旦被写进一份看起来正式的记录，后面的人就会把它当事实继续引用。

第二种：事后拿不出。事情做完，只有聊天记录和零散日志；要回答“当时到底量到了什么”，只能靠回忆。 日志能证明“调用发生过”，但不能证明“那句‘核对过’对应哪一次调用、哪个价格源”；也不能回答“12 个页面里有没有哪一格其实是没量到，却被写成了 0”。

这两种失效的共同点是：说错话的成本太低，而证明说错话的成本太高。 这颗内核的全部设计，就是把“说错话”变成一次可以被当场拒收的写入。 它最有力的演示不是 PPT，而是一次真实 session 里当面拒了 4 次不实装配：

  • 把空响应记成正常收尾；
  • 把类别谎报去留状态码；
  • 把对端自报的数标成自己量的；
  • 宣称通知发了，而段里没有。

每一次都能从账上读出“被拒的写入 N 次”这个数，并指名是哪一格拦的。 通用 lint / eval 做不到这件事：它们能告诉你“输出看起来不对”，但不能告诉你“这一格的出处是假的，所以整发不收”。

2.5 为什么不用“AI 治理”整体做 TAM

因为单位不对。AI 治理市场的很大一部分是咨询、政策、培训、模型风险管理平台； 这些预算的买方是合规部门和咨询公司，交付物是制度、评估报告、认证准备， 不是“一次 Agent 调用的 49 格账”。把这部分算进 TAM，会得到一个漂亮但无法转化为收入的数字。

同样，也不把“安全”算进来。安全预算买的是阻断和防护；这颗内核不挡攻击，只记录“谁算的”。 把它卖进安全预算，第一次 POC 就会被要求“挡住一次提示注入”，而它做不到；这不是产品缺陷，是预算错配。

2.6 规模结论对进入方式的含义

  • 市场够养活窄产品，不够撑平台公司。60–400 个账户、1.5 万美元 ARPU 就能到 90 万–600 万美元；这足够一个两人团队，但撑不起销售组织。
  • 必须高单价、低销量。按 29 美元/月卖，需要数万账户，获客成本会把毛利吃光；按 1.2–3 万美元/年卖，100 个账户就是 120–300 万美元。
  • 必须寄生在已有预算里。可观测性预算已经存在，合规预算正在形成；不要教育买方“你需要一个新产品”，要告诉他“你已有的追踪缺一层签收”。
  • 必须先用开源换渠道。没有销售组织时，开源是唯一能低成本触达工程团队的渠道；研究出版是唯一能低成本触达合规/决策者的渠道。
规模结论

这不是一个“赢家通吃”的市场，也不是一个“快速增长”的市场。它是一个窄、深、高单价、低销量的合规/收口件市场。进入方式必须匹配这个形状：先开源换证据，再私有化换收入；不要用 SaaS 的获客模型去套它。

不要说“用了它就符合 EU AI Act”。它只提供技术记录，不提供法律结论。
不要把“高风险系统”的义务外推到所有 Agent。大多数Agent不是高风险；过度宣称会被合规买家一眼识破。
不要把“模型调用记录”当成“对客承诺记录”。后者是另一个产品（B 路线），单位不对。

合规驱动还有一个时间差：法规生效不等于预算到位。EU AI Act 的高风险义务从 2026-08-02 起适用， 但企业的合规预算通常提前 6–12 个月立项，且在第一次审计/问卷/客户追责时才会真正花钱。 所以 2026 年下半年到 2027 年上半年，是“问询增多、预算释放”的窗口；窗口里卖的是“技术附件”，不是“认证”。

3.2 技术驱动：MCP 采用了，遥测没跟上

MCP 生态的采用数据说明两件事：预算存在，且缺口存在。 公网 MCP 服务器已经超过 10,000 个；Stacklok 的调查里 41% 的组织在生产中使用 MCP； LangChain 的调查里 57% 的受访者在生产中使用 Agent，约 89% 有某种可观测性，29.5% 没有评测。 这些样本偏向活跃开发者，不能当全球普查，但足以说明“追踪/评测”已经是常规预算项。

外部读数数字对内核的含义
公网 MCP 服务器数量10,000+供给端已经形成；调用审计有对象，不需要教育“什么是 MCP”

这组数据最容易被误读成“市场很大，赶紧做”。正确的读法是： 可观测性是红海，证据/拒收是红海里的一个窄缝。 89% 有可观测性，说明买方已经习惯了“看追踪”；他们不会为“再一个追踪面板”付钱， 但可能会为“追踪之后的一层签收”付钱——前提是你能证明这层签收能拦住东西、能指名格位。

3.3 事故驱动：调查需要账，但账不是防线

2026-02-27 披露的 MCPwnfluence 是一个典型：CVE-2026-27825（CVSS 9.1，任意文件写到 RCE） 加 CVE-2026-27826（CVSS 8.2，未认证 SSRF），影响 0.17.0 之前版本，有公开 PoC； 按披露方口径，受影响包的下载量逾 400 万。FreeBuf 与 Bishop Fox 的复盘都指向同一件事： 认证与边界在每一环缺席。

这类事故会带来两个需求：事前阻断和事后调查。 这颗内核只做后者的一小部分：它能告诉你“这一发调用记了什么、谁算的、哪一格被拒”， 但它不能告诉你“攻击者怎么进来的”，也不能阻止下一次。把两者混为一谈，是进入安全预算时最常见的死法。

审计层不是防线（对外材料第一屏）

如果买方问“能不能挡提示注入”，正确答案是“不能”。如果买方需要阻断，应该找 MCP 网关、WAF、DLP、访问控制。内核的价值是事后能拿出发生过什么，而不是事前不让它发生。

内部事故的说服力更强，因为它有账可查：一次 session 里，内核当面拒了 4 次不实装配 （空响应记正常收尾、类别谎报去留状态码、对端自报数标成自己量的、宣称通知发了而段里没有）。 每一次都能从账上读出“被拒的写入 N 次”并指名格位。 这不是“模型变聪明了”，而是“说错话被当场收费了”。

采购驱动最关键的不是“预算大小”，而是“谁在什么时候会主动找”。可观测性预算是常态预算，但买方不会主动找“签收层”； 合规预算是触发预算，一旦审计/问卷/追责发生，买方会在几周内找人。 所以冷启动的正确顺序是：先用开源进入可观测性预算，再用一次真实触发把签收层推进合规预算。 反过来（先打合规、再补工程）会卡在采购周期和法律审查上。

3.5 反驱动：五件会让需求消失的事

  • 大厂捆绑：LangSmith、Langfuse、Datadog 把“证据/签收”做成默认功能，价格包含在现有套餐里。
  • 开源替代：Langfuse 以 MIT 协议自托管；买方会说“我为什么不用免费的”。
  • 自建：一个工程师 2–4 周能写一个“记录 + 哈希”的版本；难点不在代码，在判据和证据，但买方常常低估后者。
  • “我们已经有日志”：买方把“调用发生过”当成“出处可核”，不认为需要额外一层。
  • Agent 项目取消：Gartner 预测到 2027 年底超过 40% 的 Agentic AI 项目会被取消；预算消失时，审计是第一个被砍的“非功能项”。

这五条反驱动里，前三条是竞争，后两条是需求本身的风险。 它们共同说明：不能做“泛审计”，只能做“触发点上的收口”。 泛审计会被免费/捆绑打掉；触发点上的收口有明确的“现在就要”的买方。

3.6 需求结论

需求是触发型的，不是常态型的

平时买方不会主动找“可复核的交代”；事故、审计、外包交付、客户追责发生时，他会在一周内找。产品的市场动作应该围绕触发点设计：让他在触发时能搜到你、能在 30 分钟试到你、能在一次 POC 里看到你拦住东西。

这也解释了为什么“研究出版 + 开源”是正确顺序：研究出版让触发时的搜索能找到你（合规/审计关键词）， 开源让触发时的工程验证能立刻开始（不需要销售、不需要合同）。两者都不需要现金投入，却正好覆盖触发型买方的两个动作。

4.3 竞争定位：空白在右下角，但不大

4.4 五力：横向 SaaS 不具吸引力

“五力都强”通常意味着这个市场不该进。但对这颗内核来说，正确的结论不是“不进”，而是“不要以横向 SaaS 的方式进”。 作为窄合规组件，它可以用高单价、低销量、私有化交付绕开五力中最伤人的两条：买方比价和免费替代。 买方仍然强，但他买的不是“日志”，而是“出了事能拿出的交代”；这个价值不在 Langfuse 的比价表里。

4.5 竞争会从哪里打死它

第一条路径：可观测性平台向下做证据。LangSmith、Langfuse、Datadog 已经有追踪、评测、提示管理； 再加一个“evidence / attestation”模块，把“逐格出处 + 拒收”做成套餐功能，是完全合理的产品延伸。 它们的优势是分发和现有预算，时间窗 12–24 个月。

第二条路径：MCP 网关把审计做成默认。Microsoft、Docker、Zuplo、TrueFoundry 等控制面厂商， 已经在做认证、路由、策略；再加“调用后审计”是同一采购人的相邻需求。 它们的优势是“准入”这个必经之路，时间窗 6–18 个月。

还有两条慢路径：云厂商把“AI 审计账本”做成基础设施（AWS/Azure 的信任与合规优势）， 以及开源社区复制 49 格契约（代码可复制，证据 corpus 不可复制）。 这四条路径里，前两条最危险，因为它们不需要“相信一个新品类”，只需要在现有产品里加一个功能。

防御不是“代码更难抄”

49 格、哈希链、MCP 集成都不是壁垒。真正的壁垒是：判据表的可证伪性、拒收语义的细节、真实故障的证据 corpus、以及“外部调用方已经过了干净臂”这件事。前三个可以写出来，第四个只能跑出来。

4.6 合作而非替代：做签收层，不做追踪层

最现实的进入方式不是“替代 Langfuse/Datadog”，而是“接在它们后面”： 追踪层记录“发生了什么”，签收层记录“这句话是谁算的、能不能收”。两者用 trace ID 关联， 买方不需要换掉现有可观测性，只需要在收口处多一步“签收”。

  • 与 OTel 合作：消费 GenAI 语义约定的 span，或在 span 结束后生成一份“收口凭证”；不重复造追踪。
  • 与 Langfuse/Datadog 合作：把内核账本的指纹写回追踪，作为“可验附件”；它们有分发，内核有拒收语义。
  • 与 MCP 网关合作：网关管准入，内核管报账；“过了网关”不等于“这句话有出处”，两者互补。
  • 与 GRC 合作：GRC 管制度和风险登记，内核提供运行时证据；GRC 是证据的消费者，不是竞品。

“为什么不用 Langfuse？”他在比价；Langfuse 免费/便宜“Langfuse 记录发生了什么；内核判断这句话能不能收，并指名哪一格拦的。单位不同。你可以两个都用，用 trace ID 关联。”
“谁来支持？一个人靠谱吗？”他在评估交付风险“私有化部署 + 支持合同 + 源码可审计；单作者是风险，我们把它写进合同和路线图，不藏着。”

这五类反对意见里，前三类必须在第一次通话就回答，不能等到 POC。 因为前三类决定“预算对不对”，后两类决定“能不能成交”。 如果第一次通话不主动说“不是防线、不是合规认证、不是能力增强”，买方会在尽调时自己发现，然后把你归类为“过度宣称”。

POC 是整条旅程的生死点。买方在 POC 里最想看到的不是“系统跑起来了”，而是“它拦住了一个我故意做坏的调用，并告诉我哪一格错了”。 所以 POC 设计必须包含一个坏发：调用方故意把 relayed 标成 measured，或把 absent 写成 0，内核必须整发拒收并指名格位。 如果 POC 只跑好发，买方会认为它只是一个“更复杂的日志”。

POC 成功判据（与唯一验收一致）

1. 账上“被拒的写入 ≥1”，且能指名哪一格、内核原话是什么；
2. 全程链自洽、sk- 0 次、没有“没量到却写成 0”；
3. 接入 ≤30 分钟，调用方模型代码零改动。

注意：这条验收今天严格 FAIL（真人外部未跑、拒收归因 5/8、缺席表达 G1）。POC 之前必须先补这三项，否则会把买方变成测试员。

5.4 非客户：五类不要追

  • 个人开发者：没有预算，也不需要审计；给他们开源版即可，不投入销售。
  • 模型实验室：自建能力强，且他们的“账”是训练数据/评测，不是调用记录。
  • 纯单轮聊天产品：没有多代理/工具调用，49 格的大部分格用不上。
  • 把审计当防火墙的团队：他们会用“能不能挡注入”验收，必然失望；不要试图教育，直接转介网关。
  • 只想让模型更准的团队：8/8 vs 6/8 是负证据；卖给他们等于自证无用。

5.5 零成本需求验证计划

在写任何销售材料之前，先做 10 次访谈。访谈对象来自已有网络：做多代理平台的工程负责人、受监管行业的 AI 交付负责人、 Agent 框架/MCP 网关的产品负责人。全部远程、零差旅、零礼品；不要求对方付费，也不要求对方部署。

5.6 细分结论

先打“多代理平台团队 + 合规暴露”这个交集，而不是整个可观测性市场。 这个交集的人数不多，但正好是“有预算、有触发、能自己做 POC”的买方； 他们成功后，会成为受监管客户的参考案例；受监管客户成功后，会成为框架厂商 OEM 的背书。 顺序是：开源入口 → 设计伙伴 → 付费试点 → OEM，不能跳步。

Chapter 07 · Go-to-Market Options

07市场进入方式：五个选项

本章回答：面对市场，具体有哪五种方式？每一种承诺什么、卖给谁、要什么证据、今天该不该走？

五个选项不是“五个都试试”，而是“五种不同的承诺”。 开源承诺“可接入”，私有化承诺“可交付”，托管承诺“可运营”，研究承诺“可复现”，竞赛承诺“可展示”。 这颗内核今天能兑现的是“可接入 + 可复现”，还不能兑现“可交付 + 可运营”；所以顺序必须是 D + A → B，而不是反过来。

7.1 选项 A：开源 / 开放核心

承诺：任何人可以在 30 分钟内把闸门接进自己的 Agent 框架，免费看到“哪一格被拒、为什么”。 核心闸门与账本开源（建议 Apache-2.0 或同等宽松许可）；付费部分放在“签名构建、合规证据包、私有化支持、SSO/HA、审计导出”，而不是把判据表藏起来。

为什么现在走：这是唯一不需要销售组织的分发渠道；也是唯一能在触发点上让工程团队立刻验证的方式。开源还能把“49 格判据”变成公共语言，降低教育成本。

需要什么证据：3 分钟 README、10 分钟演示、外部干净臂、可复现构建、SBOM、明确的“不做什么”。没有这些，开源只会带来 issue，不会带来信任。

收入模型：无直接收入；后续靠私有化许可、支持合同、OEM、合规包。不要把开源当“免费试用”，要当“分发与证据机器”。

风险：维护成本、被大厂吸收、被克隆、支持负担、没有收入。缓解：范围冻结、只维护一个版本、把支持写进付费合同。

结论：现在走。

7.2 选项 B：企业私有化许可

承诺：把闸门部署进客户 VPC，按年授权 + 支持；提供签名二进制、SBOM、合规证据包、部署手册、回滚方案。 建议价格 1.2–3 万美元/年；试点 3–5 千美元/6 周，可抵扣年费。

为什么有条件：它匹配“窄市场、高单价、低销量”的形状，也能避开按 seat 比价。但它要求客户信任一个单作者项目，要求安全审查、责任边界、支持 SLA；这些今天都还没有。

需要什么证据：外部干净臂、2 家设计伙伴 LOI、1 次安全审查通过、可复现构建、DPA/责任条款、至少一次真实付费试点。缺一件，都不要报价。

风险：销售周期 2–4 个月（受监管 4–9 个月）、单作者交付、支持挤占开发、责任上限、采购门槛。缓解：只做私有化、不做托管；只签有限支持；把“不挡攻击/不认证”写进合同。

结论：条件触发：Gate 2 通过后再走。

7.3 选项 C：托管按次证据服务

承诺：客户把调用发到托管服务，按次收费，出具证据包；无需部署。 价格可能是 0.05–0.5 美元/次收口，或 99–999 美元/月套餐。

为什么不走：它要求托管、可用性、数据驻留、隐私、事件响应、保险；这些运营负担与“单作者、运行时不联网”的现状冲突。 更致命的是价格锚：按次计价会被拿去和 span/request 比价，而内核的价值是“一次收口”，不是“一次请求”。

需要什么证据：托管基础设施、SLA、数据驻留、隐私影响评估、保险、7×24 响应；这些今天都没有，也不应该为了市场报告去补。

结论：不做。如果未来有 OEM/云厂商愿意托管，可以作为他们的服务，不是我们的。

7.4 选项 D：研究出版 / 标准

承诺：公开方法、契约、证据与失败案例；把“可验证记账”变成一个可讨论、可复现、可引用的概念。 输出包括本报告、白皮书、OWASP MCP08 映射、EU AI Act 第 12 条技术附件说明、可复现实验。

为什么现在走：零现金成本；能在触发点上被搜到；能建立“这个人不是来卖焦虑的”信任；能把判据表变成公共语言，降低后续销售教育成本。

需要什么证据：报告、可复现实验、原始件、明确的边界与缺口。研究出版最忌“只讲成功”，要把 8/8 vs 6/8、严格 FAIL、G1 一起写进去。

风险：影响力慢、被抄、没有直接收入。缓解：公开判据、保留证据 corpus、用开源做分发。

结论：现在走，与 A 并行。

7.5 选项 E：竞赛 / 生态

承诺：用可运行作品、演示视频、文档参加竞赛/生态活动，换取曝光、奖金、合作伙伴。 MatrixNEXT 2026 的公开信息是：截止 2026-11-11、活动 11-14、奖池 30 万人民币，要求可运行作品 + 演示视频 + 文档，评审看创新、完整度、技术深度、UX。

为什么可选：23 天截止，当前 UI/演示弱，准备演示会挤占 Gate 1 的证据工作；获奖不确定，且奖金不能替代产品验证。

什么情况下走：如果 10 天内能做出 5 分钟演示且不碰内核判据，可以低成本参加；否则不参加。不要把竞赛当市场验证。

结论：可选，不优先。

Chapter 09 · Pricing & Unit Economics

09定价与单位经济

本章回答：按什么单位收费？价格带在哪？毛利够不够养一个窄产品？

定价不是“拍一个数字”，而是“选一个计价单位”。 按 seat 卖，会被 39 美元/月的开发者工具压死；按 span 卖，会被 160 美元/月的可观测性套餐压死； 按“收口次数/年费”卖，才能把价值锚定在“一次可复核的交代”上，而不是“又一条日志”。

9.1 计价单位：收口，不是 seat / span / token

单位买方怎么理解对内核的后果是否采用
seat“每个工程师每月多少钱”被 29–39 美元/月锚定；内核不是人用的，是系统调用的不采用
span / request“每次请求多少钱”被 Datadog/Helicone 的按量价格锚定；内核按发收口，不是按 span不采用
token“模型用量多少钱”与模型账单混在一起；内核不调模型不采用
收口次数 / 年费“一份可复核的交代多少钱”与人工复核、合规附件对比；避开可观测性比价采用

“收口”可以定义为“一发完整往来落账并给出三态结论”。它比“调用”更贴近买方价值： 买方不关心你记了多少 span，他关心“这一发能不能收、出了事能不能拿出来”。 年费 + 收口包的好处是：买方可以预算，卖方可以承诺；超出部分按次，避免无限支持。

9.2 价格锚：三个参照系

  • 人工复核：一次复核 30–120 分钟，按 50–150 美元/小时计，成本 25–300 美元。若内核能省下一次复核，单次价值上限是 25–300 美元；但买方不会按上限付。
  • 可观测性：29–249 美元/月的入门套餐；这是买方最熟悉的锚，也是最低的锚。内核不能和它比“记录”，只能比“拒收 + 归因”。
  • 合规/审计：一次外部审计/律师意见的成本远高于软件年费；但采购周期长、决策人多。内核作为“技术附件”进入，价格可以到 1.2–3 万美元/年。

11.2 依赖关系

  • 证据修复 → 外部干净臂：不修 #48/G1/计数行，干净臂会在“拒收归因”上失败。
  • 外部干净臂 → 销售：没有干净臂，销售会把买方变成测试员，且一次失败会传开。
  • LOI → 私有化包：没有 LOI，不知道客户要什么部署形态，容易做出无用的包。
  • 安全审查 → 付费试点：没有 SBOM/DPA/责任边界，受监管客户无法采购。
  • 付费试点 → 规模化：没有续费/转正，规模化只是把获客成本放大。

Chapter 12 · Financial Scenarios

12财务情景与继续 / 冻结判据

本章回答：三种情景下，三年收入/成本/现金流是什么样？什么条件下值得继续？

这一章不是预测，是“情景假设”：在没有融资、没有销售、单作者的前提下，收入能到什么量级。 三种情景都用同一组价格与支持成本，只改“付费账户数”与“ARPU”。 如果连保守情景都跑不到，说明市场对象或切口错了，应该冻结，而不是加功能。

12.3 什么会改变模型

  • 设计伙伴带预算：如果一家受监管客户愿意签 3–5 万美元的试点，基准情景的 Y1 会从 1 家变 2–3 家，但交付压力也上升。

  • OEM：如果一家 Agent 框架/网关愿意白标，收入可以跳档，但会失去定价权与客户关系。
  • 收购：如果可观测性/云厂商收购，回报可能高于独立经营；但这不在基准情景内，也不应作为目标。

基准情景：第三年 81 万美元收入；三年累计约 105 万美元

第三年净现金流约 75 万美元，三年累计约 94 万美元。这是一个“一个人 + 窄产品”的合理上限，不是 VC 级增长。它足以证明产品有人买，也足以支撑继续投入；但如果目标是“平台公司”，这个模型不够，需要 OEM/合规强制/收购等外部变量，不能靠加功能解决。

Chapter 13 · Conclusion

13结论

回到问题：agentkernel 应该以哪种方式面对市场？

先以“研究出版 + 开源闸门”面对市场，把付费私有化设为条件触发；不做托管按次，不做承诺记账，不做“更可信的 Agent”叙事。 六个月四道闸，不过就冻结为研究资产。这不是保守，而是让产品的第一次市场接触与它的证据状态匹配。

五条结论

  1. 市场存在，但窄。SAM 约 1.6–3.0 亿美元，SOM 三年 0.8–600 万美元；这是一个能养活窄产品的市场，不是平台市场。
  2. 产品是收口件，不是引擎。它管“这句话是谁算的、能不能收”，不管“活干得好不好”；8/8 vs 6/8 是负证据。
  3. 今天不能卖。真人外部验收 NOT_RUN、严格 FAIL、拒收归因 5/8、G1 缺席表达、交付凭据错位；卖早了会把证据债变成声誉债。
  4. 进入方式是 D + A → B。研究出版换信任，开源换分发与外部证据；私有化只在 Gate 1–3 都过后启动；托管按次不做；竞赛可选。
  5. 六个月四道闸，不过就冻结。冻结不是失败，是把研究资产从产品叙事里救出来；保留开源、报告、判据与证据 corpus。

为什么不是“直接卖”

直接卖看起来更快：有市场数据、有价格锚、有竞品空白。但它要求产品先具备三件今天没有的东西： 一个非作者真人能过干净臂、每次拒收都能机核格位、交付包与凭据一致。 这三件不是“销售能补”的，是“证据能补”的。先卖再补，等于让买方替你发现缺口； 而“可复核”产品的第一次失败，会被记成“它自己都不可复核”。

为什么不是“只做研究”

只做研究能保住声誉，但换不到外部证据。研究出版的价值在于“被引用、被试用、被挑战”； 如果没有开源闸门，读者只能相信文字，不能自己跑。D + A 的组合，是把“可复现”从论文变成可执行件： 读者可以下载、接入、故意做一发坏数据，看它是否拒收。这比任何市场报告都更能证明产品。

什么会推翻这个结论

  • 10 次访谈里出现 ≥3 个“现在就要、有预算、愿意做设计伙伴”的买方——说明需求比报告判断的更急，可以提前启动 B。
  • 一个非作者真人在 30 分钟内过干净臂——说明 Gate 1 提前达成，可以缩短 Phase 1。
  • 一家设计伙伴愿意为试点付 ≥3k 美元——说明付费意愿成立，可以提前做私有化包。

反过来，如果 10 次访谈里连 3 个真实触发都没有，或者第 60 天仍无干净臂，那么结论不是“再努力销售”， 而是“市场对象或切口错了”；应该回到第 1 章重选对象，而不是加功能。

一句话

先让它被外部复核，再让它被市场购买。 本报告的最终建议 · 2026-10-19

这不是一个“市场很大、赶紧融资”的故事，也不是一个“技术很强、只是没人懂”的故事。 它是一个“证据已经有一半、市场入口很窄、需要用零成本方式换外部证据”的故事。 对这颗内核来说，最贵的不是开发，也不是获客，而是在证据没齐的时候被当成“可信产品”卖出去。 避免这件事，就是本报告的全部目的。

结论基于 2026-10-19 前的内部证据与外部资料；所有情景、价格、闸门均为可修改的设计，不是承诺。外部数据访问日 2026-10-19。

E.4 FAQ

Q1：和 Langfuse/Datadog 有什么区别？
A：它们记录“发生了什么”，我们判断“这句话能不能收、哪一格拦的”。可以两个都用，用 trace ID 关联。

Q2：为什么要 49 格，字段太多？
A：49 格不是字段堆，而是把一句人话拆成可反驳的几件事：谁说的、怎么知道的、量到了没有、出处是什么。字段多是为了让“说不清”有地方暴露。

Q3：哈希链能证明内容是真的吗？
A：不能。它只能证明记录没被改过；内容真假要靠出处与对质物。没有签名时，它也不是不可伪造。

Q4：为什么现在不卖？
A：因为“可复核”必须由外部调用方证明。真人干净臂、拒收归因 8/8、交付凭据对齐，这三件没过之前，卖它是不负责任的。

Q5：什么时候能买？
A：Gate 1–3 过后开放私有化许可；现在可以申请设计伙伴或干净臂，不收费。
