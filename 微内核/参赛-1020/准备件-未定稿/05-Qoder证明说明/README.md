## 2. 为什么不能拿别的东西顶

- 不贴其他工具（Claude / Copilot / Cursor 等）的截图冒充 Qoder：这是伪造，直接毁掉参赛资格与全部证据的可信度。
- 不把“本会话是 Qoder”写成“已提交 Qoder 证明”：过程事实 ≠ 可验收材料。
- 不写“Qoder 生成了 X% / Y 行”这类没有分母的数字：没有逐条对应，就不可复核。
- 不删 AI 生成标识（C9）；不把 AI 生成图冒充屏幕实拍。

## 3. 若 C1 确认“必须华为云码道”

Qoder 不能替代码道。此时 `codearts_proof/` 是硬缺口，应停在报名前，不提交；不要把 Qoder 材料改名塞进 `codearts_proof/` 充数。

## 4. 若后续要补（本人操作，不由本件代做）

一条可验收的记录至少包含：

```
时间：
工具：Qoder
Prompt（原文，可脱敏）：
产出：改了哪个文件 / 生成了哪段（对应 project/ 里的真实文件）
验证：跑了哪条命令、退出码、关键读数
截图：含上述内容，账号 / 路径 / token 已打码
脱敏检查：无姓名、学校、学号、手机号、密钥、客户数据
```

三类各至少 1 条：

1. **交互与 Prompt**：一条真实需求 → Qoder 回话 → 采纳/拒绝的理由。
2. **代码生成 / 重构**：一条改动 → 对应文件 → 验证命令与读数。
3. **排错**：一个失败 → 定位过程 → 修复 → 复跑读数（含“修之前红、修之后绿”）。

## 5. 红线

- 不伪造、不挪用、不补拍“看起来像”的截图。
- 不把会话记录原样交出去（含工作区路径、可能的个人信息）。
- 不在没有对应文件与验证命令的情况下写“Qoder 生成”。
- 提交前逐条对照：每条记录都能指到 `project/` 里的真实文件与一条可复跑的命令。

- 若 C1 适用且允许 Qoder：这是硬缺口，必须先补真实材料，否则不提交。
- 若 C1 适用且强制码道：不提交。
