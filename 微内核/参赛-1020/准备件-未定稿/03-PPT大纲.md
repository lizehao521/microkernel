## 第 2 页 · 问题：AI 说“我改了”，证据在哪

**屏幕文字**

```
三类事后问题，今天都答不实：
1. 模型输入被平台改过吗？改了几段、裁了多少字节？
2. 输出里的每个数字，是测量、估算，还是根本没有？
3. 出了纠纷，日志在谁手里？有没有被改过？

现状：日志有，但“谁算的、能不能重算、有没有被改”三件事通常分开存。
```

**口播（25 秒）**

> “不是没有日志，而是日志回答不了三个问题：每一格是谁算的、第三方能不能重算、有没有被改过。这三个问题不解决，‘AI 改了’就只是一句承诺。”

**证据**：`作品提交规范.md` §0 的定位段；`docs/README.md` 第一屏。

## 第 3 页 · 现有做法与边界

**屏幕文字**

```
护栏 / 网关：拦请求、改输入 —— 解决“能不能做”，不解决“事后怎么核”
可观测 / 日志：记录多，但通常不逐格给“测量/估算/缺席”，也不保证可重算
本件：只做“记账 + 复核”，不拦、不改、不产训练数据

一句话：审计层 ≠ 防线。
```

**口播（25 秒）**

> “护栏解决‘能不能做’，我们解决‘做完怎么核’。所以我们不宣称挡住攻击，也不把‘没拦’说成‘拦住了’。这条边界写在第一屏。”

**证据**：`docs/product-positioning.md`；`作品提交规范.md` §1.5 的授权范围。

## 第 4 页 · 方案：一条哈希链，三种状态

**屏幕文字**

```
采集：调用前后的元数据（输入/输出两侧，49 格）
落账：每格一条记录，<kind>:<key>，前一条的 hash 进后一条
复核：第三方只拿账本字节，逐条重算链与整格指纹

每格必带三态之一：
  measured  测量
  estimated 估算（必须带来源与“这是估算”）
  absent    缺席（必须带理由，不写 0）
```

**口播（30 秒）**

> “核心不是‘记了很多’，而是**每一格都有状态**：测量的就是测量，估算的必须自报估算，缺席的必须写理由。我们没有把‘没量到’写成 0——这是这个件最硬的规矩。”

**证据**：`docs/contract.md` §2.5；`证据/verify-100.json`；`证据/readback-20cell.json`。

## 第 8 页 · 创新点：把“证据等级”做成可执行件

**屏幕文字**

```
1. 三态不塌：measured / estimated / absent；缺席不写 0
2. 估算自报：estimated 必须带 source，“这是估算，不是测量”
```

## 第 10 页 · 落地规划：两周试点，先量三件事

**屏幕文字**

```
试点对象：1 个真实调用方（1 个模型接口，1 类调用）
周期：2 周；不改对方代码，只接账本落盘与复核

验收（先定分母）：
  A. 账本可复核率 = 能重算原像的条目 / 总条目
  B. 篡改检出 = 人为改 N 条，点名条数 / N（目标 N/N）
  C. 接入成本 = 对方从拿到包到跑通 verify 的分钟数

不做：不承诺拦截率；不接生产写路径；不收集客户原文
```

**口播（30 秒）**
