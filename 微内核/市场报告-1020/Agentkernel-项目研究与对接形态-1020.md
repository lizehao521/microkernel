# Agentkernel 项目研究报告

## 可复核的二次修改证据包：现状、证据与对客对接形态

- **日期**：2026-10-20
- **版本**：v1.0
- **性质**：研究 / 决策件；不是报价单、投资建议、合规意见或交付承诺
- **范围**：只基于本地已有研究件与实测读数；本轮不新增客户访谈、不调用模型、不写入真流量账本
- **证据口径**：A（工具自印 + 独立复算）/ B（单源自印）/ C（作者复算 / 规划假设）/ D（外部公开）/ X（未验证，`NOT_RUN`，不塌成 0）

---

## 摘要

> 现在能卖的不是“更可信的 Agent”，也不是“记账平台”，而是**一次真实修改的可复核证据包**；对客形态应是**陪跑式证据包服务 + 薄适配层**，而不是自助 SaaS。

### 五条研究发现

1. **技术底座是真的，但只证明了一件事。** 2,940 条记录的链可按同一规则重算通过（2,940 / 2,940，A）；但账本没有产物原像字段（0 / 2,940）、没有版本三元组（0 / 3），本次导出也没有拒收计数（不可得）。因此可以说“记录未被改、顺序自洽、断点可定位”，不能说“内容为真、修好有效、审计通过”。
2. **产品已经改判。** 从“卖可验证记账内核 / 账本”改为“卖可复核的二次修改证据包”；产品级评估的结论是**条件 GO——只批准一个 6 周付费试点，不批准平台化**。
3. **真正稀缺的不是代码。** 产物原像的 custody、版本三元组的现场对齐、非作者复核人的 60 分钟，这三样都不在软件里，在服务流程里。所以顺序必须是“先服务、后软件；先一次可复核交付、后年费”。
4. **对客形态应是服务，不是软件产品。** 客户可见面只保留五件：一页决策卡、受理单（S1）、复核工作台（S3）、POC 报告（S5）、只读状态板（S0）；组包（S2）与拒收账（S4）留在交付方内部。不做自助 SaaS、不做托管按次、不做运行时网关、不卖认证。
5. **当前外部读数全为 `NOT_RUN`。** G0 访谈 0 / 10、真实修改 0、非作者复核 0、R/N 0 / 10、LOI 0 / 2、付费 0。因此“对客形态”目前是设计与判断（C），不是客户验证过的结论；下一步的验证不是继续改页面，而是 G0 与一次非作者试读。

### 三条建议

1. **先卖一次交付，不卖平台。** 6 周、一个真实修改、一个 8 段包、一次非作者 60 分钟复核、一份报告；软件只做内部工作台。
2. **对客首触点用一页决策卡，不用 48 页重评。** 重评是研究件；决策卡是对客件。首次通话只确认三件事：真实修改、非作者复核人、数据条款。
3. **在 G0 前不扩软件。** 当前 P0 工具包已够跑一次试点；新增多租户、账号、计费、自助注册，都是把未验证的流程放大。

### 三句当前不能说的话

- 不能说“验证通过 / POC 达标 / 客户已验证”——真人复核与客户试点均 `NOT_RUN`。
- 不能说“链自洽 = 内容可信 / 未被换账”——`load_journal` 可整本替换，`APPEND_ONLY` 默认关闭。
- 不能说“符合 EU AI Act / 覆盖 MCP01、03、06”——只提供技术证据，只对应 MCP08（审计与日志）。

## 2. 项目现状：有什么、缺什么

### 2.1 可复算的资产

本轮可独立复算的读数集中在“记录完整性”和“样本可复核性”，不在“内容真实性”。

| 项 | 读数 | 等级 | 说明 |
| --- | --- | --- | --- |
| 账本文件 | 1,483,862 字节；1 行人读表头 + 2,940 条记录 | A | SHA-256 `fb1fa5ef7a9347769eede05d48b06a3e712861cc1e979076cdf18f922543d220` |
| 记录 | 2,940 条；seq 1–2,940；每条 11 个字段 | A | 60 发 × 49 格 = 2,940 |
| 会话 / actor | 12 个会话；4 个自报 actor | A | actor 是自报字符串，无第二根轴反证 |
| 格 | 49 种 kind；48 键 / 49 格 | A | v1 已封板结构 |
| 链 | 2,940 / 2,940 通过 | A | 按 `Seq\nSession\nActor\nStep\nKind\nClaim\nBasis.String()\nSource\nAt\nPayloadH\nPrevHash` 逐条重算 |
| 出处分布 | measured 2,213 / relayed 188 / estimated 124 / model_says 60 / absent 355 | A | 相加 = 2,940；absent 是记账缺席，不是 0 |
| 样本切片 | seq 491–539，49 / 49；锚点 seq 490 | A | 切片 seal / prev / payload 可复算 |
| 受控前缀 | 539 / 539 | A | 不含真流量；与完整账本的 custodian 绑定仍待确认 |
| 非作者试读包 | 14 个文件 + 包内清单；86,049 B；SHA-256 `40572043…` | A（打包/解压实测） | 样本包，不是客户证据包 |
| 决策卡 | 1 页 A4；机械测评 10 / 10 PASS；反臂 6 PASS / 3 FAIL / 1 NOT_RUN | A（机械） | 真人可用性 `NOT_RUN` |
| CycloneDX 草案 | 16 组件 / 8 条运行时依赖边；7 个文件哈希与实体一致；自检 17 / 17；反臂 4 / 4 | A（自检/反臂） | schema 校验 `NOT_RUN`；不是完整 SBOM |

**能说**：记录未被改、顺序自洽、断点可定位；2,940 条链可被第三方按同一规则重算；样本切片与受控前缀可独立复算。
**不能说**：内容为真、行为正确、修好有效、审计通过。

### 2.2 关键缺口

| 缺口 | 当前读数 | 状态 | 为什么重要 |
| --- | --- | --- | --- |
| 产物原像 | 0 / 2,940 条账带产物路径 / 哈希 / 版本字段 | X | 没有原像，证据包退化为“账本切片” |
| 版本三元组 | 0 / 3 | X | 答不出“改的是哪一版” |
| 拒收计数（本次导出） | 不可得 | X | 导出发生在计数栏落地之前；无 gate 行 |
| 真实客户修改 | 0 | `NOT_RUN` | 没有样本，试点无法开始 |
| 非作者真人复核 | 0 人 / 0 次 | `NOT_RUN` | 60 分钟承诺未验证 |
| R/N 双臂 | 0 / 10 | `NOT_RUN` | 增量与假修复率均未测 |
| G0 访谈 | 0 / 10 | `NOT_RUN` | 需求真实性未验证 |
| LOI / 付费 | 0 封 / 0 个 | `NOT_RUN` | 商业闭环未验证 |
| 安全审查 / DPA | 0 / 1；0 / 1 | `NOT_RUN` | 企业采购与数据条款未成立 |
| 完整 SBOM | 0 / 1 | X | 草案有结构自检，但 schema 校验、漏洞扫描、部署 OS/DLL 未完成 |
| 真人可用性 | 0 人 | `NOT_RUN` | AI 模拟读者 29 / 30 不是真人通过率 |

**读法**：`0 / 2,940` 不是“2,940 条都错”，而是“账本结构里没有这个字段”。`absent 355` 也不是 0，是记账缺席。两者都不能被写成“全绿”或“全错”。

### 2.3 8 段证据包的桌面推演

拿现有账本按 8 段证据包逐段检查，不冒充真实试点：

| # | 证据包段落 | 推演结果 | 状态 |
| --- | --- | --- | --- |
| 1 | 范围与非声明 | 可按模板起草 | 可起草（C） |
| 2 | 修改记录（改前 / 改后 + 哈希） | 无产物，无法填 | 缺（X） |
| 3 | 版本三元组 | 三格全空 | 缺（X） |
| 4 | 账本切片 + 链验证 | 2,940 / 2,940 通过 | 有（A） |
| 5 | 拒收账 | 导出无 gate 行，R1–R7 无计数 | 缺（X） |
| 6 | 非作者复核记录 | 未跑 | `NOT_RUN` |
| 7 | R/N 记录 | 未跑 | `NOT_RUN` |
| 8 | custody / 留存 / 删除回执 | 试点函有条款，未签署 | 草案（C） |

**结论**：8 段里只有 1 段有 A 级证据，2 段可起草，5 段缺失或未跑。这不是失败，而是产品设计的真实起点——**Pack Builder 必须把“缺原像 / 缺版本 / 缺拒收”做成硬门，而不是黄色警告**。

### 2.4 技术底座的边界

| 能证明 | 不能证明 |
| --- | --- |
| 记录未被改、顺序自洽、断点可定位 | 记录内容为真、行为正确、修好有效 |
| 第三方可按同一规则重算链 | 账本未被整本替换（`load_journal` 可替换） |
| 切片与账本一致 | 切片来自原账本（custodian 绑定仍待） |
| 样本前缀可独立复算 | 前缀就是完整账本 |
| 工具自检与反臂可重复 | 工具自检通过 = 产品/证据包合规 |

其中两条最贵的限制必须写进对客材料：

- **`read_back` 不返回指纹**，`declare_reader` 仅内存，`load_journal` 可整本替换，`APPEND_ONLY` 默认关闭。因此“链自洽”不等于“未被换账”。
- **`payload_b64` 是每格值的原像，不是产物原文**。账本不能替代改前 / 改后产物。

## 3. 产品定义与角色

### 3.1 一句话产品

> 客户给一次真实的 Agent 行为修改（改前 / 改后产物 + 一次失败复盘），我们在 6 周内交付一个**另一个人能在 60 分钟内复核、拒收或定位断点**的证据包。

### 3.2 五类角色

| 角色 | 在交易中的位置 | 要完成的事 | 成功标准 | 失败 / 不买 |
| --- | --- | --- | --- | --- |
| **AI 平台负责人** | 买家 / 发起人 | 回答“这次改动为什么发生、改的是哪一版、是否真的更好” | 拿到可复核包，内部复盘能结论 | 现有 trace 够用；不想再加供应商 |
| **安全工程负责人** | 买家 / 共同发起 | 事后取证：当时看到什么、用了哪版策略、谁批准 | 能定位断点、能保全证据 | 认为审计层不是防线，不愿单独付费 |
| **合规 / 风险负责人** | 预算 / 否决人 | 留可审计证据，不负责认证 | 证据包范围清楚、留存删除可交代 | 要认证不要工具；治理平台已买 |
| **非作者复核人** | 客户指派 / 服务必经 | 60 分钟内按清单复算链、定位断点、通过或拒收 | 独立得出“通过 / 拒收 / 超时”，作者不参与判定 | 没时间、没资格、与作者同一人 |
| **证据工程师（我方）** | 交付方 | 组包、补齐原像与版本、维护拒收账、跑 R/N、写报告 | 包完整、可复核、无过度声明 | 客户不交原像 / 不指定复核人 |

### 3.3 买家 ≠ 用户 ≠ 复核人

- **买家**关心“能不能交差 / 能不能归因”；
- **用户**关心“操作麻不麻烦”；
- **复核人**关心“我能不能在 60 分钟内独立判断”。

三者不是一个人。产品设计不能只优化买家首屏，必须为复核人设计一张**可执行的 60 分钟工作台**。这也是“一个客户门户”必然失败的原因：它会把三种不同的任务压成同一个界面。

### 3.4 需求成立的最低条件

| 触发 | 场景 | 证据等级 | 当前状态 |
| --- | --- | --- | --- |
| 事故复盘 | Agent 执行错误操作，要回答“看到什么、哪版策略、谁批准、改了什么” | D（外部共性）+ C（本项目推演） | 无客户事故样本；`NOT_RUN` |
| 受监管审计 | EU AI Act 第 12 条记录义务、第 26(6) 条日志保存 | D（法条公开） | 无受监管客户访谈；`NOT_RUN` |
| 行为变更与回归 | 改 prompt / 路由 / 阈值后，要知道新版是否更好、为什么改 | B（本机 60 发 / 2,940 条记录）+ C（无客户案例） | 有本机记录，无客户真实修改样本；`NOT_RUN` |

**合格线索的最低条件**：客户能拿出一次真实修改，且这次修改已经造成或可能造成回归 / 审计追问；同时能指派一名非作者。拿不出，就没有证据包需求。

### 3.5 五条反需求，以及对界面的含义

| 反需求 | 为什么会让需求消失 | 对产品 / 对接的含义 |
| --- | --- | --- |
| 失败率很低 | 没有二次修改，就没有证据需求 | 只接高变更、高监管、高事故成本场景 |
| 现有日志“够用” | 买家分不清 trace 与证据包 | 用一次真实复盘演示“缺的是原像 / 版本 / 拒收”，不要堆功能 |
| 隐私与留存顾虑 | 不愿把 prompt / 工具输出交给第三方 | 本地 / 私有化交付；30 天留存、5 天删除、无子处理方 |
| 不想再加供应商 | 采购周期长，平台已绑定 | 做适配层 / 插件，不做替代平台 |
| 平台捆绑 | LangSmith / Langfuse / Datadog 把证据功能打包 | 守“可验证 + 可回滚 + 可披露”的深水区，不拼看板 |

**结论**：这不是广谱需求。对客材料的第一句话不应该是“我们有账本 / 哈希链”，而应该是“你能不能拿出改前产物、指派一名非作者、接受数据条款”。

## 4. 市场与替代方案：为什么是功能市场

### 4.1 市场判断

- 重评判定为**功能市场，不是平台市场**；SAM 1.0–2.0 亿美元、SOM 0.5–4.0 百万美元，均为 C 级假设（`README.md` §相对 v1 的关键变化）。
- 定价同为 C 级假设：试点 3–5 千美元 / 6 周；团队版 1.5–3.0 万美元 / 年；证据包版 4–8 万美元 / 年；社区版免费。
- 窗口：MCP 已被采用，但遥测侧仍在演化；OTel GenAI semconv 未稳定；平台把“可观测”做得很深，但“可复核的修改证据”还没有标准件（D + C）。
- 合规需求真实存在，但预算常挂在治理 / 可观测科目下（C）。

### 4.2 替代方案

| 替代 | 客户为什么可能选它 | 它答不了什么 | 我们的相对位置 |
| --- | --- | --- | --- |
| 什么都不做 | 便宜、无采购 | 下次事故仍然无法归因 | 只在事故 / 审计后才有窗口 |
| 在现有 trace 上加日志 | 复用平台、无新供应商 | 改的是哪一版、产物原像、拒收计数、非作者复核 | 我们消费 trace，不替代 trace |
| Eval 平台 | 有数据集、有基线 | 证据链、custody、可披露包 | 我们接在 eval 之后 |
| AI 治理平台 | 合规框架、流程 | 具体一次修改的可复核证据 | 我们做技术证据，不做治理套件 |
| 内部人工复盘 | 灵活、信任内部 | 跨版本可复算、拒收语料、R/N 对照 | 我们把人工复盘变成可复核件 |
| 请咨询顾问 | 有报告、有背书 | 证据包本身、复核记录、可回滚 | 我们交付可复核物，不是观点 |

### 4.3 可防守差异

不是哈希链，不是 49 格，而是**证据包规范 + 拒收计数 + 版本三元组 + R/N 协议**。链很容易被复制；拒收语料与复核记录需要时间积累。

壁垒的本质是**跨客户积累的拒收语料 + 复核记录 + R/N 基线**。这三样只有在真实试点里才长出来，不能靠写代码提前造出来。

### 4.4 最贵的两条风险

| 风险 | 触发信号 | 影响 | 对界面 / 对接的含义 |
| --- | --- | --- | --- |
| 拿不到产物原像 | 客户只能给日志，给不出文件 / 配置 / 提示词 | 证据包降级为“账本切片” | 受理即硬门；无原像不封包 |
| 账本可被整本替换 | `load_journal` 默认允许替换；`APPEND_ONLY` 默认关闭 | “链自洽”被误读为“未被换账” | 试点强制 `APPEND_ONLY=1` + `REQUIRE_TOKEN=1`，并在包内记录部署姿态 |

其余风险（复核人不可用、拒收标准争议、隐私拒绝、被当防线、平台捆绑、两本账、过度声明）已在 `产品设计-1020/产品级-二次评估.md` §11 登记，本文不重复展开。

## 5. 对客对接形态分析

### 5.1 先区分三个问题

“以什么形式对接用户”至少包含三层，不能混在一起：

1. **商业形态**：卖服务、卖软件、卖许可，还是卖咨询？
2. **交付界面**：谁看什么、在什么时间盒里看、看到什么证据？
3. **获客节奏**：从哪一句话开始、何时收钱、什么情况下停止？

### 5.2 七种形态比较

下表是作者判断（C），不是客户读数；客户验证仍是 `NOT_RUN`。

| 形态 | 适配度 | 客户得到什么 | 主要限制 | 结论 |
| --- | --- | --- | --- | --- |
| 自助 SaaS | 低 | 账号 + 仪表盘 + 自助组包 | 原像 / 版本 / 复核人依客户现场而定，无法标准化到零服务；隐私与多租户未建 | 不做 |
| 托管按次 | 低 | 上传数据、按次出报告 | 隐私与留存是硬阻力；重评已判定不做 | 不做 |
| 开源库 + 规范 | 中 | 代码、规范、反例 | 客户仍要自己补原像、版本、拒收、验证器；无交付收入 | 后期社区版，不做主形态 |
| **陪跑式证据包服务 + 薄适配层** | **高** | 6 周、一个真实修改、一个 8 段包、一次非作者复核、一份报告 | 服务重、依赖客户材料与复核人；工时未测 | **首选** |
| 企业私有化（B） | 条件 | 本地部署 + 适配层 | 成本高、当前无部署件；只在 G1.5 + G2 后启动 | 后期，不现在卖 |
| 审计 / 咨询 | 部分 | 报告、意见、背书 | 卖观点不是可复核物；与“证据包”定位冲突 | 不做主形态 |
| 运行时网关 / 拦截 | 否 | 实时拦截、策略执行 | 审计层不是防线；会招来“挡住攻击了吗”的错误预期 | 不做 |

### 5.3 为什么首选“陪跑式证据包服务 + 薄适配层”

**第一，三样稀缺资源都在服务侧。**

- 产物原像的 custody：客户环境里谁来保管、怎么证明新鲜、谁能签；
- 版本三元组的现场对齐：产物版、行为版、判据版分别从哪个系统取；
- 非作者复核人的 60 分钟：谁有资格、是否独立、能不能约到。

这三样不在代码里。把它们做成 SaaS 的自助表单，只会把失败推迟到客户现场。

**第二，三层顺序不能反。**

```
服务层（人）  受理 · 组包 · 预演 · 正式复核 · R/N · 报告
证据层（规范）8 段证据包 · 版本三元组 · R1–R7 · A1–A6
工具层（软件）Intake · Builder · Reviewer · Ledger · Report
```

先有人跑通服务，再有工具提效；首版工具是内部工作台，不是客户自助产品（`产品设计-1020/产品设计蓝图.md` §2.1）。

**第三，软件是交付工具，不是售卖标的。**

客户买的不是账号，而是“这次修改的证据是否成立”的结论。软件只负责减少哈希、链验证、清单、计时、报告的人工错误；它不承担“让客户自己会用”的责任。

**第四，按包 / 按试点收费，比按 seat / span / token 更贴合价值。**

试点 3–5 千美元 / 6 周，对应一个真实修改、一个包、一次复核；团队版与证据包版是后话。定价是 C 级假设，第一单必须记录实际工时，作为第二单报价的分母。

**第五，本地 / 私有化交付是信任的一部分。**

数据条款写死：本地只读旁挂、30 天留存、5 天删除、无子处理方、密钥只走环境变量、不经第三方 SaaS。对客形态必须与这些条款一致；托管按次天然冲突。

### 5.4 为什么不做自助 SaaS

| 问题 | 具体原因 |
| --- | --- |
| 零服务不可能 | 原像、版本、复核人都依客户现场而定；没有证据工程师，客户填不出一份可封包的受理单 |
| 隐私与留存 | 客户不愿把 prompt / 工具输出交给第三方；托管多租户会放大顾虑 |
| 多租户未建 | 当前没有账号、计费、权限、隔离；这些不是本轮范围 |
| 会把证据变成状态 | 仪表盘容易显示“绿 / 红”“信任分”；但状态不是质量分，A1 通过不代表 A2–A6 通过 |
| 会放大未验证流程 | G0 0 / 10、非作者复核 0；自助会让不合格线索直接产出无效包，制造过度声明 |
| 商业上不匹配 | 这是窄而深的取证 / 审计型服务，不是广谱 PLG 工具 |

**如果以后要做软件，先做只读门户**：让已有客户看自己的包状态（S0）和报告（S5），不做自助组包、不做自助受理、不做计费。只读门户是提效，不是获客。

### 5.5 为什么现在不做开源主形态

开源适合做**分发与反例**，不适合做**交付**：

- 客户拿到适配层 / 规范，仍然要自己补原像、版本、拒收、验证器；最难的三样没有被解决；
- 没有证据工程师，8 段包仍然组不起来；
- 开源可以换使用与反例，但换不到“非作者复核记录”和“拒收语料”；
- 拒收语料、复核记录、客户数据不能开源。

**后期可做的社区版**：开源适配层 + 规范 + 验证器；保留拒收语料、复核网络、R/N 基线作为付费服务。社区版是漏斗，不是主产品。

### 5.6 为什么不做运行时网关

- 本产品只对应审计与日志（MCP08），不拦截、不调度、不联网、不执行工具；
- 一旦做成网关，客户会问“能不能挡住攻击 / 注入 / 工具滥用”，预期立刻错位；
- 审计层不是防线；这是首屏、报告、合同三处都要写的非声明；
- 不接运行时，也是信任来源：不改客户代码、不调模型、不引入新的故障点。

### 5.7 角色 × 界面矩阵

| 角色 | 首触点 | 交付中 / 交付后 | 不该看到 |
| --- | --- | --- | --- |
| AI 平台负责人 | 一页决策卡 + 15 分钟资格通话 | S1 受理单共同填写；S0 只看自己的包；S5 报告 | 其他客户的包；内部拒收语料原文 |
| 安全工程负责人 | 决策卡 + 证据清单 | S1 原像 / custody；链验证报告；断点；删除回执 | 作者的口头解释；未脱敏的第三方数据 |
| 合规 / 风险负责人 | 决策卡 + 试点函 / DPA 草案 | S1 范围与非声明；留存 / 删除条款；S5 报告 | “认证 / 合规通过”字样；无分母的百分比 |
| 非作者复核人 | 包 + 复核工作台（S3） | 60 分钟清单、计时、断点、三态决定 | 作者在场解释；AI 代读；包外材料 |
| 证据工程师（我方） | 内部运行手册 | S1 / S2 / S4 / S5 全流程 | —（在 custody 范围内） |
| 买家法务 | 试点函 / DPA | 责任边界、数据条款、删除回执 | 技术原始数据（除非单独授权） |

### 5.8 客户可见的五件，和内部的两件

**客户可见**：

1. **一页决策卡**：首触点；讲清“拍板哪三件事”，不是产品功能巡演。
2. **受理单（S1）**：把样本、原像、版本、复核人、条款一次问清；缺件逐项点名。
3. **复核工作台（S3）**：核心信任界面；60 分钟、清单、计时、断点、三态决定。
4. **POC 报告（S5）**：A1–A6 逐项 A/B/C/D/X；明确“证明了什么 / 没证明什么”。
5. **只读状态板（S0）**：客户只看自己的包；X 项显示 `NOT_RUN`，不显示空白或 0。

**内部**：

- **Pack Builder（S2）**：组包、链验证、版本对齐、缺口清单；客户不需要自己操作。
- **Rejection Ledger（S4）**：R1–R7 计数、分母、样例；买家只读汇总，不看原始语料。

**不要给客户看的**：运行时拦截面板、信任分 / 绿灯、其他客户的包、原始拒收语料、没有分母的百分比、任何“认证 / 零风险”徽标。

### 5.9 60 分钟复核工作台：最具体的一张对客界面

复核清单第 1–6 步（源文件称 S1–S6，注意与产品界面 S0–S5 区分）：

| 步骤 | 内容 | 预算 |
| --- | --- | --- |
| 1 | 范围与非声明：包 ID / 客户 / 触发能对上；“证明什么 / 不证明什么”能复述 | 5 分钟 |
| 2 | 修改记录与原像：路径、SHA-256、custodian、时间戳；抽样复算 1 个产物 | 12 分钟 |
| 3 | 版本三元组：产物版 / 行为版 / 判据版 + 来源；行为版覆盖修改时点；判据版修改前冻结 | 8 分钟 |
| 4 | 账本切片：文件 SHA、记录数、seal / prev、锚点、受控前缀、absent 理由 | 15 分钟 |
| 5 | 拒收账与 R/N：R1–R7 计数 + 分母 + 样例；样本 <10 写 `NOT_RUN` | 10 分钟 |
| 6 | 复核记录与条款：独立性声明、用时、custody / 留存 / 删除、密钥扫描、报告只引用包内证据 | 10 分钟 |
| **合计** | — | **60 分钟** |

纪律：

- 作者不在场、不口头补充；任何“我来说明一下”都记为干预。
- 60 分钟到点即停，未完成即 `超时`（R6），不延长。
- 决定只有三态：通过 / 拒收 / 超时；“基本没问题”“差不多”不算决定。
- 拒收必须带 R 码与断点；通过也必须写“本次未覆盖什么”。
- 复核人不使用 AI 代读或代填；AI 记录不计入真人试读。

### 5.10 对客节奏：四段漏斗

| 阶段 | 对象 | 交付物 | 证据产出 | 退出条件 | 当前 |
| --- | --- | --- | --- | --- | --- |
| 0 资格 | 三类买家 | 一页决策卡 + 15 分钟通话 | 资格记录 | 真实修改 + 非作者 + 数据条款，缺一不进受理 | 访谈 0 / 10 |
| 1 非作者试读 | 外部非作者 | 样本 zip + 60 分钟工作台 | 试读记录（不是客户证据） | 能说出“缺哪几段、为什么不能封包” | 0 / 1 |
| 2 付费试点 | 有真实修改的团队 | 6 周、一个 8 段包、一次正式复核、报告 | 受理记录、包、复核记录、拒收账、R/N（样本足时） | G1 / G1.5 | 0 |
| 3 年费 / 私有化 | 已过 G1.5 + G2 的客户 | 多包、拒收语料、审计披露支持、私有部署 | 续费 / 转正 | G2 / G3 | 0 |

**不要跳过第 1 段。** 样本试读验证的是“包能不能被读懂”，不是“客户的系统好不好”；它不能计入真实复核，也不能当作客户证据。

**第 0 段不是免费咨询。** 15 分钟只做资格判断；没有真实修改、没有非作者、不接受条款，就停止，不做免费审计。

**第 2 段的钱怎么收。** 沿用试点函 v0.1：30% 启动 / 40% 交付证据包 / 30% 非作者复核通过；判定由客户指定的非作者按 A1–A5 做，作者不参与；争议按未达成处理，尾款不付。

### 5.11 渠道与材料

| 渠道 / 材料 | 用法 | 现在能不能用 | 边界 |
| --- | --- | --- | --- |
| 一页决策卡（HTML / PDF） | 首触点、留档、会后转发 | 可以（机械 10 / 10；真人 `NOT_RUN`） | HTML 为主件；PDF 中文文本层不可提取，只作打印 |
| 试点函 v0.1 | 说明 6 周、A1–A6、R1–R7、数据条款 | 草案，未签署 | 不是合同；需双方法务 / 安全确认 |
| P1 客户数据请求单（M1–M7） | 受理前收集最小材料 | 草稿，0 发送 | 不收集密钥 / 完整代码 / 个人信息原文 |
| 样本试读包 | 60 分钟非作者试读 | 已构建，0 / 1 | 是样本，不是客户证据；不含完整账本 / 真流量 |
| 首客户 Pitch | 对客叙事草稿 | 未对任何客户使用 | 所有“客户会……”都是假设 |
| G2 材料（LOI / SBOM / DPA） | 企业采购 | 草案，0 / 2 等 | 不是完整 SBOM、不是 DPA、不是安全审查 |

**渠道选择**：

- **直接、具名、温引荐**：对 AI 平台负责人、安全工程负责人、合规 / 风险负责人；不做大众广告、不做自助注册、不做 PLG。
- **先给判断，再给产品**：首次通话只问“最近一次改了什么、改前改后还在吗、谁能独立复核”，不展示哈希链。
- **本地 / 客户批准通道**：包、原像、账本切片不经第三方 SaaS；不上传公开链接 / 网盘外链。
- **远程复核会**：60 分钟、作者不在场、录制需书面同意；会后只发记录与报告。
- **社区版**：后期做适配层 / 规范 / 验证器的开源；不做客户数据、拒收语料、复核记录的开源。

**不要用的渠道 / 话术**：

- 不要把 48 页重评当销售 deck；它是研究件，含 C 级假设与内部风险登记。
- 不要把样本试读包当“客户案例”发给买家；它是内部样本。
- 不要让 AI 代替非作者复核；AI 记录不计入真人通过率。
- 不要承诺“认证 / 防线 / 零风险 / 保证不出事”；这些不是本产品。
- 不要在没有分母的情况下写百分比；0 例也要写 `0 / N`。

### 5.12 什么会改变这个形态判断

| 事件 | 形态判断怎么变 |
| --- | --- |
| G0 发现多数买家说“trace / eval 已经够用” | 需求不成立，转研究 / 开源规范，不做付费服务 |
| 客户普遍拿不出改前 / 改后产物 | 降级为“账本审计服务”，不卖证据包 |
| 非作者 60 分钟两轮都做不完 | 不承诺 60 分钟；重做清单，或改产品形态 |
| R/N 无增量（G1.5 不过） | 冻结商业化，保留研究资产 C |
| 平台免费捆绑证据包 | 转研究出版 / 开源适配层，不拼平台 |
| 隐私条款不允许任何外部服务 | 只做本地 / 私有化或开源，不做托管 |
| 买家只想要认证 | 不是目标客户，放弃 |
| 样本试读被误读为客户证据 | 立即隔离材料与话术；样本包只用于流程试读 |

### 6.2 先做 / 后做 / 不做

**先做（服务关键，本地零成本）**：

1. Intake Sheet（S1）可打印 / 可填写；
2. Reviewer Console（S3）计时 + 清单 + 断点 + 三态决定；
3. Rejection Ledger（S4）R1–R7 + 分母；
4. Pack Builder 的脚本版（S2）：哈希、链验证、缺口清单；
5. POC Report 模板（S5）。

**后做（提效）**：

- S0 状态板自动化；
- 原像 custodian 同步；
- 多包对比；
- 证据包导出 HTML / PDF；
- 与客户 trace / eval 的只读连接。

**不做（本阶段）**：

- 多租户、账号体系、计费；
- 运行时拦截 / 网关；
- 模型调用 / 自动改代码；
- 自助注册 / 自助组包；
- 认证 / 合规结论；
- 移动端。

### 6.3 停止规则

1. 第 5 天仍无真实修改 → 停止，退回线索池。
2. 第 5 天仍无具名非作者复核人 → 停止，不进入组包。
3. 第 10 天仍无原像 → 降级为“账本审计”，不卖证据包。
4. 链断且不可定位 → 停止，出断点报告。
5. 预演两轮 >60 分钟 → 改清单；仍超 → 对外不承诺 60 分钟。
6. 复核人利益冲突 → 更换；无替代 → 延期或停止。
7. 数据条款未签 → 不传输任何客户数据。
8. R/N 样本 <10 → 只写 `NOT_RUN`，不写“有提升”。
9. G1.5 连续两次不过 → 冻结为研究资产 C。
10. 客户要求“认证 / 防线 / 零风险” → 不接，改范围或退出。
11. 发现过度声明 → 立即更正，报告与对外材料同步。

### 6.4 需要拍板的事

#### Ask 1 · 是否批准对客形态为“陪跑式证据包服务 + 薄适配层”，不批准自助 SaaS / 平台化？

- **为什么需要决定**：这决定接下来做服务件还是做软件平台；两条路的投入与验证方式不同。
- **决定时间**：现在。
- **不决定的影响**：工具层会继续膨胀，但 G0 仍未验证；容易把未验证流程做成产品。

#### Ask 2 · 是否批准在 G0 前不扩软件，只收口现有材料？

- **为什么需要决定**：当前 P0 工具包已够跑一次试点；新增多租户 / 账号 / 计费会把资源从 G0 抽走。
- **决定时间**：现在。
- **不决定的影响**：30 天内可能继续做“看起来完整”的平台，但 0 客户、0 复核、0 收入。

#### Ask 3 · 是否批准把“非作者试读”作为 P0 的下一个出口，作者不在场、AI 不计入？

- **为什么需要决定**：P0 出口当前 0 / 1；没有这次试读，无法证明这套件“能被别人读懂”。
- **决定时间**：本周。
- **不决定的影响**：P0 只能停在“写完 + 可交接”，不能算“能用”；G1 的 60 分钟承诺也没有预演。

#### Ask 4 · 是否批准对外材料继续只做草稿，逐次确认后才发送？

- **为什么需要决定**：决策卡、Pitch、邀请话术、P1 数据请求单都含未验证项；误发会把研究件变成承诺。
- **决定时间**：长期有效。
- **不决定的影响**：一次过度声明就可能耗尽信任；回滚成本高于发送前确认。
