00 · Executive Summary

00重评摘要与建议

v1 的排序仍然成立：研究出版与开源先行，企业私有化条件触发，托管按次不做，竞赛/生态可选。 但 v1 把一个尚未证明的东西当成了产品核心——“账本能让第二次修改更好”。上一轮研究证明：账本只能证明记录未被改，不能单独支撑归因；二次修改要成立，必须有外部验证器、产物原像与版本三元组。 所以 v2 改的是卖什么、凭什么卖、什么时候能卖，不是把五条路重新排一遍。

三个结论

结论一：这是一个“功能市场”，不是“平台市场”

买家的预算挂在 LLM 可观测性、Agent 评测或 AI 治理科目下，而不是“可验证记账”这个独立科目 [8][9][10]。 这意味着：产品最合理的形态是证据适配层，挂在现有 trace / eval 平台旁边；独立平台的空间窄，销售周期长，替代成本高。 v1 的 SAM 1.6–3.0 亿美元按“相邻市场 × 占比”估算；v2 把占比下调到 3–6%，SAM 改为 1.0–2.0 亿美元。这是 C 级规划假设，不是市场调查结论。

结论二：可防守的差异是“证据包”，不是“账本”或“链”

账本、哈希链、49 格本身很容易被复制；真正难的是把产物原像、行为/判据版本、拒收计数、外部验证结果装进一个可复核、可回滚、可对外披露的证据包。 这也解释了为什么“开源内核”不够：客户拿到的如果只是一个记账 API，他还要自己补原像、版本、拒收与验证器，价值没有闭环。 开源应交付“适配层 + 证据包规范 + 参考实现”，而不是再发一个账本。

结论三：顺序不变，门槛变严

D（研究出版）第一，因为类别需要外部复核；A（开源证据适配层）第二，用来换真实使用与反例；B（企业私有化）只在 Gate 1.5（R/N 双臂）与 Gate 2（2 封 LOI + 安全审查）都通过后触发；C（托管按次）不做；E（竞赛/生态）可选。 如果 Gate 1.5 显示“看记录再改”相对“不看记录直接改”没有增量，就停止商业化，冻结为研究资产。

本报告可能错在哪里

  • SAM 下调可能过度悲观。如果“AI 审计”在 2027 年成为独立预算科目，SAM 会回升；本报告按“功能预算”估算，偏保守。

  • Gate 1.5 的 10 例 smoke 统计力不足。它只能证伪“有明显增量”，不能证明“普遍有效”；报告不把它写成显著性检验。
  • 财务基准仍可能乐观。Y1 假设 1 个付费客户；如果 Gate 1.5 拖到 Q2，Y1 收入应为 0。
  • 适配层依赖平台开放性。如果 OTel / LangSmith / Langfuse 收紧导出或改变 semconv，适配层要跟着改；这是持续成本。

Chapter 01

01为什么要重评

问题：v1 已经给出“D + A 先行、B 条件触发、C 不做、E 可选”。上一轮研究又证明“账本本身不构成闭环”。这两件事放在一起，原来的进入方式还成立吗？

1.1 v1 的结论与它的前提

v1 的排序建立在三个前提上：第一，市场存在一个“可验证记账”的空位；第二，账本能把“谁做了什么”记清；第三，记录足以支撑一次二次修改。 前两个前提有本地读数支撑：账本 2,940 条、链 2,940/2,940 重算通过、49 格形状稳定 [27][30]。第三个前提在 v1 里是假设，不是实测。

v1 的严格双臂验收已经 FAIL：`declare_reader` 拒收六桶全 0，真人干净臂 NOT_RUN [27]。当时这被解释为“验收工具还没准备好”；现在看，问题更深一层： 即使验收工具准备好，账本也缺少产物原像、行为/判据版本与拒收计数，二次修改无法归因。v1 把“记录完整”当成了“记录足以支持修改”，这是 v2 要修正的核心。

1.2 变了什么：从账本到证据包

上一轮研究（《Agent 执行 → 项目记录 → 二次修改》）给出的结论是：没有外部反馈时，LLM 的内在自省在推理任务上可能使表现下降 [34]； 可靠的自我纠正几乎都依赖测试、工具或人类反馈 [35]。从轨迹学习也一样：Agent Lightning 需要奖励或可验证结果 [38]， ExpeL 依赖任务成败标签 [39]，AWM 的在线模式只从评估器判为正确的轨迹归纳 [41]，Voyager 只把环境验证过的技能入库 [42]。 共同点是：先有外部结果信号，再谈从记录学习。

本地记录面又恰好缺三样：产物原像、版本三元组、拒收计数。账本里没有产物内容，只有 60/60 个 `model_says_sha256` [30]； 没有行为/配置版本、判据版本、审阅者字段；`declare_reader` 只在内存里生效，声明被拒不会进账 [26]。 `read_back` 的描述承诺返回指纹，实现没有打印 [26]。`load_journal` 可以整本替换账本，`APPEND_ONLY` 默认关闭 [26]。 这意味着：账本可以证明“记录未被改”，但不能单独证明“这次修改有依据”。

因此，产品叙事必须换

从“可验证记账内核”换成“可复核的二次修改证据”：账本只是证据包的一件，另外三件是产物原像、版本清单、外部验证器。 这不是加功能，而是加交付物；内核仍然不调度、不联网、不执行工具。

1.3 重评问题与判据

重评问题不变：以哪种方式面对市场。但判据从“哪条路收入大”改成四条更硬的：

  1. 证据判据：这条路能不能产出外部可复核的证据，而不只是内部读数？
  2. 预算判据：买方有没有现成预算科目，还是要新开一个“AI 审计”科目？
  3. 交付判据：能不能在不做托管、不接客户 prompt / 工具输出的前提下交付？
  4. 防守判据：被平台复制时，还剩下什么是难复制的？

这四条判据会把五条路重新排一次。排序结果与 v1 相同，但理由和门槛不同：D 第一，是因为它先解决“证据判据”；A 第二，是因为它解决“交付判据”； B 必须等“预算判据”和“证据判据”都过；C 违反“交付判据”；E 只解决传播，不解决前三条。

Chapter 02

02市场与定位

问题：“可验证记账”到底是独立市场，还是可观测性 / 评测 / 治理三个市场之间的一个功能？

2.1 市场边界：记账层不是可观测性

可观测性回答“发生了什么”，评测回答“好不好”，治理回答“合不合规”。记账层回答的是另一个问题： 这次修改凭什么发生、改的是哪一版、能不能回滚、能不能对外披露。它需要可观测性的 trace 作为输入，但不是 trace 的替代品； 它需要评测的结果作为外部信号，但不是评测平台本身。

2.2 规模重算：为什么下调 SAM

TAM 仍按相邻口径估算：LLM 可观测性约 26.9 亿美元、AI TRiSM 约 30.9 亿美元，两者相邻但不相加，形成 27–31 亿美元的区间 [8][9]。 v1 假设 SAM 占 LLM 可观测性 8–12%、AI TRiSM 5–8%，得到 1.6–3.0 亿美元。v2 把占比下调到 3–6%，理由是： 记账/证据不是可观测性的主预算，而是主预算里的一个附加项；买方不会为“证据包”单独开一个和可观测性同量级的科目。

这样 SAM 约为 1.0–2.0 亿美元：LLM 可观测性 26.9 亿 × 3–6% = 0.8–1.6 亿；AI TRiSM 30.9 亿 × 3–6% = 0.9–1.9 亿； 取相邻区间 1.0–2.0 亿。SOM 按 SAM 的 0.5–2% 估算，三年为 0.5–4.0 百万美元；按 1.5–3.0 万美元 ARPU，对应约 17–267 个账户。 这些占比是 C 级规划假设，不是市场调查结论；v1 的 8–12% / 5–8% 同样是 C 级，v2 只是把假设调得更保守。

Chapter 03

03需求与反需求

问题：什么事件会让买家真正需要“可复核的修改证据”？什么条件下需求会消失？

3.1 三个真实触发

触发一：事故复盘。Agent 执行了一次错误操作，团队要回答“它当时看到了什么、用了哪一版策略、谁批准了修改”。现有 trace 能回答“看到了什么”，不一定能回答“哪一版、谁批准、改了什么”。 A1 注入测试已经证明：链通过、内容仍可以是不可信的 [30]；复盘需要的不是更多 span，而是可追溯的修改证据。

触发二：受监管审计。EU AI Act 第 12 条要求高风险系统在全生命周期内技术上支持自动记录事件；第 26(6) 条要求部署方在其控制范围内保存日志，保存期与预期用途相称，至少六个月 [2][48]。 这类需求真实存在，但买家要的是“能交差的记录”，不是“又一个日志平台”；合规预算通常已经有主，证据层只能做附加项。

触发三：行为变更与回归。团队改了 prompt、路由或阈值，想知道“新版是不是真的更好”。这需要旧版与新版在同一留出集上的对比，以及“为什么改”的证据。 如果没有记录，第二次修改只能靠感觉；有了记录但没有外部验证器，第二次修改会退化成“照着记录再写一遍” [34][35]。

3.2 技术驱动：MCP 采用了，遥测没跟上

MCP 已成为 Agent 工具接入的常见协议 [14]；但遥测侧仍在演化：OpenTelemetry 的 GenAI 语义约定截至 2026-08 的公开资料仍标为 Development， `gen_ai.system` 已在 semconv v1.37.0 起标记弃用、由 `gen_ai.provider.name` 取代 [15][50]。Microsoft Agent Framework 的敏感数据采集默认关闭， prompt、响应、工具入参出参都要显式开启 [45]。这意味着：默认 trace 只是骨架，证据层必须自己补内容、补版本、补拒收。

这既是机会也是成本。机会是：平台还没把“证据包”做成标准；成本是：字段还在变，适配层要固定 semconv 版本并加映射。 v2 因此把 A 的交付物定为“适配层 + 证据包规范”，而不是“又一个 trace 后端”。

3.3 反需求：五件会让需求消失的事

反需求为什么会让需求消失应对
失败率很低没有二次修改，就没有证据需求只盯高变更、高监管、高事故成本场景
现有日志“够用”买家分不清 trace 与证据包，认为再加一层是浪费用一次真实复盘演示“缺哪三样”
隐私与留存顾虑不愿把 prompt / 工具输出交给第三方只做私有化 / 本地证据包，不做托管
不想再加供应商采购流程长，平台已绑定做平台插件 / 适配层，不做替代
平台捆绑LangSmith / Langfuse / Datadog 把证据功能打包进主产品守住“可验证 + 可回滚 + 可披露”的深水区

3.4 需求结论

需求是真的，但窄：它依附于“事故复盘 / 受监管审计 / 行为变更”三个触发，不是一个独立的大科目。正确的进入方式不是教育市场“你需要一个记账内核”， 而是等买家已经在做复盘或审计时，告诉他“你缺的是这三样证据”。这也决定了销售动作：先做复盘工作坊，再卖证据包；先接入现有 trace，再谈替换。

4.2 价格锚：为什么不能按 seat / span / token 卖

可观测性平台按 seat、span 或数据量计价 [16][17][19][20]；评测平台按 experiment / 样本量计价 [18]；治理平台按年度合同计价。 这些锚都不适合“证据包”：证据包的价值不在“记录了多少”，而在“能不能支撑一次修改、能不能回滚、能不能对外披露”。 按 span 卖，会把证据层拉进可观测性的价格战；按 seat 卖，会把价值锚在“人头”而不是“风险”。

合理的锚是“每次可复核修改”或“每年证据包订阅”：试点 3–5 千美元 / 6 周，年度 1.5–3.0 万美元；需要私有化与安全审查的版本 4–8 万美元 / 年。 这个价格带低于企业治理平台，高于纯工具订阅；它对应的是“事故成本”而不是“日志成本”。

五力结论很直接：作为一个横向 SaaS，这不是一个有吸引力的市场。但如果把它做成“嵌在现有平台里的证据层”，竞争强度会下降： 替换成本低、采购链条短、不需要教育买家“再买一个平台”。这也是 v2 把 A 的形态定为适配层，而不是独立 SaaS 的原因。

4.5 竞争会从哪里打死它

  1. 平台打包：LangSmith / Langfuse / Datadog 把“证据包”做成高级功能，免费或低价捆绑。
  2. 云账本下沉：AWS / Azure 把不可抵赖日志与 Agent 语义结合，直接覆盖“完整性”需求 [24][25]。
  3. 治理平台上探：治理平台加技术读数，把“政策 + 证据”一起卖。
  4. 开源克隆：哈希链 + 49 格 + 读回接口没有专利壁垒，复制成本低。
  5. 买家自建：平台团队用现有 trace + 脚本拼一个“够用”的证据包，不采购。

这五条里，最致命的是第一条和第五条。平台打包会压缩价格，买家自建会压缩需求。能对抗这两条的，不是“链更安全”，而是 证据包规范 + 拒收计数 + 版本三元组 + R/N 协议这四样“跨工具、跨团队、可对外”的东西；它们比哈希链更难复制，也更容易被外部复核。

4.6 合作而非替代：做签收层，不做追踪层

正确的合作姿态是：trace 从 OTel / LangSmith / Langfuse 来，评测结果从 LangSmith / Braintrust 来，存储从云账本来，agentkernel 只做“签收”： 把产物原像、行为/判据版本、拒收计数、外部验证结果装成一个可复核的包，签发给审计、客户或内部复盘。 这样既不与平台争入口，也不与云账本争存储；它争的是“最后一公里”的签收权。

06五条进入方式重评

问题：在“功能而非平台”的判断下，五条路各自还剩下什么？哪条先走，哪条不做？

选项 A：开源证据适配层

交付物：证据包规范 + OTel / LangSmith / Langfuse 适配器 + 参考实现 + 一个 10 例的失败样本包。 不交付：又一个 trace 后端、又一个 dashboard、又一个托管服务。 目标：非作者真人在 60 分钟内，把一个失败运行变成“账本 + 原像 + 版本 + 外部验证结果”的证据包，并完成一次可复核修改。

商业模式：开放核心。适配器与规范免费；企业版收“私有化部署 + 安全审查 + 支持”。为什么先走：它直接解决“交付判据”，且替换成本低， 买家可以在现有 trace 上试用，不需要换平台。风险：平台把适配器吸进主产品；对策是把“拒收计数 + 版本三元组 + R/N 协议”做成规范，而不是单个连接器。

选项 B：企业私有化

交付物：VPC / 本地部署的证据包服务 + SBOM + DPA + 责任边界 + 安全审查材料。 价格：基础版 1.5–3.0 万美元 / 年；证据包版 4–8 万美元 / 年；试点 3–5 千美元 / 6 周。 为什么条件触发：它解决“预算判据”，但销售周期长、支持成本高；在 Gate 1.5 证明增量之前，不应把资源压到 B。 触发条件：Gate 2 的 2 封 LOI + 1 次安全审查 + SBOM/DPA/责任边界都过；且 Gate 1.5 已通过。

选项 C：托管按次

为什么不做：托管意味着接客户的 prompt、工具输出与产物；隐私、留存、跨境、运维成本同时上升，且与“不执行工具”的定位冲突。 按次计价还会把价值锚在“调用量”，而不是“证据包”。如果未来一定要做托管，只做“元数据 + 哈希”的签收服务，不接内容；但这仍然不是当前优先项。

选项 D：研究出版 / 标准

交付物：《Agent 执行 → 项目记录 → 二次修改》研究报告、R/N 双臂协议、负结果（严格双臂 FAIL、拒收六桶全 0）、证据包规范草案。 为什么第一：它解决“证据判据”。这个类别还没有被外部复核过；先发布“什么能证明、什么不能证明”，比先卖产品更能建立信任。 不是收入线：D 的直接收入接近 0；它的产出是外部复现、批评、引用与第一个 POC 志愿者。

选项 E：竞赛 / 生态

形态：“二次修改证据”基准赛：给 10 个失败运行，要求参赛者产出可复核的证据包并完成修改；评分看留出集通过率、假修复率、证据完整性。 为什么可选：它能带来传播与外部样本，但不解决预算与交付；只有在 A 的适配层可用之后才有意义，否则会变成一次性活动。

08定价与单位经济

问题：证据包按什么计价？为什么不能按 seat / span / token？单位经济在什么条件下成立？

8.1 计价单位：证据包，不是调用量

可观测性平台按 seat、span 或数据量计价 [16][17][19][20]；评测平台按 experiment / 样本量计价 [18]。 证据包的价值不在“记录了多少”，而在“能不能支撑一次修改、能不能回滚、能不能对外披露”。因此计价单位应是 “每年证据包订阅”或“每次可复核修改”，而不是 seat / span / token。按调用量卖，会把证据层拉进可观测性的价格战； 按人头卖，会把价值锚在“人头”而不是“风险”。

  • 平台捆绑：可观测性平台把证据功能打包，价格被压到“功能价”；对策是卖“跨平台 + 可披露 + 可回滚”，不卖单点功能。

9.3 三条红线

红线一：不把审计层说成防线

agentkernel 不拦截、不调度、不联网、不执行工具。它能证明“记录未被改”，不能证明“攻击被挡住”。 对外材料必须把“审计”“验链”“读回”和“防护”分开写；否则第一次真实事故就会暴露预期错位。

红线二：不把“记录完整”说成“内容为真”

A1 注入实测已经证明：链可以全通过，内容仍然不可信 [30]。证据包必须携带“谁生成、什么版本、有没有外部验证器、拒收了多少”， 否则客户会把“账本通过 verify”误读成“结论可信”。

红线三：不在 R/N 未跑前说“闭环已通”

严格双臂仍是 FAIL，`declare_reader` 拒收六桶全 0，真人臂 NOT_RUN。Gate 1.5 之前，所有对外表述只能是 “条件可复核的修改证据”，不能是“记录驱动的自动改进”。

9.4 红队：最可能被打穿的两条

第一条：买家自建。红队会说：“我有 OTel、有 Git、有 CI，为什么还要买你？”如果回答是“我的链更完整”， 这条防线很薄；如果回答是“我能把产物原像、行为/判据版本、拒收计数和外部验证结果装成一个可披露、可回滚的证据包， 并且换一个平台也能复核”，才有得谈。也就是说，卖点必须是跨平台的证据规范与复核流程，不是单点记账。

第二条：平台打包。红队会说：“LangSmith / Langfuse 加一个‘修改审计’标签页就做完了。”这在追踪深度上确实成立。 本报告的应对不是否认，而是换战场：平台记录“发生了什么”，证据包回答“这次修改凭什么算数、失败样本有没有被挑掉、换个人能不能复核”。 这两件事相关，但不是同一件；如果平台把这件也做了，本路线应退回到研究/标准，不硬拼产品。

9.5 风险结论

最危险的不是“没有需求”，而是需求被满足到 60% 时，客户认为剩下的 40% 不值得单独付费。R1 与 R4 都指向这一点。 因此本报告把商业化的前置条件放在“外部复核 + 跨平台可复核 + 事故成本可量化”三件事上，而不是放在功能清单上。 R3 是唯一必须在写第一行销售材料之前解决的技术风险：没有原像、版本与拒收计数，证据包就退化成日志导出。

Chapter 12

12结论

以“证据适配层”的方式面对市场，不以“平台”的方式；以“研究 + 开源”换取外部复核，不以“发布即推广”换取流量； 以“证据成立后再收费”约束私有化，不以“先卖再做”换取短期收入。

12.1 直接回答

D + A 先行；B 条件触发；C 不做；E 可选

D（研究出版）第一，因为“执行记录能否支撑二次修改”还没有被外部复核；先把负结果、R/N 协议与证据包规范公开，换取 3 个评审与 1 个真实触发。 A（开源证据适配层）第二，交付的不是又一个账本，而是把账本、产物原像、行为/判据版本、拒收计数与外部验证器装进可复核的证据包。 B（企业私有化）只在 Gate 1.5（R/N 双臂）与 Gate 2（LOI + 安全审查）都通过后启动，先卖 3–5 千美元试点，再谈 4–8 万美元证据包版。 C（托管按次）不做：隐私、留存、跨境与运维成本同时上升，且与“不执行工具”的定位冲突。E（竞赛/生态）可选，放在 A 之后，不单独立项。

12.2 三条不许越过的前提

  1. R/N 没有增量，就不卖“记录驱动改进”。可以卖验证器、证据包模板与复盘服务，但不能把“看记录再改”写成产品能力。
  2. 没有原像、版本与拒收计数，就不叫证据包。只有账本，客户买到的是日志导出；这三样必须在链外补齐，且可被外部复核。
  3. 没有外部复核，就不进入私有化。Gate 1.5 与 Gate 2 是商业化的前置条件，不是“以后再说”的改进项。

12.3 如果只做一件事

未来 7 天只做一件事：把 R/N 协议冻结，并从现有材料里挑出 10 个修改样本 + 10 个留出样本。 没有这两组样本，Gate 1.5 无法开始；没有 Gate 1.5，B 的销售材料写了也会被一条读数打穿。 协议与样本清单不需要新代码，只需要把已发生过的修改逐条编号、补上产物原像与判据版本；这是当前成本最低、信息量最大的一步。

12.4 什么会改变这个结论

  • G1.5 出现明显增量：R 臂留出集通过率显著高于 N 臂，且假修复率不升；此时可以提高对 B 的投入，甚至考虑 C 的轻量托管。
  • 买家愿意为“可复核”单独设预算科目：SAM 与 ARPU 应上调；本报告的“功能市场”判断需要修订。
  • 头部平台把证据包做成标准功能：A 应退回为规范与适配器，B 不做；项目转为研究 / 标准资产。
  • 外部复现连续失败：停止对外推广；先修证据包，不修叙事。
最后一句

这个项目的市场价值，不取决于账本有多完整，而取决于一个外部团队能否在 60 分钟内，用你的证据包复核一次真实修改，并得出与你相同的结论。 在这一点被证明之前，最诚实的市场姿态是研究出版与开源适配层，而不是平台销售。

agentkernel 把一次 Agent 修改的账本、产物原像、行为/判据版本与拒收计数装进一个可复核的证据包，让另一个团队能独立判断这次修改是否算数。

一段话（对外简介）

Agent 团队已经不缺 trace，缺的是“这次修改凭什么算数”的可复核证据。agentkernel 是一个证据适配层：它接在现有 trace / eval 旁边， 把账本、产物原像、行为与判据版本、拒收计数和外部验证结果装进一个证据包。它不拦截、不调度、不执行工具，也不宣称让 Agent 更可信； 它只让一次修改可被另一个人复核、回滚和披露。当前版本是研究资产，R/N 双臂尚未运行；我们优先寻找有真实事故复盘、审计或行为变更触发的团队做 POC。
