# Agentkernel 试点函（草案 v0.1）

- **日期**：2026-10-20
- **对应决策卡**：V2.1（2026-10-20）
- **性质**：研究与试点邀请的附件；不是报价单、投资建议、合规意见或合同
- **适用对象**：已收到决策卡、愿意先做第 0 步的团队
- **证据分级**：A 工具自印 + 可复算 / B 单源自印 / C 规划假设 / D 外部公开 / X 未验证（不写成 0）

> 本函把卡上“第 0 步不收费”落成可执行口径：先给复核清单、拒收判据、数据条款与 60 分钟计时口径；第 0 步不收费，也不要求采购平台。双方书面确认前，本函不构成任何一方义务。

---

## 0. 第 0 步（不收费）

### 0.1 目的

判断一次真实修改能否在 6 周内产出可复核证据包。能，则进入付费试点；不能，则书面说明缺口，不进入付费试点。

### 0.2 输入（客户提供，可先脱敏）

- 一次真实的 Agent 行为修改：修改前 / 后的产物（文件、配置、提示词）
- 一次失败复盘：发生了什么、当时怎么归因、缺什么证据
- 现有账本 / 日志导出（若有）
- 1 名非作者复核人的可用时间（60 分钟）

### 0.3 产出（我方提供，不收费）

- 复核清单 v0.1（见 §3）
- 拒收判据 R1–R7（见 §5）
- 60 分钟计时口径（见 §6）
- 数据条款草案（见 §7）
- 书面判断：可进入 / 不可进入，以及缺口清单

不承诺“一定可进入”；“不可进入”也是有效结论。

### 0.4 第 0 步的边界

- 不接模型调用、不联网、不执行工具；只读材料与本地校验
- 不修改客户代码
- 不在第 0 步生成对外案例

## 2. 双方投入与交付物

### 2.1 客户投入

| 项 | 最低要求 |
| --- | --- |
| 样本 | 1 次真实修改，含修改前后产物 |
| 复盘 | 1 次失败复盘，说明当时缺哪类证据 |

### 2.2 我方交付（证据包最小内容）

| 内容 | 说明 | 状态写法 |
| --- | --- | --- |
| 账本导出 | 记录链原始数据与校验脚本 | 有 / 无 |
| 产物原像 | 修改前后文件、配置、提示词的哈希清单 | 有 / 无 |
| 版本三元组 | 产物版本、行为版本、判据版本 | 齐全 / 缺失 |

| 拒收清单 | 每次拒收的原因码 R1–R7 与证据 | 计数 / NOT_RUN |
| R/N 记录 | 留出集 vs 无记录的双臂对照 | MEASURED / NOT_RUN |
| 交付说明 | 能说什么、不能说什么、剩余缺口 | 必附 |

**不交“通过率”**：没有真人样本时，不写通过率；没有跑 R/N 时，写 `NOT_RUN`，不写 0。

## 3. 复核清单（60 分钟版，v0.1）

复核人只按本清单执行；作者不代跑、不提示答案、不中途改判据。

| 步骤 | 时间盒 | 动作 | 通过判据 |
| --- | --- | --- | --- |
| S1 材料核对 | 5 min | 核对文件清单、哈希、版本号 | 清单齐全，哈希可复算 |
| S2 链复算 | 20 min | seq 连续、prev 指向前一条、payload 哈希、seal 校验 | 逐条复算通过；断点可定位 |
| S3 原像抽查 | 10 min | 随机 3 个产物，重算哈希并与清单比对；不足 3 个则全查 | 抽查全部一致 |
| S4 版本三元组 | 10 min | 核对产物 / 行为 / 判据版本是否齐全且一致 | 齐全且一致 |
| S5 断点定位 | 10 min | 若链有断点，定位到记录与原因；若无可确认无断点 | 有证据的定位，或“无断点”结论 |
| S6 书面结论 | 5 min | 写通过 / 拒收 + 原因码 + 证据引用 | 结论可复核，不写“感觉” |

- 清单 v0.1 会按样本调整；调整须在第 0 步书面确认，不得在复核中途改判据。
- 复核人可用我方校验脚本，但脚本输出必须能由复核人自己重跑。
- 复核人不需要理解 Agent 内部实现，只需要按清单核对材料与读数。

## 4. 验收清单 A1–A6

| 编号 | 验收项 | 判据 | 分母 | 未达成处置 |
| --- | --- | --- | --- | --- |
| A1 | 链自洽 | seq / prev / payload / seal 逐条复算通过；若有断点，断点可定位 | 账本记录数 | 尾款不付 |
| A2 | 产物原像 | 修改前后产物可取得，哈希与清单一致 | 抽样产物数 | 尾款不付 |
| A3 | 版本三元组 | 产物 / 行为 / 判据版本齐全且一致 | 修改次数 | 尾款不付 |
| A4 | 外部复核 | 至少 1 名非作者在 60 分钟内完成清单并提交书面结论 | 复核次数 | 尾款不付 |
| A5 | 拒收计数 | 每次复核记录通过 / 拒收 / 超时及原因码；不以 0 代替未测 | 复核次数 | 尾款不付 |
| A6 | R/N 双臂 | 报告留出集 vs 无记录的增量，或明确 `NOT_RUN` | 留出集样本数 | 不挂钩尾款，但必须披露 |

- A1–A5 与尾款挂钩；A6 未运行不视为失败，但不得写成“已有效”。
- A6 的 `NOT_RUN` 必须出现在证据包与对外材料中；写成 0 视为 R5。
- 所有分母必须写成实际数；无法取得时分母写 `absent` 并说明原因。

### 4.1 R/N 双臂定义

| 臂 | 材料 | 复核人做什么 | 记录 |
| --- | --- | --- | --- |
| R（留出集） | 账本 + 产物原像 + 版本三元组 + 复核清单 | 按 §3 的 60 分钟清单执行 | 通过 / 拒收 / 超时；断点是否定位；用时 |
| N（无记录） | 只有现有 trace / 日志，无原像、无版本、无复核清单 | 回答同一组问题：改的是哪一版、能否定位断点、能否判断修好 | 同上；明确“无法判断”也记录 |

- 两臂使用同一批问题、同一批评审人标准；不把 R 臂的清单泄漏给 N 臂。
- 增量至少报告：断点定位比例、复核用时中位数、拒收计数；样本不足时写 `NOT_RUN`，不写 0。
- N 臂不是“没有证据包也能通过”的对照，而是用来量“缺证据时到底缺多少”。

## 5. 拒收判据 R1–R7

| 编号 | 拒收条件 | 记录方式 |
| --- | --- | --- |
| R1 | 链不可复算：seq / prev / payload / seal 任一断，且无法定位 | 记录断点位置与复算输出 |
| R2 | 产物原像缺失或哈希不符 | 记录缺失文件 / 不符哈希 |
| R3 | 版本三元组缺失或不一致 | 记录缺哪一版、与哪一版冲突 |
| R4 | 非作者在 60 分钟内无法定位断点 | 记录计时与卡住步骤 |
| R5 | 拒收计数未测却写成 0 | 记录原文与出处 |
| R6 | 对外材料出现禁用宣称：挡住提示注入 / 工具滥用、内容可信、自动改进已有效、30 分钟接入、托管按次、已通过合规认证 | 记录原句与材料位置 |
| R7 | 数据条款未签，或样本处理越界 | 记录越界事实与处置 |

- 拒收不是“失败率”：每条拒收都要有原因码、证据与复核人。
- 超时按拒收计，但原因写“超时”，不写“链断”。
- 因 R1–R7 拒收时，不对外发布该样本案例；书面说明缺口后可重新提交一次。

## 6. 60 分钟计时口径

| 项 | 口径 |
| --- | --- |
| 起点 | 材料包交付且复核人确认可读 |
| 终点 | 复核人提交书面结论 |
| 允许 | 运行校验脚本；一次材料澄清，不超过 10 分钟，计入 60 分钟 |
| 不允许 | 作者代跑、提示答案、追加样本、中途修改判据 |
| 超时 | 按拒收计，原因写“超时”；同时记录实际用时 |
| 记录 | 开始 / 结束时间、澄清次数、卡住步骤、结论 |

“60 分钟”是验收上限，不是平均耗时；没有真人计时前，不写“平均 60 分钟”。

## 7. 数据条款（摘要）

| 项 | 口径 |
| --- | --- |
| 处理环境 | 客户指定机器或区域；离线处理；不接模型调用、不联网 |
| 最小化 | 只收与本次修改相关的产物与复盘；客户可先脱敏 |
| 驻留 | 客户指定位置；未指定时默认留在客户提供的环境 |
| 留存 | 交付后 30 天；客户可书面要求延长或缩短 |
| 删除 | 到期或应客户要求后 5 个工作日内删除，并提供删除确认 |
| 子处理方 | 无 |
| 访问 | 仅试点执行人与客户指定的复核人；签署保密条款 |
| 责任上限 | 已付费用 |
| 披露 | 仅匿名化披露，且需客户书面同意；被拒收的样本不公开 |
| 安全事件 | 发现后立即书面通知，不超过 24 小时 |

客户可书面提出替代条款；未达成一致前不开始处理样本。

## 9. 明确不做 / 不说

- 不拦截、不调度、不联网、不执行工具。
- 不替代 SIEM、可观测性、评测平台。
- 不提供合规认证；为 EU AI Act 第 12 条记录义务提供的只是技术证据。
- EU AI Act 第 12 条仅涉及记录保存；本试点不评估第 9–15 条的其他义务，不构成合规认证。
- 不承诺“挡住提示注入 / 工具滥用”；审计层不是防线。
- 不承诺“内容可信”；链只证明记录未被改。
- 不承诺“记录驱动自动改进已有效”；R/N 双臂未运行前写 `NOT_RUN`。
- 不做托管按次 / 多租户。
- 当前版本是研究资产，不是成熟平台。
