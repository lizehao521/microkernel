# Agentkernel 产品设计蓝图（v1.0）

- **日期**：2026-10-20
- **对象**：可复核的二次修改证据包服务 + 6 周试点运营
- **不是**：单页决策卡改版、内核代码设计、合规认证方案
- **上游**：`产品级-二次评估.md`（判定：条件 GO，只批准一个试点）
- **可视化件**：`产品设计蓝图.html`（自包含，可浏览器打开）

## 1. 设计简报（Brief）

### 1.1 一句话

> 让一个不信任作者的人，在 60 分钟内独立判断：这次 Agent 修改改的是哪一版、证据是否成立、应当通过还是拒收。

### 1.2 问题

Agent 团队已经有 trace / eval，但一次行为修改发生后，仍然答不出三个问题：

1. **改的是哪一版**——产物、行为、判据三者的版本对不上；
2. **凭什么算修好**——没有同一留出集上的对照，也没有拒收记录；
3. **另一个人能不能复核**——记录在作者手里，复核人只能听作者讲。

现有工具答“发生了什么”，不答“这次修改凭什么算数”。产品要补的是后者。

### 1.3 用户

| 角色 | 一句话 |
| --- | --- |
| AI 平台负责人 | 要回答“这次变更为什么发生、是否真的更好” |
| 安全工程负责人 | 要做事后取证与复盘 |
| 合规 / 风险负责人 | 要留可审计证据，但不负责认证 |
| 非作者复核人 | 要在 60 分钟内独立通过或拒收 |
| 证据工程师（我方） | 要把一次真实修改组装成可复核包 |

### 1.4 设计原则

| # | 原则 | 落到界面 / 流程 |
| --- | --- | --- |
| 1 | **证据先于界面** | 每个屏先问“这一屏产出哪件证据”，再问布局 |
| 2 | **硬门而非警告** | 缺原像 / 缺版本 / 缺复核人 → 不能封包，不是黄色提示 |
| 3 | **三态不塌** | 有 / 缺席（带理由）/ 未运行，三态分开显示；未运行不写成 0 |
| 4 | **复核人优先** | 60 分钟工作台是核心屏，不是报告附属页 |
| 5 | **只读旁挂** | 不接运行时、不改客户代码、不拦截 |
| 6 | **可删除** | 留存 30 天、删除 5 天、无子处理方、删除回执 |
| 7 | **不冒充防线** | 首屏、报告、合同三处写非声明 |
| 8 | **先服务后软件** | 首版用模板 + 脚本 + 人工；软件只做提效，不卖平台 |

### 1.5 约束

- 不调用模型、不改客户模型代码、不联网执行工具。
- 不做多租户、不做托管按次、不做按 seat / span / token 计费。
- 证据包只对应审计与日志（MCP08），不宣称覆盖 MCP01/03/06。
- 试点 6 周、3–5 千美元；做不出可复核包不收尾款。
- 真人复核、R/N 双臂当前均 `NOT_RUN`；设计件不能写成已验证。

### 1.6 成功标准

**试点级成功**：一个真实修改 → 一个 8 段证据包 → 一名非作者在 60 分钟内给出通过 / 拒收 / 超时，且断点可定位。
**不把以下当成功**：页面好看、AI 模拟读者高分、链自洽但没有原像、报告写完但没人复核。

## 2. 产品结构

### 2.1 三个层

```
┌─────────────────────────────────────────────────────────┐
│  服务层（人）  受理 · 组包 · 预演 · 正式复核 · R/N · 报告  │
├─────────────────────────────────────────────────────────┤
│  证据层（规范）8 段证据包 · 版本三元组 · R1–R7 · A1–A6    │
├─────────────────────────────────────────────────────────┤
│  工具层（软件）Intake · Builder · Reviewer · Ledger · Report│
└─────────────────────────────────────────────────────────┘
```

**顺序不能反**：先有人跑通服务，再有工具提效。首版工具是内部工作台，不是客户自助产品。

### 2.2 六个界面

| ID | 界面 | 主要用户 | 一句话 | 产出证据 |
| --- | --- | --- | --- | --- |
| S0 | Evidence State Board | 交付方 / 买家 | 所有包现在在哪一步、缺什么 | 状态快照（只读） |
| S1 | Intake Sheet | 买家 + 交付方 | 受理时把样本、原像、版本、复核人、条款一次问清 | 受理记录 + 原像清单 |
| S2 | Pack Builder | 证据工程师 | 把账本、原像、版本、拒收组装成 8 段包 | 包清单 + 链验证报告 |
| S3 | Reviewer Console | 非作者复核人 | 60 分钟内按 S1–S6 复算并给出决定 | 复核记录 + 断点 |
| S4 | Rejection Ledger | 交付方 | 把每次拒收变成可计数的原因码 | 拒收记录 + 计数 |
| S5 | POC Report | 买家 + 交付方 | 把“证明了什么 / 没证明什么”写成决策件 | 报告 + 决策备忘 |

### 2.3 信息架构

```
产品
├─ S0 状态板（只读总览）
│  ├─ 包列表
│  ├─ 证据状态（A/B/C/D/X）
│  └─ 到期 / 阻塞
├─ S1 受理
│  ├─ 线索资格
│  ├─ 修改描述
│  ├─ 原像清单
│  ├─ 版本三元组
│  ├─ 复核人指派
│  └─ 数据条款
├─ S2 组包
│  ├─ 账本导入与链验证
│  ├─ 原像哈希与 custody
│  ├─ 版本对齐
│  ├─ 拒收账
│  ├─ 8 段完整性
│  └─ 封包
├─ S3 复核
│  ├─ 包摘要 / 非声明
│  ├─ 60 分钟计时
│  ├─ S1–S6 清单
│  ├─ 断点定位
│  └─ 通过 / 拒收 / 超时
├─ S4 拒收账
│  ├─ R1–R7 计数
│  ├─ 样例与证据链接
│  └─ 处置
└─ S5 报告
   ├─ A1–A6 结果
   ├─ R/N 对照
   ├─ 工时与成本
   ├─ 非声明
   └─ 决策
```

## 3. 服务蓝图（7 段）

| 阶段 | 客户动作 | 前台（可见） | 后台（不可见） | 证据件 | 系统 | 失败态 / 停点 |
| --- | --- | --- | --- | --- | --- | --- |
| 0 触发与资格 | 内部发生事故 / 审计 / 行为变更 | 15 分钟资格通话 | 查三件事：真实修改、非作者、数据条款 | 资格记录 | S1 | 任一项没有 → 不进入受理 |
| 1 受理 | 填 Intake Sheet、交原像、指派复核人 | 受理会 + 清单确认 | 建包 ID、哈希原像、记录 custody | 受理记录 + 原像清单 | S1 | 原像 / 复核人 / 条款缺 → 不签约 |
| 2 组包 | 提供账本导出、补充版本信息 | 组包进度与缺口清单 | 链验证、版本对齐、拒收账、8 段检查 | 包 v0.1 + 链验证报告 | S2 | 链断 / 原像缺 / 版本缺 → 不封包 |
| 3 预演 | 不参与（内部） | 预演结论 | 内部复核人按 S1–S6 试跑、调清单 | 预演记录 | S3 | 两轮仍 >60 分钟 → 改清单，不承诺 60 分钟 |
| 4 正式复核 | 指派非作者复核人 | 60 分钟复核会（可远程） | 计时、记录每步、断点定位 | 复核记录 + 决定 | S3 | 超时 / 冲突 / 证据缺 → 记为超时或拒收 |
| 5 R/N（可选） | 提供同题样本与验证器 | 结果只读 | R 臂（有包）vs N 臂（只有 trace），同题同时 | R/N 表 | S5 | 样本 <10 → `NOT_RUN`，不宣称增量 |
| 6 报告与收尾 | 收报告、做保留 / 回滚决定 | 30 分钟读报 | 汇总 A1–A6、工时、非声明、删除 | 报告 + 删除回执 | S5 / S0 | 无复核记录 → 报告只能是草稿 |

### 3.1 前台 / 后台 / 支撑

| 层 | 内容 |
| --- | --- |
| 前台 | 资格通话、受理会、复核会、报告读会 |
| 后台 | 原像哈希、链验证、版本对齐、拒收账、R/N 设计、报告撰写 |
| 支撑 | 试点函 / DPA、复核人池、模板库、证据分级口径、删除流程 |

### 3.2 关键时刻（Moment of Truth）

1. **受理时**：客户发现“原来我拿不出改前产物”——这是最常见的失败点，必须当场暴露，不能拖到第 4 周。
2. **预演时**：内部复核人第一次跑，发现清单读不懂或超时——这决定 60 分钟承诺是否可信。
3. **正式复核时**：复核人找不到断点，或作者忍不住解释——这决定“非作者独立复核”是否成立。
4. **报告时**：买家问“所以你们证明了我的 Agent 可信吗”——必须回答“没有，只证明了这次修改的证据是否成立”。

## 4. 端到端旅程

| 阶段 | 用户目标 | 触点 | 情绪 | 痛点 | 机会 |
| --- | --- | --- | --- | --- | --- |
| 触发 | 解释一次回归 / 应付审计 | 内部事故会、审计通知 | 焦虑、被追问 | 现有 trace 答不出“哪一版” | 用一张“缺三样”对照表切入 |
| 资格 | 判断值不值得做 | 15 分钟通话 | 怀疑、怕麻烦 | 不知道要交什么 | 先给清单与拒收判据（第 0 步不收费） |
| 受理 | 把材料交齐 | Intake Sheet | 被清单压住 | 原像散落、版本说不清 | 用“缺什么 / 谁补 / 何时补”三列 |
| 组包 | 看到进度 | 周报 / 缺口清单 | 等待、担心 | 不知道还要多久 | 每周固定缺口清单 + 风险等级 |
| 预演 | 确认 60 分钟可行 | 预演结论 | 紧张 | 怕复核人看不懂 | 先内部试跑，修清单 |
| 复核 | 独立判断 | Reviewer Console | 专注、时间压力 | 证据找不到、术语太多 | 每步一个证据入口 + 计时 |
| 报告 | 做保留 / 回滚决定 | POC Report | 需要确定性 | 怕被过度承诺 | A/B/C/D/X 逐条标注 |
| 收尾 | 删除 / 留档 | 删除回执 | 谨慎 | 不知道删了什么 | 删除清单 + 哈希回执 |

**情绪曲线**：触发时焦虑 → 资格时怀疑 → 受理时被清单压住 → 组包时等待 → 复核时专注 → 报告时需要确定性。设计要在“受理”和“复核”两个低谷给确定性，而不是在首屏给热闹。

## 5. 核心流程

```
[触发] 
  │
  ▼
[S1 资格] ── 无真实修改 / 无复核人 / 不接受条款 ──▶ [不进入受理]
  │ 有
  ▼
[S1 受理] ── 原像缺 / 版本缺 ──▶ [补料] ── 仍缺 ──▶ [停止或降级]
  │ 齐
  ▼
[S2 组包] ── 链断 ──▶ [定位断点] ── 不可修 ──▶ [停止]
  │ 链自洽 + 8 段齐
  ▼
[S3 预演] ── >60 分钟 ──▶ [改清单] ── 两轮仍超 ──▶ [不承诺 60 分钟]
  │ 可复现
  ▼
[S3 正式复核] ── 拒收 ──▶ [S4 记账] ──▶ [修包 / 终止]
  │ 通过
  ▼
[S5 R/N] ── 样本 <10 ──▶ [标 NOT_RUN]
  │ 样本足
  ▼
[S5 报告] ── 无复核记录 ──▶ [草稿]
  │ 有
  ▼
[决策：保留 / 回滚 / 再改 / 冻结]
  │
  ▼
[收尾：留存 / 删除 / 回执]
```

### 5.1 流程规则

- **没有样本不签约**：资格通话当天确认改前 / 改后产物与失败复盘。
- **没有复核人不签收**：复核人必须在受理时具名，且不能是作者。
- **没有原像不封包**：原像是硬门，不是“后续补”。
- **没有复核记录不出报告**：报告只能标草稿，不能对外。
- **样本不足不跑 R/N**：标 `NOT_RUN`，不把“没跑”写成“无增量”。

## 6. 界面规格

### S0 · Evidence State Board

- **目的**：一屏看清所有包的状态与缺口，防止“默认全绿”。
- **用户**：交付方（全量）、买家（仅自己的包）。
- **字段**：包 ID、客户、触发类型、阶段、A1–A6、X 项、复核人、截止日、最后更新、决定。
- **主操作**：打开包 / 导出状态。
- **状态**：空（0 个真实包，显示“0 个”，不画假曲线）、加载、错误、边界（多包分页）、权限（客户只看自己）、离线（只读缓存）。
- **证据产出**：状态快照（时间戳 + 包列表哈希）。
- **验收**：任何 X 项必须显示 `NOT_RUN`，不能显示空或 0。
- **非声明**：状态不是质量分；A1 通过不代表 A2–A6 通过。

### S1 · Intake Sheet

- **目的**：一次问清受理所需的最小证据，当场暴露缺口。
- **用户**：买家发起人 + 交付方证据工程师。
- **字段**：
  - 组织 / 联系人 / 角色；
  - 触发类型（事故 / 审计 / 行为变更）；
  - 修改描述（改了什么、为什么、何时）；
  - 改前 / 改后产物（文件 / 配置 / 提示词），每个含路径、SHA-256、custodian；
  - 版本三元组：产物版、行为版、判据版（各含来源）；
  - 现有 trace / eval 链接；
  - 验收 A1–A6、拒收 R1–R7；
  - 非作者复核人：姓名、角色、独立性声明、60 分钟可用时段；
  - 数据条款：驻留、30 天留存、5 天删除、无子处理方、责任上限；
  - 同意 / 签署。
- **主操作**：`受理`（硬门全过）或 `拒绝线索`。
- **状态**：草稿、缺件（逐项点名）、不合格（无真实修改）、已受理、撤回。
- **证据产出**：受理记录（时间戳）、原像清单、签署。
- **验收**：原像、复核人、条款三项无 `TBD`；任一缺 → 不能点“受理”。
- **非声明**：提交不等于受理；受理不等于通过。

### S2 · Pack Builder

- **目的**：把账本、原像、版本、拒收组装成 8 段证据包，并强制硬门。
- **用户**：证据工程师（内部）。
- **字段 / 区块**：
  1. 包 ID、客户、受理记录；
  2. 账本文件 + SHA、实例 ID、部署姿态（append-only / require token / max entries）；
  3. 链验证：记录数、发数、格数、链通过 / 失败、absent 数；
  4. 原像清单：artifact ID、类型、路径、SHA-256、custodian、改前 / 改后；
  5. 版本三元组：3 项 + 来源 + 对齐状态；
  6. 拒收账：R1–R7 计数 + 分母；
  7. 清单：S1–S6 生成；
  8. 缺口清单：blocking / non-blocking；
  9. 包哈希清单。
- **主操作**：`导入`、`验证链`、`封包 v0.1`。
- **状态**：空、导入中、链断（block）、原像缺（block）、版本缺（block）、拒收不可得（draft only）、已封包。
- **证据产出**：包清单、链验证报告、缺口清单、包 SHA。
- **验收**：8 / 8 段齐；blocking 缺口 0；包 SHA 可复算。
- **非声明**：封包不等于内容为真；链验证只证明记录未被改。

### S3 · Reviewer Console

- **目的**：让非作者在 60 分钟内独立复算、定位断点、给出决定。
- **用户**：非作者复核人。
- **字段 / 区块**：
  - 包摘要 + 范围 + 非声明；
  - 计时器（开始 / 暂停 / 总计 / 每步）；
  - S1–S6 清单：每步一条指令、一个证据入口、通过 / 失败、备注、用时；
  - 断点定位：seq / 记录 / 原像哈希；
  - 决定：通过 / 拒收 / 超时；
  - 拒收原因码 R1–R7；
  - 独立性声明 + 签名。
- **主操作**：`开始复核`、`提交决定`。
- **状态**：未开始、进行中、暂停、通过、拒收、超时、回避（利益冲突）。
- **证据产出**：复核记录（时间戳、每步结果、决定、原因、签名）。
- **验收**：60 分钟内提交；S1–S6 均有尝试；拒收必须带断点。
- **非声明**：复核人只对包负责，不对系统认证。

### S4 · Rejection Ledger

- **目的**：把拒收变成可计数、可复用的资产。
- **用户**：交付方；买家只读。
- **字段**：拒收 ID、包 ID、阶段、R1–R7、描述、证据链接、严重度、owner、处置、是否复发。
- **主操作**：`记录拒收`、`关闭并处置`。
- **状态**：空（0 条，如实）、有记录、争议中、已解决、不适用。
- **证据产出**：拒收记录 + 计数（分子 / 分母）。
- **验收**：每条有原因码与证据；`其他` 必须带说明；不允许无分母的百分比。
- **非声明**：拒收不是产品失败，是读数。

### S5 · POC Report

- **目的**：给买家一份能拍板的报告，明确“证明了什么 / 没证明什么”。
- **用户**：买家 + 交付方。
- **字段 / 区块**：
  - A1–A6 结果（逐项 A/B/C/D/X）；
  - 包摘要 + 链验证；
  - 复核记录（通过 / 拒收 / 超时）；
  - 拒收计数；
  - R/N 表（样本足时）；
  - time-to-pack、实际工时；
  - 非声明；
  - 决策：保留 / 回滚 / 再改 / 冻结；
  - 下一步与 owner。
- **主操作**：`发布报告`（需复核记录）。
- **状态**：草稿、阻塞（无复核）、可发布、已发布、归档。
- **证据产出**：报告 + 决策备忘 + 报告哈希。
- **验收**：每个结论有等级；X 不塌；决策有 owner 与日期。
- **非声明**：报告不是认证，不是投资建议。

## 7. 六态矩阵

| 界面 | 空 | 加载 | 错误 | 边界 | 权限 | 离线 |
| --- | --- | --- | --- | --- | --- | --- |
| S0 状态板 | 0 个真实包，显示 0，不画假趋势 | 读取中 | 读取失败，保留上次快照并标时间 | 多包分页 / 筛选 | 客户只看自己的包 | 只读缓存 |
| S1 受理 | 无线索 | 校验组织信息 | 字段校验失败，逐项点名 | 原像 >20 件，分批 | 非本组织不可见 | 本地草稿 |
| S2 组包 | 未导入账本 | 哈希 / 验证中 | 链断 / 文件损坏，定位到 seq | 10 万条记录分页 / 流式 | 无原像访问权 → 停 | 本地模式，联网后复核 |
| S3 复核 | 未分配包 | 打开包 | 证据链接失效，标断点 | 60 分钟到点 → 超时 | 非指派 / 利益冲突 → 回避 | 计时本地，提交后同步 |
| S4 拒收账 | 0 条拒收，如实显示 | 查询中 | 重复记录 / 缺原因码 | 大量记录分页 | 买家只读自己的 | 队列待同步 |
| S5 报告 | 无报告 | 生成中 | 无复核记录 → 阻塞 | 大包分页 / 附件 | 仅买家与交付方 | 只读缓存 |

### 7.1 状态文案规则

- 空：说“还没有”，不说“0 个问题”。
- 加载：说“正在读哪一件”，不说“稍等”。
- 错误：说“哪一步失败、断在哪、谁能修”。
- 边界：说“超过多少、如何分批”。
- 权限：说“谁有权、怎么申请”。
- 离线：说“哪些可看、哪些要联网”。

## 8. 证据包规范（8 段）

| # | 段落 | 必填内容 | 硬门 |
| --- | --- | --- | --- |
| 1 | 范围与非声明 | 包 ID、客户、触发、范围、非声明 | 无 → 不封包 |
| 2 | 修改记录 | 改前 / 改后产物、SHA-256、custodian、时间 | 无原像 → 不封包 |
| 3 | 版本三元组 | 产物版、行为版、判据版 + 来源 | 缺一 → 不封包 |
| 4 | 账本切片 | 账本文件 SHA、实例 ID、部署姿态、链验证、absent 理由 | 链断 → 不封包 |
| 5 | 拒收账 | R1–R7 计数 + 分母 + 样例 | 无计数 → 只能草稿 |
| 6 | 复核记录 | 复核人、独立性、S1–S6、用时、决定、断点 | 无 → 只能草稿 |
| 7 | R/N 记录 | 样本、同题、同验证器、同时间、R/N 结果 | 样本不足 → `NOT_RUN` |
| 8 | custody / 删除 | 驻留、留存、删除、子处理方、回执 | 无条款 → 不签约 |

### 8.1 版本三元组

| 字段 | 含义 | 来源 | 示例 |
| --- | --- | --- | --- |
| 产物版 | 被修改的文件 / 配置 / 提示词的版本 | 客户 VCS / 哈希清单 | `prompt.md@sha256:…` |
| 行为版 | 模型、路由、阈值、策略、工具集版本 | 客户配置 / 部署记录 | `router=…; model=…; threshold=…` |
| 判据版 | 验收标准、留出集、拒收判据版本 | 客户 eval / 本服务清单 | `A1–A6@v1; holdout=…` |

**没有三元组，就无法回答“改的是哪一版”。** 账本里的 49 格不含这三样，必须在链外证据包里补。

### 8.2 拒收原因码 R1–R7

| 码 | 含义 | 例子 |
| --- | --- | --- |
| R1 | 无真实修改样本 | 只有日志，没有改前 / 改后 |
| R2 | 原像缺失 / 不可核 | 文件没有哈希或 custody |
| R3 | 版本三元组不全 | 判据版说不清 |
| R4 | 链不自洽 / 断点不可定位 | verify 失败且找不到 seq |
| R5 | 复核人无资格 / 不独立 | 作者本人复核 |
| R6 | 超时 | 60 分钟未完成 |
| R7 | 范围 / 数据条款不符 | 不允许留存或删除 |

## 11. 数据与安全设计

| 项 | 设计 |
| --- | --- |
| 部署 | 本地 / 客户环境；只读旁挂；不改客户代码 |
| 账本 | 导入导出文件；`APPEND_ONLY=1`、`REQUIRE_TOKEN=1` 作为试点默认姿态并记录 |
| 原像 | 客户环境保管；包内只放 SHA-256 + 受控副本；custodian 具名 |
| 留存 | 30 天；到期提醒 |
| 删除 | 5 天内删除；删除清单 + 哈希回执 |
| 子处理方 | 无 |
| 密钥 | 只走环境变量；不写入包、不写入账、不写入报告 |
| 脱敏 | 原像中的密钥 / 口令 / 个人信息在入包前脱敏；脱敏规则客户确认 |
| 访问 | 买家只看自己的包；复核人只看被指派的包；作者不看判定过程 |
| 传输 | 本地拷贝或客户批准的通道；不经过第三方 SaaS |

## 12. 失败与停止规则

| 条件 | 动作 |
| --- | --- |
| 第 5 天无真实修改 | 停止，退回线索池 |
| 第 5 天无具名复核人 | 停止，不进入组包 |
| 第 10 天仍无原像 | 降级为“账本审计”，不卖证据包 |
| 链断且不可定位 | 停止，出断点报告 |
| 预演两轮 >60 分钟 | 改清单；仍超 → 对外不承诺 60 分钟 |
| 复核人利益冲突 | 更换复核人；无替代 → 延期或停止 |
| 拒收争议 | 按试点函：双方技术代表复核；仍不一致按未达成 |
| 数据条款未签 | 不传输任何客户数据 |
| 发现过度声明 | 立即更正，报告与对外材料同步 |
