# 产品设计插件 · 产品级触发场景映射（v1.0）

- **日期**：2026-10-20
- **插件**：`product-design` 0.5.10
- **对象**：Agentkernel 证据包服务 + 6 周试点运营（产品整体），**不是**单页决策卡
- **分母**：插件 `skills/` 目录实际 28 个 `SKILL.md`（`ls | wc -l = 28`，2026-10-20 实数）
- **方法**：读各 `SKILL.md` 的 description / 触发条件，再按本项目实际产物与读数判定
- **口径**：这是触发映射，不是执行日志。不把“插件里有”写成“本项目用了”，不把“部分应用”写成“通过”，不把 `NOT_RUN` 写成 0。

---

## 1. 判定口径

| 判定 | 含义 | 可以写成 | 不可写成 |
| --- | --- | --- | --- |
| 已应用 | 有对应产物，产物可复核 | “应用了该技能的结构 / 方法” | “技能全流程通过” |
| 部分应用 | 只做了子集，或缺少该技能的核心交付物 | “部分应用；缺口是 X” | “已完成 / 已通过” |
| NOT_RUN | 触发条件出现，但没有读数或产物 | “`NOT_RUN`；重开条件是 X” | “0”“失败”“不需要” |
| 不触发 | 触发条件未出现，或产品形态不适用 | “本轮不触发；出现 X 再开” | “不重要” |

**证据等级**（沿用蓝图 §9）：

- **A**：工具自印 + 独立复算；
- **B**：单源自印（本项目的设计件、渲染 QA 均属此级）；
- **C**：规划假设；
- **D**：外部公开；
- **X**：未验证（`NOT_RUN`，不写成 0）。

本映射中“已应用 / 部分应用”的产物证据是 **B**；涉及真人、客户、试点结果的格子一律 **X**，即使设计件里写了目标值。

## 3. 产品级触发场景与闸门目标

七个场景覆盖从资格通话到工程化。每个场景的目标都挂到评估 §12 的闸门，不设“尽量”“提升”这类不可判定的词。

| # | 触发场景 | 主要 Skill | 目标（可判定） | 闸 / 时点 | 当前 |
| --- | --- | --- | --- | --- | --- |
| T1 | 资格通话：买家说“出了一次回归 / 要审计” | `frame` `brief` `journey` `probe` | 10 次买家访谈；≥3 个真实触发；≥1 个 POC 意向；≥1 个预算科目 | G0 / 30 天 | 0 / 10；0 / 3；0 POC；`NOT_RUN` |
| T2 | 试点启动：客户交一次真实修改 | `sitemap` `flow-web` `stories` `brief` | 受理单 8 / 8 段有字段；原像 custody 写清；版本三元组有 schema | W0–W1 | 蓝图已定义；真实客户 0 |
| T3 | 组包：证据工程师产出 1 个包 | `flow-web` `edge` `metric` `check` | 非作者真人 ≤60 分钟完成组包 + 1 次修改；拒收被计数；链自洽；`sk-` 0；调用方模型代码 0 改动 | G1 / 60 天 | 链 2,940 / 2,940（A）；其余 `NOT_RUN` |
| T4 | 正式复核：复核人按 S1–S6 判定 | `edge` `access` `test` `bench` | 5 名复核人 × 3 个任务；通过 / 拒收 / 超时三态有记录；界面无阻断性可用性问题 | G1 / 60 天 | 0 名复核人；`test` `NOT_RUN` |
| T5 | R/N 增量验证：证明“改后更好” | `metric` `test` | 10 例 R/N；R 臂通过率 ≥ N 臂 +20pp；假修复率不高于 N 臂；反臂按预期失败或拒绝 | G1.5 / 90 天 | 0 / 10；`NOT_RUN` |
| T6 | 对外分发：报告、LOI、安全审查 | `pitch` `access` `prd` | 2 封 LOI；1 次安全审查；SBOM / DPA / 责任边界齐 | G2 / 120 天 | 0 封；未审查；`NOT_RUN` |
| T7 | 工程化：把适配层接进客户平台 | `prd` `qa` `check` | 只读接入；0 模型代码改动；0 密钥入账；实现与设计源逐项对照 | G1–G2 | 未进入实现；`NOT_RUN` |

**T1 是所有下游的前提**：没有真实触发，T2–T7 的目标都只是设计假设。

## 5. 目标推进顺序（按闸门）

| 闸 | 必须从 X 变成有读数的格子 | 对应 Skill | 不达的处置 |
| --- | --- | --- | --- |
| G0 / 30 天 | 10 次访谈、3 个真实触发、1 个 POC、1 个预算科目 | `probe` `frame` `journey` | 不启动付费试点 |
| G1 / 60 天 | 非作者 ≤60 分钟组包 + 1 次修改；拒收有计数；链自洽；`sk-` 0；模型代码 0 改动 | `test` `check` `stories` `metric` | 修协议再跑一次，不宣称可复制 |
| G1.5 / 90 天 | 10 例 R/N；R ≥ N +20pp；假修复率 ≤ N | `test` `metric` | 连续两次不过 → 冻结为研究资产 C |
| G2 / 120 天 | 2 封 LOI；安全审查；SBOM / DPA / 责任边界；对外界面完整 WCAG 审计 | `pitch` `access` `prd` `bench` | 不接企业私有化 |
| G3 / 180 天 | ≥3 家付费 ≥1 万美元，或 ≥5 家付费试点；≥1 续费 / 转正 | `retro` 开始有输入 | 回研究 / 开源适配器路线 |

**顺序不能倒**：`pitch` 不能先于 `probe` 宣称需求被验证；`access` 不能先于实现宣称合规；`retro` 不能先于试点写“经验”。

## 6. 与卡片级映射的差异

| 维度 | 卡片级（`决策卡-1020/产品设计-触发场景.md`） | 产品级（本文件） |
| --- | --- | --- |
| 对象 | 单页 A4 决策卡 + 试点函 | 证据包服务 + 6 周试点 + 六面 |
| 已应用 | 1（`pitch`） | 5（`journey` `sitemap` `flow-web` `edge` `metric`） |
| 部分应用 | 4（`check` `access` `test` `qa`） | 6（`frame` `brief` `stories` `check` `access` `pitch`） |
| NOT_RUN | 0（并入“不触发”） | 4（`probe` `test` `bench` `prd`） |
| 不触发 | 23 | 13 |
| 结论 | 卡片可读、可打印，但无真人验证 | 服务可设计、可推演，但无客户、无复核人、无 R/N |

同一 Skill 在两级的判定可以不同：卡片级的 `test` 指“读者能否读懂卡片”，产品级的 `test` 指“复核人能否 60 分钟完成判定”，后者样本与后果都更重，所以产品级标 `NOT_RUN` 而不是部分应用。

## 7. 不能下的结论

- **不能**说“28 个 Skill 已应用 28 个 / 通过 28 个”：实际是 5 已应用 + 6 部分 + 4 `NOT_RUN` + 13 不触发。
- **不能**说“60 分钟已成立”：这是目标，真人计时 `NOT_RUN`。
- **不能**说“WCAG AA 合规”：只算了 9 组色对，未做完整审计。
- **不能**说“复核人可用”：0 名真人，AI 模拟读者不计入。
- **不能**说“有产品市场验证”：0 访谈、0 客户、0 付费。
- **不能**说“PDF 可检索”：Edge 导出的 PDF 文本层 CJK 为 0，HTML 才是可复制 / 可引用源。
- **不能**把线框当已验证界面：S1–S5 是示意，数据是占位。

## 8. 维护口径

1. 每次闸门评审后更新本文件的“当前 / 目标”两列；**只改有读数的那一格**。
2. 插件升级后先重数 `skills/` 目录；28 变化时，本文件的四态合计必须重新闭合。
3. 新增 Skill 只在“触发信号出现”时开；不为凑数把不触发改成部分应用。
4. 真人 / 客户 / 试点结果未产生前，任何格子不得从 `NOT_RUN` 直接改成“通过”；至少要有原始记录 + 独立复算。
