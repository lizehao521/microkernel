- **日期**：2026-10-20
- **对象**：产品整体——可复核的二次修改证据包服务 + 6 周试点运营，不是单页决策卡，也不是内核代码
- **输入**：
  - 《Agentkernel 市场进入重评 2026-10-20》48 页（下称“重评”）
  - `构建-1017/agentkernel/docs/contract.md`（2026-10-19 版，§2.5 为代码导出）
  - `构建-1017/客服靶场/导出/账本-全量-1018.jsonl`（2,940 条，本轮独立重算）
  - `试点函.md` v0.1、决策卡 V2.1 机械测评与 AI 模拟读者记录（非真人）
- **口径**：A 工具自印 + 独立复算；B 单源自印；C 作者复算 / 规划假设；D 外部公开；X 未验证（`NOT_RUN`，不塌成 0）
- **一句话结论**：**条件 GO——只批准一个 6 周付费试点，不批准平台化。** 产品形态是“驻场式证据包服务 + 薄适配层”，不是自助 SaaS；先证明一个真实修改能被非作者在 60 分钟内复核，再谈 B（企业私有化）。

## 0. 这轮二次评估改了什么

重评回答了“卖什么”：从“可验证记账内核”改为“可复核的二次修改证据包”。它没有回答“这门服务怎么跑”：

| 重评已回答 | 重评未回答（本轮补齐） |
| --- | --- |
| 产品叙事 = 账本 + 原像 + 版本 + 外部验证器 | 证据包由谁、按什么顺序、在多长时间内生产 |
| 买家 = AI 平台 / 安全工程 / 合规风险 | 三类买家之外还有两个必经角色：非作者复核人、证据工程师 |
| 五道闸与定价假设 | 闸门之间每天怎么操作、失败时停在哪一步 |
| G1.5 要 10 例 R/N | 样本从哪来、没有 10 例时报告怎么写 |
| “不做平台” | 不做平台之后，产品的前台 / 后台 / 证据件是什么 |

**本轮判断**：重评的“功能市场”结论成立；但它对交付难度的估计偏轻。真正稀缺的不是链，而是**产物原像的 custody（保管）、版本三元组的现场对齐、非作者复核人的可用时间**。这三样都不在软件里，在服务流程里。

因此产品设计的第一原则是：

> **先做 concierge（陪跑式交付），再做 tooling；先卖一次可复核的交付，再卖年费。**

## 2. 产品定义

### 2.1 一句话

> 客户给一次真实的 Agent 行为修改（改前 / 改后产物 + 一次失败复盘），我们在 6 周内交付一个**另一个人能在 60 分钟内复核、拒收或定位断点**的证据包。

### 2.2 卖的是什么

| 交付件 | 内容 | 证据状态 |
| --- | --- | --- |
| 证据包 | 8 段：范围与非声明、修改记录、版本三元组、账本切片与链验证、拒收账、非作者复核记录、R/N 记录、custody 与删除回执 | 规范已定义；真实包 0 个 |
| 复核清单 | S1–S6，60 分钟计时口径 | 草案 v0.1；真人 `NOT_RUN` |
| 拒收账 | R1–R7 原因码、计数、分母、样例 | 规范已定义；真实拒收 0 例 |
| R/N 记录 | R 臂（有证据包）vs N 臂（只有现有 trace），同题、同验证器、同时间预算 | `NOT_RUN` |
| 决策备忘 | 保留 / 回滚 / 再改；支持证据与仍未知项 | 模板已定义；真实决策 0 次 |
| 删除回执 | 驻留、留存、删除、子处理方 | 试点函 v0.1 已写；未签署 |

### 2.3 不卖什么

- 不卖“更可信的 Agent”——那是能力承诺，会被真实读数打穿。
- 不卖“防线”——不拦截、不执行；客户拿“没挡住”来退货是预期风险。
- 不卖“认证”——合规买家要认证时，这单不成立。
- 不卖“平台”——不自建 trace / eval / SIEM；做它们的相邻证据层。

### 2.4 产品形态判断

| 形态 | 适配度 | 理由 |
| --- | --- | --- |
| 自助 SaaS | 低 | 产物原像、版本三元组、复核人资格都依客户现场而定，无法标准化到零服务 |
| 托管按次 | 低 | 重评已判定不做；隐私与留存是硬阻力 |
| 开源库 + 文档 | 中 | 能换使用与反例，但客户仍要自己补原像、版本、拒收、验证器 |
| **陪跑式试点服务 + 薄适配层** | **高** | 先用人工把流程跑通，沉淀模板与拒收语料；软件只做内部提效 |
| 企业私有化（B） | 条件 | 只在 G1.5 + G2 都过后启动；现在不启动 |

**结论**：首版产品是服务，不是软件产品。软件是交付工具，不是售卖标的。

## 3. 用户与任务

### 3.1 五类角色

| 角色 | 在交易中的位置 | 触发 | 要完成的事 | 成功标准 | 失败 / 不买 |
| --- | --- | --- | --- | --- | --- |
| **AI 平台负责人** | 买家 / 发起人 | 行为变更后回归、无法归因 | 回答“这次改动为什么发生、改的是哪一版、是否真的更好” | 拿到可复核包，内部复盘能结论 | 现有 trace 够用；不想再加供应商 |
| **安全工程负责人** | 买家 / 共同发起 | 事故复盘、内部审计、对外说明 | 事后取证：当时看到什么、用了哪版策略、谁批准 | 能定位断点、能保全证据 | 认为审计层不是防线，不愿单独付费 |
| **合规 / 风险负责人** | 预算 / 否决人 | EU AI Act 第 12 条、客户尽调、内部留痕 | 留可审计证据，不负责认证 | 证据包范围清楚、留存删除可交代 | 要认证不要工具；治理平台已买 |
| **非作者复核人** | 客户指派 / 服务必经 | 收到证据包 | 60 分钟内按 S1–S6 复算链、定位断点、通过或拒收 | 独立得出“通过 / 拒收 / 超时”，作者不参与判定 | 没时间、没资格、与作者同一人 |
| **证据工程师（我方）** | 交付方 | 受理后 | 组包、补齐原像与版本、维护拒收账、跑 R/N、写报告 | 包完整、可复核、无过度声明 | 客户不交原像 / 不指定复核人 |

### 3.2 JTBD

1. **当一次 Agent 行为修改引发回归或事故时**，AI 平台负责人想确认“改的是哪一版、依据是什么、是否真的修好”，从而决定保留、回滚还是再改，并能对内部说明。
2. **当审计、尽调或客户追问时**，合规 / 风险负责人想拿出一份范围有限、可复算、可披露的记录，从而完成交代，而不把“记录”说成“认证”。
3. **当收到一个证据包时**，非作者复核人想在不信任作者的前提下，用 60 分钟复算并定位断点，从而给出通过或拒收，而不被人情与话术带走。

### 3.3 关键洞察：买家 ≠ 用户 ≠ 复核人

- 买家关心“能不能交差 / 能不能归因”；
- 用户关心“操作麻不麻烦”；
- 复核人关心“我能不能在 60 分钟内独立判断”。

三者不是一个人。产品设计不能只优化买家首屏，必须为复核人设计一张**可执行的 60 分钟工作台**。这是重评没有展开、而本蓝图的核心。

## 4. 需求与反需求

### 4.1 三个触发（附证据等级）

| 触发 | 场景 | 证据等级 | 当前状态 |
| --- | --- | --- | --- |
| 事故复盘 | Agent 执行错误操作，要回答“看到什么、哪版策略、谁批准、改了什么” | D（外部共性）+ C（本项目推演） | 无客户事故样本；`NOT_RUN` |
| 受监管审计 | EU AI Act 第 12 条记录义务、第 26(6) 条日志保存 | D（法条公开） | 无受监管客户访谈；`NOT_RUN` |
| 行为变更与回归 | 改 prompt / 路由 / 阈值后，要知道新版是否更好、为什么改 | B（本机 60 发 / 2,940 条记录）+ C（无客户案例） | 有本机记录，无客户真实修改样本；`NOT_RUN` |

**需求成立的最低条件**：客户能拿出一次真实修改，且这次修改已经造成或可能造成回归 / 审计追问。拿不出，就没有证据包需求。

### 4.2 五条反需求

| 反需求 | 为什么会让需求消失 | 产品应对 |
| --- | --- | --- |
| 失败率很低 | 没有二次修改，就没有证据需求 | 只接高变更、高监管、高事故成本场景 |
| 现有日志“够用” | 买家分不清 trace 与证据包 | 用一次真实复盘演示“缺的是原像 / 版本 / 拒收” |
| 隐私与留存顾虑 | 不愿把 prompt / 工具输出交给第三方 | 本地 / 私有化交付；30 天留存、5 天删除、无子处理方 |
| 不想再加供应商 | 采购周期长，平台已绑定 | 做适配层 / 插件，不做替代平台 |
| 平台捆绑 | LangSmith / Langfuse / Datadog 把证据功能打包 | 守“可验证 + 可回滚 + 可披露”的深水区 |

**结论**：这不是广谱需求。合格线索的标准不是“对证据感兴趣”，而是“已经有一次真实修改 + 一个必须回答的追问 + 一个能指派的非作者”。

## 5. 替代方案

| 替代 | 客户为什么可能选它 | 它答不了什么 | 我们的相对位置 |
| --- | --- | --- | --- |
| 什么都不做 | 便宜、无采购 | 下次事故仍然无法归因 | 只在事故 / 审计后才有窗口 |
| 在现有 trace 上加日志 | 复用平台、无新供应商 | 改的是哪一版、产物原像、拒收计数、非作者复核 | 我们消费 trace，不替代 trace |
| Eval 平台 | 有数据集、有基线 | 证据链、custody、可披露包 | 我们接在 eval 之后 |
| AI 治理平台 | 合规框架、流程 | 具体一次修改的可复核证据 | 我们做技术证据，不做治理套件 |
| 内部人工复盘 | 灵活、信任内部 | 跨版本可复算、拒收语料、R/N 对照 | 我们把人工复盘变成可复核件 |
| 请咨询顾问 | 有报告、有背书 | 证据包本身、复核记录、可回滚 | 我们交付可复核物，不是观点 |

**差异化**：不是哈希链，不是 49 格，而是**证据包规范 + 拒收计数 + 版本三元组 + R/N 协议**。链很容易被复制；拒收语料与复核记录需要时间积累。

### 6.1 A 级：本机可复算

本轮独立重算 `账本-全量-1018.jsonl`（不引用内核自印聚合）：

| actor | 4 个 | 自报字符串，无第二根轴反证 |

- 8799 实例的 490 条账、6 发、append-only 未被回改：来自 10-18 收尾件，本轮未重连该进程复算。标记 B，不升级为 A。

## 8. 桌面推演：拿现有账本当证据包会发生什么

把 2,940 条账本按 8 段证据包逐段检查（不冒充真实试点）：

| # | 证据包段落 | 推演结果 | 状态 |
| --- | --- | --- | --- |
| 1 | 范围与非声明 | 可按模板起草 | 可起草（C） |
| 2 | 修改记录（改前 / 改后产物 + 哈希） | 无产物，无法填 | 缺（X） |
| 3 | 版本三元组（产物 / 行为 / 判据） | 三格全空 | 缺（X） |
| 4 | 账本切片 + 链验证 | 2,940 / 2,940 通过 | 有（A） |
| 5 | 拒收账 | 导出无 gate 行；R1–R7 无计数 | 缺（X） |
| 6 | 非作者复核记录 | 未跑 | `NOT_RUN` |
| 7 | R/N 记录 | 未跑 | `NOT_RUN` |
| 8 | custody / 留存 / 删除回执 | 试点函有条款，未签署 | 草案（C） |

**结论**：8 段里只有 1 段有 A 级证据，2 段可起草，5 段缺失或未跑。这不是失败，而是产品设计的真实起点——**Pack Builder 必须把“缺原像 / 缺版本 / 缺拒收”做成硬门，而不是黄色警告**。

### 10.1 窗口

## 13. 本轮判定

### 13.1 判定

**条件 GO：批准一个 6 周付费试点，不批准平台化、不批准 B、不做 C。**

三个前置条件，缺一不启动：

1. 客户提供一次**真实修改**（改前 / 改后产物 + 一次失败复盘）；
2. 客户指派 **1 名非作者**复核人，且能保证 60 分钟；
3. 客户接受**数据条款**（驻留、30 天留存、5 天删除、无子处理方、责任上限）与**非声明**（不是防线、不是认证）。

### 13.2 为什么不是“全面 GO”

- 0 个真实包、0 名复核人、0 例 R/N、0 次访谈；产品还没有被任何外部流程碰过。
- 原像、版本、拒收三族证据缺失；桌面推演只过 1 / 8 段。
- 60 分钟是目标，不是读数；真人计时 `NOT_RUN`。

### 13.3 为什么不是“NO-GO”

- 链的自洽性有 A 级读数（2,940 / 2,940）；这不是空想。
- 证据包规范、拒收码、复核清单、R/N 协议已经可执行，不是 PPT。
- 市场窗口与预算科目有外部依据；只差一次真实试点来证伪。

### 13.4 什么会改变结论

| 事件 | 结论变化 |
| --- | --- |
| 10 次访谈找不到 3 个真实触发 | NO-GO，冻结研究资产 |
| 第 5 天仍无真实修改样本 | 试点不启动，退回线索池 |
| 客户给不出产物原像 | 降级为“账本审计服务”，不卖证据包 |
| 非作者 60 分钟做不完且无法修清单 | G1 不过，产品形态需重做 |
| R/N 无增量 | G1.5 不过，冻结商业化 |
| 平台免费捆绑证据包 | 转研究出版 / 规范，不做商业产品 |
| 合规买家只要认证 | 不是目标客户，放弃 |
