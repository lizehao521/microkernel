00

The product / 产品形态

先做服务，再做工具。

买家预算挂在 trace / eval / AI 治理科目下；原像、版本、复核人都在客户现场。首版必须是陪跑式交付，不是自助平台。

形态

陪跑式证据包服务

Service + Adapter

我们进客户现场，把一次真实修改组装成可复核包；软件只做内部提效。不是又一个 trace / eval / SIEM。

卖什么

一次修改的完整证据

8 段包

账本切片 + 产物原像 + 版本三元组 + 拒收账 + 非作者复核 + R/N（样本足时）+ custody + 决策备忘。

不卖什么

不卖防线、认证、平台

4 个不

不拦截、不执行；不构成合规认证；不做多租户 / 托管按次；不卖“更可信的 Agent”这种能力承诺。

为什么不是平台：平台已经被 trace / eval / 治理工具占住；客户的缺口是“这次修改的证据”，不是“再多一条日志”。平台的替换成本高、销售周期长；证据包的替换成本低，反而更容易被试用。

02

Service blueprint / 服务蓝图

七段流程，三道硬门。

客户可见的只有四次会：资格、受理、复核、读报。其余是后台组包与证据工程。每一段都产出证据件，失败时知道停在哪。

阶段客户动作前台（可见）后台（不可见）证据件失败态 / 停点
0 触发与资格QUALIFY 内部发生事故 / 审计 / 行为变更 15 分钟资格通话 查三件事：真实修改、非作者、数据条款 资格记录 任一项没有 → 不进入受理
1 受理INTAKE 填 Intake Sheet、交原像、指派复核人 受理会 + 清单确认 建包 ID、哈希原像、记录 custodian 受理记录 + 原像清单 原像 / 复核人 / 条款缺 → 不签约
2 组包BUILD 提供账本导出、补充版本信息 组包进度与缺口清单 链验证、版本对齐、拒收账、8 段检查 包 v0.1 + 链验证报告 链断 / 原像缺 / 版本缺 → 不封包
3 预演DRY RUN 不参与（内部） 预演结论 内部复核人按 S1–S6 试跑、调清单 预演记录 两轮仍 >60 分钟 → 改清单，不承诺 60 分钟
4 正式复核REVIEW 指派非作者复核人 60 分钟复核会（可远程） 计时、记录每步、断点定位 复核记录 + 决定 超时 / 冲突 / 证据缺 → 记为超时或拒收
5 R/NARMS 提供同题样本与验证器 结果只读 R 臂（有包）vs N 臂（只有 trace），同题同时 R/N 表 样本 <10 → NOT_RUN，不宣称增量
6 报告与收尾REPORT 收报告、做保留 / 回滚决定 30 分钟读报 汇总 A1–A6、工时、非声明、删除 报告 + 删除回执 无复核记录 → 报告只能是草稿
关键时刻：受理时暴露“客户拿不出改前产物”；预演时发现“清单读不懂 / 超时”；正式复核时复核人找不到断点；报告时买家问“所以证明了我的 Agent 可信吗”。这四个时刻决定产品是否成立。

States / 六态矩阵

空、加载、错误、边界、权限、离线。

六个界面 × 六种状态。重点不是“有没有空状态”，而是每种状态是否说清“现在缺什么、谁能修、下一步是什么”。

界面空加载错误边界权限离线
S0 状态板0 个真实包，显示 0，不画假趋势读取中读取失败，保留上次快照并标时间多包分页 / 筛选客户只看自己的包只读缓存
S1 受理无线索校验组织信息字段校验失败，逐项点名原像 >20 件，分批非本组织不可见本地草稿
S2 组包未导入账本哈希 / 验证中链断 / 文件损坏，定位到 seq10 万条记录分页 / 流式无原像访问权 → 停本地模式，联网后复核
S3 复核未分配包打开包证据链接失效，标断点60 分钟到点 → 超时非指派 / 利益冲突 → 回避计时本地，提交后同步
S4 拒收账0 条拒收，如实显示查询中重复记录 / 缺原因码大量记录分页买家只读自己的队列待同步
S5 报告无报告生成中无复核记录 → 阻塞大包分页 / 附件仅买家与交付方只读缓存
三态规则：有 / 缺席（带理由）/ 未运行，三态分开显示。NOT_RUN 不是 0，也不是失败；它是“还没有读数”。

草稿
Version triple / 版本三元组

没有它，就答不出“改的是哪一版”。

  • 产物版：文件 / 配置 / 提示词，客户 VCS 或哈希清单
  • 行为版：模型、路由、阈值、策略、工具集
  • 判据版：验收标准、留出集、拒收判据

账本 49 格不含这三样；必须在链外证据包里补。

Rejection codes / 拒收码

拒收不是失败，是读数。

  • R1 无真实修改样本
  • R2 原像缺失 / 不可核
  • R3 版本三元组不全
  • R4 链不自洽 / 断点不可定位
  • R5 复核人无资格 / 不独立
  • R6 超时
  • R7 范围 / 数据条款不符
09

Boundaries / 边界

能说 / 不能说 / 不接什么。

所有对外材料必须带 NOT_RUN。不把“链自洽”说成“内容可信”，不把“记录”说成“认证”，不把“审计层”说成“防线”。

Can say / 可以说

有读数的

  • 链可自洽重算；2,940 / 2,940 通过
  • 记录未被改；断点可定位
  • 证据包能指出缺的是原像、版本还是验证
  • EU AI Act 第 12 条的技术证据（不构成认证）
  • “AI 模拟读者 29 / 30（非真人）”
Cannot say / 不能说

没有读数的

  • “验证通过 / POC 达标 / 读者验证通过”
  • “记录驱动自动改进已有效”
  • “挡住提示注入 / 工具滥用”
  • “链自洽 = 内容可信”
  • “30 分钟接入”
  • “托管按次 / 多租户 / 按 seat 计费”
Out of scope / 不接

边界

  • 不接模型调用、不改客户模型代码
  • 不拦截、不调度、不联网、不执行工具
  • 不做 SIEM / 可观测 / eval 替代
  • 不做合规认证
  • 不做托管按次、多租户
  • 只对应 MCP08，不宣称 MCP01/03/06
一句话收口：这不是“更可信的 Agent”，而是“这次修改的证据是否成立”。前者是能力承诺，后者是可复核件。
