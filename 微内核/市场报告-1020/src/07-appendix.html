Appendix A

A方法与证据分级

A.1 研究问题与范围

本报告回答一个决策问题：在“账本完整性已验证、但记录驱动二次修改尚未实证”的前提下，agentkernel 应以哪种方式面对市场。 范围限定为：产品叙事、进入方式、进入门槛、定价与三年财务；不重新做 v1 的市场规模调查，不评估内核代码质量，不评价模型能力。 市场数据沿用 v1（2026-10-19）；记录面事实来自 2026-10-19 至 10-20 的本机复算；外部文献用于校验“记录 → 修改”的因果链，不用于证明产品有效。

A.2 证据分级

等级判据本报告中的典型用法
A工具自印 + 独立复算；或两个独立来源逐字对上账本 2,940 条、链 2,940/2,940、封板 78 针、外部 6 发对账
B单一来源自印，未独立复算单次运行读数、单一内部文件

使用规则：X 级不得写成 0；C 级不得写成调查结论；D 级不得写成官方原文已核（除非确已打开原文）；A 级必须能给出复算命令或对账文件。 本报告没有把“未找到付款证据”写成“0 个买家”，也没有把“未跑双臂”写成“无效”。

A.3 资料与方法

  • 记录面审计：对导出的账本逐行复算 seq / prev / payload / seal；统计调用数、会话数、basis 分布、字段空值；检查 read_back、declare_reader、load_journal 的行为。
  • 市场数据：沿用 v1 的三路自上而下与自下而上估算；v2 只改“相邻市场占比”，从 8–12% / 5–8% 下调到 3–6%，理由是本产品是功能而非平台。
  • 外部文献：检索自我修正、轨迹学习、可观测性与合规四组资料；优先 Tier 1（论文、官方文档），Tier 2（律所指南、厂商工程博客），Tier 3 仅作旁证。
  • 财务：按“付费账户 × ARPU”建模，成本不含作者人力；另做含 8 万美元 / 年作者成本的敏感性。
  • 红队：用“买家自建”“平台打包”两条攻击路径反推产品边界；未做真人红队演练。

A.4 局限

  • 没有做付费市场调查。10 次访谈是 G0 的动作，不是本报告已完成的工作；SAM / SOM 是规划假设。
  • R/N 双臂未跑。报告只能给出协议与闸门，不能给出“记录驱动修改有效”的结论。
  • 单一作者。记录面审计、市场判断与财务假设都出自同一作者，缺少独立复核；这是本报告最大的方法风险。
  • 外部资料有时效。价格、法规与 semconv 都会变；引用日期为 2026-10-18 至 10-20。
  • 财务不含融资与税费。三情景只用于量级判断，不能作为投资决策或报价依据。

A.5 复现与推翻

记录面数字可用本机账本重新复算；财务表可按表 11 的账户数与 ARPU 重算；市场规模可用 v1 的三路数据与 3–6% 占比重算。 以下任一读数出现，本报告的核心结论应被推翻或修订：

  • G1.5 的 R 臂留出集通过率 ≥ N 臂 + 20 个百分点，且假修复率不升——应上调对 B 的投入，并重新评估“功能市场”判断。
  • 外部团队在 60 分钟内无法产出可复核证据包——A 的交付物设计失败，应退回研究阶段。
  • 买家为“可复核”单独设预算科目——SAM 与 ARPU 应上调，定价梯子需重做。
  • 头部平台把证据包做成标准功能——A 退回规范与适配器，B 不做。

D.1 术语表

basis记录值的来源状态：measured / absent / relayed / estimated / model_says / unset。
absent明确记录“没有这个值 + 理由”；不是 0，也不是空字符串。
read_back读回接口；当前不返回链头指纹，不能单独证明“你看到的是原来那本”。
declare_reader读者声明；当前仅内存，不持久化；严格双臂中拒收六桶全 0。
load_journal装载账本；可整本替换，APPEND_ONLY 默认关闭；证据包需另加链头指纹与外部存证。
证据包账本 + 产物原像 + 行为/判据版本 + 拒收计数 + 外部验证结果 + manifest；可复核、可回滚、可披露。
产物原像被修改的文件/配置/提示词的原始内容或其可验证哈希；账本本身不保存。
版本三元组产物版本 + 行为/配置版本 + 判据版本；缺一项，修改不可归因。
拒收计数被验证器拒绝的候选修改数量与原因；不做拒收计数，就会把“挑过的成功”当总体。
R/N 双臂R 臂看记录再改，N 臂不看记录直接改；比较留出集通过率与假修复率。
假修复率验证器判为修好、但留出集或反臂显示未修好的比例。
反臂 A/B预期失败或应被拒绝的叶子任务；用来证明验证器不是“永远通过”。
Gate 1.5R/N 增量闸；不过则冻结为研究资产，不进入私有化。
功能市场 / 平台市场前者挂在可观测性、评测、治理预算下；后者有独立预算科目与平台采购流程。本报告判断为前者。

D.2 对外材料草稿（一）：一句话与一段话

一句话

agentkernel 把一次 Agent 修改的账本、产物原像、行为/判据版本与拒收计数装进一个可复核的证据包，让另一个团队能独立判断这次修改是否算数。

一段话（对外简介）

Agent 团队已经不缺 trace，缺的是“这次修改凭什么算数”的可复核证据。agentkernel 是一个证据适配层：它接在现有 trace / eval 旁边， 把账本、产物原像、行为与判据版本、拒收计数和外部验证结果装进一个证据包。它不拦截、不调度、不执行工具，也不宣称让 Agent 更可信； 它只让一次修改可被另一个人复核、回滚和披露。当前版本是研究资产，R/N 双臂尚未运行；我们优先寻找有真实事故复盘、审计或行为变更触发的团队做 POC。

D.3 对外材料草稿（二）：不承诺清单

  • 不承诺“上了内核就挡住提示注入 / 工具滥用”——审计层不是防线。
  • 不承诺“verify 通过 = 内容可信”——链只证明记录未被改。
  • 不承诺“记录驱动自动改进已有效”——R/N 双臂 NOT_RUN，严格双臂仍 FAIL。
  • 不承诺“30 分钟接入”——当前目标是非作者真人 60 分钟产出 1 个证据包并完成 1 次修改。
