## 1 撞车（两路独立撞到同一条）= 最高信度，已修

**counts 只按 turn 键 + 跨趟 seed 整本日志**（路 A 的 P0 / 路 B 的 P0-1，两份报告互不认识）。

- **复算**：把新针 `TestCrossRunCountsArePerRun` 放到**未修改的真树**副本上跑 ——
  `跨趟日志上结算判据红：第 1 发结算自印 counts 加总 8，本发实际 4 条`（rc=1）。不是照抄报告的结论。
- **根因**：`eventBus.states` 以 `turn` 为键，而 seed 从整本既有日志读（含上一趟、含别的 session）；
  判据的分组键早先是 `(session,run,turn)` —— 上一轮加 run 轴时改了分组键、**没走到 counts**。
- **修法**：键换成**发身份块**（`blockOf(e)`，即 session\x1frun\x1fturn），写侧 6 处 + 读侧 1 处一起改；
  `countsFor(session, turn)`。seed 的注释同时还债（旧注释是 run 轴之前的口径）。
- **钉它的针**：`TestCrossRunCountsArePerRun`（18 发逐块对账）+ 真二进制 S11（独立 Python 复算，不套 Go 口径）
  + S10（跨趟合并日志 `-check-log` 四支全绿）+ S12（把 counts 翻倍的坏日志必须 RED 且 rc=4）。
- **臂**：E1（多站点变异：键退回只按 turn）→ BIT；对照绿、变异红、无编译崩。

## 5 E4（SSE 投送 + Last-Event-ID 重放）已落地并推广

写侧：`cmd/agentd/sse.go`（12 支针在 `events_sse_test.go`）+ `main.go` 的 `-events-serve`。

- **游标是身份四元组** `<session>:<run>:<turn>:<seq>`，比研究件 §5.2.6 写的三元组多一段 run。
  理由（本轮量到的）：`seq` 是**发内**序号（`Emit` 按 turn 分开数，`e.Seq = b.seq[e.Turn]+1`），全局不唯一；
  日志跨趟接续后同一 session 有两条 turn=1。⇒ 能定「哪儿之后」的全序只有**日志行序**，尾部按行号切。
  这一条是**偏离契约**，要作者认（见 §7）。
- 坏游标 **409**（不当首连重播整本）、日志读不动 **503**、只认 `/events`（其余 404）。
- `ValidateReplay` 只在「游标那条在账里唯一存在」时接得上；身份撞车（>1 条）点名红。
  **重放两次同序列**不在判据里判（判据吃同一份切片 = 恒真），由 HTTP 连打两次钉。
- `resumable` 从「恒 false 的约定」改成 `canResume()` **当场算**：落点在不在、这本账降没降级、读不读得回来。
  四种形态各有话（可读 / 事件层没开 / 降级 / 内存模式）。
  - 诚实记录一条造不出来的形状：「跑一半文件被别的进程删掉」在 Windows 上删不动（总线握着句柄）→ 那半支改用最
    接近的可控现场（撕裂日志 → 降级），并写明 NOT_REPRODUCED 的是哪一半。
- 臂 **D 族 10/10 BIT**（丢 run 轴 / 跳过续传判断 / 游标那条重播 / resumable 恒 false / 内存冒充可续 /
  谎报可续不判 / 撞车不判 / 帧不写 id / 不分路径都播 / 尾部退回按 seq 定序）。
- 真二进制：**S13 边跑边读、重放两次同序列、游标 4 段**；**S14 坏游标 409**（第一跑失败是我这尺子的病 ——
  HTTP 头不许放非 latin-1 字节，改成 ASCII 游标后 409）；**S15 跑过的一趟日志四支全绿**。
- 头一块 E9 落点：`-check-log`（`checklog.go`）——四支判据 + 用的哪个上限，一行一个读数，
  退出码沿用既有六个里的 0/4/2。目的：判据口径只留一份，尺子不许自己再数一遍。
