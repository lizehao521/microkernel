# 契约对照 · 研究件 §5 与 E1+E2 实现（2026-10-22）

用途：把 `研究-协同工作-1022.md` §5.1/§5.2/§5.3 逐条对到 `cmd/agentd` 现在的产物上。
每条给三态：**已合** / **形状不符（要改）** / **本来没这回事（不归本案）**，并指到 `path:line` 或盘上读数。
这份不是 M2 报告的替代 —— 两路只读审查在跑，回来合并时以那份为准；这一份只保证「契约这一维有人逐条对过」。

## §5.1 最小形状（强制五组）

| 组 | 契约字段 | 实现 | 判定 |
|---|---|---|---|
| 身份 | `session / turn / seq` | `events.go` 的 `Event.Session/Turn/Seq`，`(session,turn)` 内严格 +1，读回判据 `ValidateLog` | **已合** |
| 转移 | `kind` + `step` | `Kind` 必填；`Step{no,name}` 有；**`Step.tool` 至今无人赋值** | **形状不符（轻）**：`tool` 是契约字段，生产路径没有一件事件带它 —— 该在 E2/E5 的步骤级事件上补，或由 §5.1 明确「可缺」 |
| 证据 | `state / evidence / why` | `eventStates` 白名单 + `evidenceTiers` 五档门禁 + `absent` 无 `why` 直接拒 | **已合（门禁在）**，但真实流只用 `measured` 一档、`absent` 只存在于测试 —— 见 `u.tier-usage`，**「有门禁」不等于「有区分」** |
| 进度 | `progress.done / total`（可缺） | `Done`/`Total`（指针）+ 我另加的 `Limit` | **已合 + 超集**：`limit` 是 E1 加的（额度与工作量分家），契约没有这一格，界面可以不读 |
| 时间 | `ts / elapsed_ms` | `ts` 优先取请求入口时刻；`elapsed_ms` 自 t0；E2 加了 `ack_ms` | **已合**；`elapsed_ms` 现在有非递减断言（原来没人对） |

`accept` 是**契约外的嵌套对象**：§5.2.1 要求回执带「session、turn、计划、上限、是否可续、怎么停」，
我落成了 `accept.{planned_steps,turn_limit,stop_via,resumable,ack_ms}` 而不是平铺。
判定：**形状不符（要拍）** —— 只读 §5.1 那份平铺形状的消费者取不到这些字段。
要么 §5.1 增补「回执载荷可嵌套」，要么平铺进 `Event`。这条留给作者拍（改契约 vs 改实现），我不擅自改研究件。
**同批已改的一处形状**：M2 两路各自撞到「跨趟追加的日志里同一 turn 会有多条回执」，而路 B 的修法（按 (session,turn) 分组）我复算不成立 ——
于是 `Event` 加了 `run` 一格（总线盖），身份从三元组变四元组 `(session,run,turn,seq)`。这条也要作者确认是否回写进 §5.1。

## 对照时抓到的一处真缺陷（我自己 E1 修出来的）

E1 那一轮我把「六态整句话」从 `state` 挪出来，理由是：
> 状态是「这一条在讲什么阶段」，必须是个可分档的 token；结束原因的整句话走 Stop 字段（塞进 state 下游就没法按档归并）。

可是 `Stop` 现在装的还是同一句散文（`"跑完：端点剧本走到最后一发"`）。
**问题没解决，只是换了格子**：下游想按结束原因分支，仍然要中文字符串匹配 —— 这正是我当初判它错的理由。
契约 §5.2.4 本来就写的是两格：`stop`（枚举）+ `stop_why`（那句话）。

修法（M2 回来后一并做，不现在动被审文件）：
- `Stop` 改存 token：`script` / `turns` / `policy` / `driver` / `capped` / `abort`（与 `exitOf` 同一套，一格不新增）；
- 整句移到新字段 `StopWhy`；
- 判据两条：`stop` 必须在六 token 内（红得了写错的那个），`stop_why` 非空；
- 臂：拿一个不认识的 token 喂 `ValidateLog`/新判据必须红；把 `stop` 写回散文必须红；
- 同时把冒烟 S6 的断言从「stop 含『跑完』」改成「stop == `script` 且 stop_why 含『跑完』」——
  旧断言本身就是那类「拿计数词关键字判过」的针，要一起换。

## §5.3 三档时延预算

| 截止 | 契约要求 | 现在能不能判 |
|---|---|---|
| 0.1s | 受理回执（含 turn 身份与停止入口） | **M2 之后才真的能**：锚点原先钉在「回执构造那一刻」，实测 42/42 与 16/16 恒 0 ⇒ 判不出；现在钉在 `main` 的请求入口（`loop.go` 的 `ackAnchor` —— 按符号认，行号会漂，要号就 `grep -n 'ackAnchor' loop.go`），生产路径那支（`TestProductionAckLatencyIsMeasurable`）能红。上限做成可注入：满载实测过 483ms 的合法跑法 |
| 1s | 首个真实进展（第 1 步开始/计划已选） | **不能**：`shot_started` 有落盘但没有时限判据 —— 归 **E5**（兜底进度那一发一起做） |
| 10s | 确定性进度或解释为什么没有 | **不能**：`progress_tick`/`why_late` 是 E5 的内容 |

⇒ 现在可以说「0.1s 这一档量的是真窗口」，但仍不能说「三档时延预算已落实」——1s 与 10s 两档还没针。
